# 排障手册

## 症状 → 定位表

「来源」一列：实机 = 用户在游戏里看到；离线 = 离线渲染或测试中发现；审查 = 代码审查中发现；未验证 = 写进发布说明的已知限制或推断，没有实机观察。

| 症状 | 来源 | 成因 | 先查什么 / 怎么修 |
| --- | --- | --- | --- |
| 过厂商 logo 后黑屏卡死 | 实机 | Mod PSARC 的数据块被 zlib 压缩了 | 数据原样存储，只压缩 manifest；≥ 64 KiB 的文件起点按 8192 对齐 |
| 脖子过长 | 实机 | 颈、头关节硬对齐 Jin | 保留她的脖长，颈根放在 Jin 颈关节下方 5 cm |

| 宽肩、男性肩宽 | 实机 | 手臂根部被推到接近 Jin 的肩宽 | 保留她的肩宽；露肩服装再加上下垂姿势反解 |
| 耸肩，肩头鼓包 | 实机 | 上臂根部在转轴内侧，手臂下垂时绕转轴翻上来 | 先看原衣服能不能遮住；遮不住就用 `--arm-hang` |

## 已被证伪的捷径

- **「在 T-pose 下多试几组根部参数就能修好肩。」** 试了六组（外移 0 / 0.5 / 0.75 / 1 × 下沉 5–9 cm），结果总是在耸肩和方肩之间取舍。转轴不匹配只能靠按姿势反解。
- **「只处理皮肤权重就够了。」** 袖套边和外套领口同样挂在上臂上，照样翻起来。
- **「foot_scale 会通过 TPS 传到鞋和腿套上。」** 实测名义 1.2 倍时，鞋约 1.29 倍，腿套下摆仍是 1.45 倍。
- **「Karin_Original 用这组参数没问题，PicodraTech 照搬也行。」** 同样的根部翻起，被宽松毛衣盖住，却在露肩服装上直接露了出来。
- **「压缩 PSARC 数据块能省空间。」** 结果是黑屏卡死。

## 推理否决、未实测的方案

- **把 Jin 的肩关节往内移（改骨架）。** 没有公开证据表明改骨骼位置在游戏里生效，而且双手的位置会各偏约 8 cm，双手握刀的姿势会被破坏。没有做实机实验。

## 两个反复出现的元错误

1. **缺陷在离线渲染里其实看得到，只是看漏或低估了。** 第二、三次实机反馈中的尖角和尖刺，在当时的离线下垂渲染里都在：第二个构建的尖角看到了但被低估；第三个构建审查时只盯着皮肤的数值剖面和放大图。发布前要把问题区域的所有网格从三个方向都看一遍。
2. **只和上一版比，不和源模型比。** 腿套相对鞋子的比例失调，只有把源模型按同比例并排渲染才看得出来。

## 工具与环境

- Git Bash 的 `sed -i` 会把 CRLF 文件改成 LF。修改 CRLF 源文件时，用 Python 按字节读入、替换、写临时文件再 `os.replace`，保留原有换行。
- 通过 Bash heredoc 内联的 Python，字符串里的 `\r` 等转义可能被解释成控制字符。改完用 `file` 查一下是否出现 `CR line terminators`；更稳妥的做法是先把脚本写成文件再执行。
- 两个 profile 默认共用同一个 `--work` 目录，并行构建会互相覆盖。
- 百度云同步目录里的 git 仓库，可能被同步回退成旧文件并生成 `*_冲突文件_*` 副本。提交前先看 `git status`，只 add 本次写的路径。
