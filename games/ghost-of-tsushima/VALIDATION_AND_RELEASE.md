# 验证与发布

## 离线闸门

1. **结构校验（`verify.py`）：**
   - 文件集合与参考 mod 完全一致，每个文件与原版等长；
   - xpps 只改动预期的字节；
   - 各部件顶点和三角数不超过容量；
   - 隐藏部件的 scale 已写入；
   - 贴图的尺寸、格式和 mip 链正确；
   - 使用到的骨骼数合理（本例 76 根）。
2. **回读渲染：** 从构建好的 PSARC 中解码 xmesh、xpps 和 SPS，用解出的数据渲染，不用内存里的中间结果。
   - 蒙皮：`M = Σ w · posed_world · bind⁻¹`。
   - 姿势用「绕世界轴旋转某根骨骼」来定义。
   - `verify.py` 固定输出：bind 贴图渲染，以及 arms_down（上臂下垂 75°、肘弯 40°）、wrist_twist、walk、ride。
   - 本项目迭代肩和脚时，还用了项目临时目录里的渲染脚本补充以下姿势：

| 姿势 | 作用 |
| --- | --- |
| idle / down | 上臂下垂 82° / 70°，肘弯 20° / 15°；看**肩部**，这是实机最常见的姿势 |
| front / raise | 手臂前伸 / 上举；看肩部拉伸代价 |
| crouch | 深蹲；看膝和裙摆 |
| toe / foot | 踮脚、屈踝；看鞋底折弯和鞋口 |

3. **审查口径：**
   - 把问题区域的**所有网格**从正、侧、背三个方向逐个看：皮肤、袖套、外套、头发都要看，不能只看数值指标；
   - 并排放源模型：绕她自己的关节摆同样的姿势，按同一比例对齐。
4. **回归：** 构建器被多个模型的 profile 共用。改工具后，旧 profile 的输出 md5 必须与上一次发布逐字节相同；Original v4 的回归值是 `a30f3ac1…`。
5. **确定性：** 同一输入构建两次，md5 必须相同。

## 实机反馈的处理

- 原话记录，并绑定到所测包的 sha256。
- 用户给的截图先裁出局部放大，再和离线渲染里同一部位对照：
  - 如果离线渲染里本来就能看到问题，说明审查口径漏了；
  - 如果离线渲染里看不到，再怀疑姿势定义或格式问题。
- 一个包里同时改了几处时，要逐项写清各自的证据级别。

## 发布

- 每个版本一个发布文件夹，放 `.psarc` 和 `README.txt`。README.txt 写清：
  - 安装：复制到 `<游戏目录>\cache_pc\psarc\`；其他同类 mod 要先移走；
  - 装备「忠赖的铠甲」，使用默认染色；
  - 卸载方法，以及如何回退到上一版；
  - 已知限制；
  - 模型许可。
- 替换发布包之前，先把旧包备份，并记下旧包的 sha256。新包的 sha256 写进项目 README，同时附上构建历史。
- 模型许可：发布前先读 VRM meta。
  - PicodraTech 的 VRM 0.x meta 是 `licenseName: Redistribution_Prohibited`、`allowedUserName: OnlyAuthor`：发布包不公开分发，使用范围以作者授权为准（本项目只在用户本人的机器上使用）。
  - Original 的 VRM 1.0 meta 为 `allowRedistribution: true`、`modification: allowModificationRedistribution`，其余条款（署名、商用等）以 meta 原文为准。
  - 两者都不放进公开仓库：公开仓库只放文档，不放包、模型或截图。
- 用到的第三方组件要署名：Dave349234 的格式工具包（MIT，要求署名）；DirectXTex `texconv`（MIT，许可文件随工具一起放）。

## 审查

- 改工具要做两席审查：原生 oracle 和 GPT oracle 并行，看同一份冻结 diff 和 sha256 快照，材料以审查包为准。
- 本工作区对 modding 项目的审计统一降一档。
- 第一轮报出的问题全部修完后，只做一次合并复审，而且只审增量。
- 本项目审查实际抓到的问题：
  - 手被减面；
  - 多块槽位缺少减面余量；
  - 减面产生重复面；
  - 贴图页的像素变换与 UV 变换不一致；
  - 透明像素的 RGB 渗入颜色；
  - upperChest 子树的映射顺序；
  - 参数 0 被当成默认值回退；
  - 大角度下的病态解；
  - 雅可比漏了混合梯度项。
