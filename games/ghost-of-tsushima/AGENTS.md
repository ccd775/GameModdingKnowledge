# Agent 入口（Ghost of Tsushima PC）

先读 [README](README.md)，再按当前问题进入对应文档。项目的当前状态在各自的项目目录 README 里，不在这里；本目录只提供方法、数值快照和已被证伪的假设。

## 接手新任务前

1. **核对 build。** 查 Steam `appmanifest_2215430.acf` 的 `buildid`，本目录的快照是 `23879181`。build 变了，下面这些都要重新提取和验证：部件哈希、容量、骨骼索引、xpps 偏移、布料开关字节。
2. **跑回归。** 改构建器之前，先确认旧 profile 的输出 md5 能复现。每改一次工具都要重跑这个回归。
3. **分清本版改什么。** 几何、权重、贴图、打包这几类改动的验收口径不同。实机反馈常常同时涉及好几处，此时要逐项写清哪一项改了什么、用什么证据。

## 硬性规矩（本项目已付过学费）

- **PSARC 的文件数据不压缩**，只有 manifest 可以 zlib。数据块压缩会导致过 logo 后黑屏卡死。
- **不改部件的顶点数和索引数，不改 xpps 包围盒。** 能跑的社区 v1.0 mod 就是这样做的，文件大小也保持原版。
- **不改骨架。** 没有公开证据表明改骨骼位置在游戏里生效。按推理（未实测），把肩关节内移还会让双手握刀的两只手各向内偏约 8 cm。
- **不要用单个网格的权重技巧修肩。** 手臂根部的所有网格（皮肤、袖套、外套）必须一起按下垂姿势处理，见 [拟合与绑定](FITTING.md)。
- **不要假设 TPS 能控制宽松布料。** 控制环只在皮肤半径附近起作用，离骨骼远的鞋和腿套会按全局比例走。需要局部缩放时，对该区域的顶点做显式变换。
- **离线渲染要覆盖问题区域的全部网格，正、侧、背三向都看**，并与按同比例摆姿势的源模型对比。
- **不要声称实机通过。** 离线闸门全绿、回归 md5 一致、两次构建逐字节相同，都只是 `offline-accepted`。
- **两个构建共用 `--work` 目录，不要并行跑。**

## 报告口径

每条结论要归入以下一类：`invariant`、`build-sensitive`、`case-derived`、`hypothesis`、`rejected`。历史失败不删除；新证据只用来收窄旧结论的适用范围，并写明 supersedes 关系。实机反馈要原话记录，并绑定到所测包的 sha256。
