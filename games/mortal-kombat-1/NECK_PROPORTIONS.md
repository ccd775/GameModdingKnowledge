# 长脖子：头颈比例检查与局部修复

本页“不缩头”针对只修颈长且头部大小已接受的任务。若用户明确指出头过大，应先核实并统一头组尺度；之后既查颈长也查上衣跨度。Karin Y收头后上衣被压短的复发案例与检查见 [手部与上半身](UPPER_BODY_HANDS.md)，不要用头颈局部规则排除已请求的躯干修复。

适用于原生骨架替换后头颈显得过长，尤其是肩宽修复后才暴露的问题。用户指出此问题在多个 agent session 重复出现；本页可核实的案例是 Wasakura → Geras / Peacemaker / OmniMan。其它会话的具体成因不能据此推定相同。

## 先区分证据与成因假设

原生骨架是动画接口，不是源角色的视觉比例模板。Wasakura 按目标 Neck/Head 锚点适配；v4肩宽获认可后，用户明确指出三者颈长不自然。v5只调整头颈几何后反馈“脖子好了很多”。这证明该局部修正改善了当前可见效果，**不证明所有长脖子都由同一骨长或权重错误造成**。

v4肩宽场只改X，未改变头颈Z。因此不要说“收窄肩膀把脖子拉长了”；可以说肩颈相对比例问题变得更显眼。先查同姿势、同视角、同版本的实际轮廓，再决定修什么。

排查顺序：

1. 锁定已安装三件套哈希和候选Blend，确认看到的确实是当前版本。
2. 检查源求值网格、对象变换、场景单位、Head末端有效尺度及原生骨序/局部变换。单位错误或头过小先处理对应原因。
3. 在相同尺度及姿势下量下巴→颈根、下巴→领口的可见距离，同时量头高、肩宽和Neck→Head锚点距离。骨头距离不等于露出的脖子长度，项圈和衣领会影响观感。
4. 比较源形、静止姿势与游戏垂臂/抬臂姿势；判断是静止几何过长，还是只在特定动画中被拉伸。不要用修改截图的方式做几何验证。

新角色初次适配及肩宽修改后都做这项检查。纯贴图或隐藏补丁不要求重做身体。

### 肩线斜坡不一定是颈长变了

UnendingFlame三角色V8收窄Shoulder/UpperArm几何锚点X，却保留目标Y/Z。2026-09-14用户指出颈根到肩峰出现不自然斜坡。实测目标颈根到上臂根高差约8.38/11.87cm，源按当前体型换算仅约3.21/3.28cm；只改宽度不能恢复源锁骨方向。

其V9按颈根相对源向量恢复三维几何锚点，原生骨架和V8权重保留。源索引匹配肩线的平均高度误差下降，颈部、实际面部与领口采样高度未变；之后用户于2026-09-14反馈“挺好的”，接受当前可见效果，未扩大为全部动画认证。这个案例不意味着所有肩部都应整体抬高：须同时查看皮肤轮廓、连着肩膀的衣物、原生运动枢轴和抬臂姿势。源T姿势与目标参考姿势不同，应说明比较范围。头部可能是独立对象，不能以身体颈顶网格的Head权重范围冒充完整头高或下巴。完整测量、方法和复用边界见[肩线指南](SHOULDER_CONTOURS.md)。

## 修复边界：头整组移动，不缩头、不动已认可的肩宽

从**最新已认可部分所在版本**创建新候选，不重新运行全身重定向。Wasakura v5以v4肩宽版为输入，而不是重新从v2开始。

- 头、脸、眼睛、耳朵、头发和头饰保持一致的平移，尺寸不变。长发即使末端低于胸口，也不能因高度低而排除。
- 颈部皮肤向领口平滑衔接；项圈、丝带、混合权重接口单独盘点。不要默认所有附件都应平移相同距离。
- 肩宽、胸腹、腿脚、身体尾巴、UV和材质冻结。不要用整体缩放、更大的头或重新加宽肩膀掩盖问题。
- 当前方法保留原生骨架/rest pose，只改绑定网格。改变原生骨长或骨架引用是另一条高风险路线，不属于本局部补丁。

## 本例位移场

以下假设所有点已处在同一Z-up坐标和单位中，Head/Neck是已核实的语义组，原权重已经归一化：

```text
z0 = 颈根锚点高度
z1 = 头部锚点高度，要求 z1 > z0
d  = 经测量和可见检查确定的下移量
t  = clamp((z - z0) / (z1 - z0), 0, 1)
s  = t²(3 - 2t)
z' = z - d * (wHead + wNeck * s)
x' = x，y' = y
```

纯Head顶点总是平移d，包括垂到腰下的头发；纯Neck在颈根位移为0、顶部为d。其它组无Head/Neck正权重则不动。**不能只用全局高度遮罩，否则长发会被压短或接口错位。**

该权重方法只适用于已经审核过归属的模型。若头发仍有独立骨链、附件混用Chest/Neck或包含未归一化权重，先显式映射完整头部家族/连通区域与接缝，不盲目套两个骨名。同位置的不同对象若权重不同会得到不同位移，必须查接口。

纯Neck且权重常量时，过渡区最小纵向导数为 `1 - 1.5*d/(z1-z0)`，要求为正以避免该简化场折叠。这个条件**不保证变化权重下完整三维Jacobian为正**，更不能代替抬头/低头时的皮肤与领口检查。缩短过多时重新设计过渡范围，不降低断言阈值。

可复用纯函数：[neck_fit.py](scripts/neck_fit.py)，测试：[test_neck_fit.py](scripts/test_neck_fit.py)。不导入Blender，不读写游戏，不自动选择区域或比例。

## Wasakura 实测参数与证据

| 目标 | 颈根/头锚点高度（cm） | 整组下移（cm） |
| --- | --- | --- |
| Geras | 170.988 / 182.404 | 5.137 |
| Peacemaker | 158.096 / 168.561 | 4.709 |
| OmniMan | 158.096 / 168.561 | 4.709 |

本例取锚点跨度的45%，**不是新角色通用比例，更不是所有模型都下移5cm**。另一模型必须重测露颈长度、头饰归属及过渡空间。纯Neck常量权重场的理论最小导数为0.325；本例未以此声称做过完整空间Jacobian审计。

每目标58,532顶点中，14,995点发生改变；42,933个无头颈权重点完全不动，另有颈根附近未移动点。13,866个纯Head点的平移残差低于0.00001cm。XY、UV、权重不变，骨架不改。43个同世界轴导出姿势含Neck/Head；它验证导出一致性，**不是43种游戏动作实机通过**。

只Cook body并移植进各自v4完整包，最终只body chunk改变，贴图/原头/头发/装备隐藏及容器header保持原字节；允许header变化的通用策略仍需明确白名单。完整三件套备份、安装后核对hash。

本机工程标识 `MK1/wasakura_triple`：`shorten_neck_v5.py`、`package_neck_v5.py`、`deploy_neck_v5.py`；每目标有 `Reports/neck-v5/local-delta.json`、`fbx.json`、`geometry.json`、`final-qa.json`，安装记录 `deployment-neck-v5.json`。这些是角色/路径/旧版哈希受限的案例脚本，不直接当作通用构建器执行。便携文档不携带模型、游戏资源或本机路径。

## 必留验证与验收范围

1. 记录基线hash、坐标单位、z0/z1/d、归属范围及变更点数。
2. 纯头部尺寸、统一平移残差；非修改集合逐点一致；UV、权重、骨架与肩宽冻结。检查颈部接缝、项圈/领口、头发是否压入衣物。
3. 中立、转头、低头、抬头及抬臂姿势可见检查；FBX同世界轴回读；最终包模型回读及非body chunk字节比较。
4. 原生动画枢轴未随可见头部下移，仍可能产生旋转弧线偏差或碰撞穿插，必须实机检查，不能说动画接口已完美适配。
5. 用户“脖子好了很多”记录为当前可见颈长改善，保留原话；不改写为全场景无穿插、全LOD或终结技认证。不覆盖历史报告的 `runtime: untested`，另记运行反馈。
