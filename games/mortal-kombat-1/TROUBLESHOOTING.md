# 故障定位速查

Riptide 后续已证明：灰色与强绿色自发光须分开定位；先读身体实际 native MI，检查父级与显式/继承标量，再做单角色最小实验。Noob v6、Ermac v7 已接受，不再试旧跨角色 Ashrah 方案；见 [材质补丁指南](NATIVE_MATERIAL_PATCHING.md)。材质失败不授权重绑已通过的脚鞋。手机有图却灰时先查玻璃覆盖和源形态键。

| 现象 | 先采集证据 | 下一项最小实验 | 不应得出的结论 |
| --- | --- | --- | --- |

## 顺序原则

### Karin Y 三角色补充

| 现象 | 先核对 | 最小修复与禁忌 |
| --- | --- | --- |
| 指节静止时就像折叠管 | 源/目标各指段方向、掌面、roll和虚拟端点 | 补齐每段旋转/缩放与掌腕衔接；骨名和FBX往返正确不代表手形正确 |
| 收头肩后上衣变短 | 同源顶点的腰封上缘/胸口/领口距离，旧Spine与新Chest场接口 | 身体/内外衣/腰封共同高度映射；不单独拉外衣或反复放大头 |
| 蝴蝶结/饰物离腰封很远 | 源连接根、各附件独立变换、前后及高度间隙 | 相关组按修正后的腰封使用共同源锚点；不连袜饰/腿带一起猜测平移 |
| 雨手里仅剩水球，手杖不见 | Gear真实网格、Staff/grab_location骨、隐藏名单 | 撤销经确认的武器覆盖和其路径/store；不能按名字排除Gear就是武器 |
| 大片纯黑但其它贴图正常 | 面→源页对应、页高与PNG/UV原点、Cook真实像素 | 修UV/矩形对应；不先假定源材质黑或shader有错 |

流程与量化样例见 [手部与上半身](UPPER_BODY_HANDS.md)、[Karin Y案例](cases/KARIN_Y_TRIO.md)。

### PicodraTech 三角色补充

| 现象 | 先核对 | 最小修复与禁忌 |
| --- | --- | --- |
| 腹部膨胀、头身怪异 | 轴向/径向缩放、源/目标关节距离 | 统一横向体型尺度，仅轴向适配骨长；不按每段 XYZ 等比放大 |
| 短裤被盖住、胯部穿插 | Hips 到左右髋关节距离、跨对象位移场 | 骨盆/裤子/大腿根共同映射并连续过渡；不只反复刷大腿权重 |
| 鞋裤跨腿异常长边 | 顶点所属腿权重、连通区域、边长比 | 按同侧骨权重归属脚，不按 x 正负 |
| 背带/前帘仍存在 | skin cloth 和装备独立资源 | 目标原生 render 索引隐藏；替换 body 不会自动隐藏所有服装 |
| 参数有效但原脸/面罩残留 | 保存参数、实际进程、Face/Mask 独立包 | 增量覆盖已审核原生索引；不重复增加同一启动参数 |
| 新增头部包断言/崩溃 | native export count、bundle、store entry | 保留多 export 原生合同；face 和 body 都是 SkeletalMesh 不代表包结构相同 |

### 共通顺序

1. 用户截图优先于先前“应该成功”的叙述。明确承认实际现象，不把原版Sindel误认成Nyako。
2. 每个截图/崩溃绑定**已安装hash和进程**，否则无法区别缓存与新包。
3. 当前状态存入PROJECT_STATE；旧测试日志只作历史。不要靠不断prepend“最新”制造多个互相矛盾的状态入口。
4. 没有日志支持的原因写“假设”；同一候选同时改两个变量后的崩溃不能用于单因果结论。
5. 先检查资产保存/读取/加载，再研究视觉算法。前者失败时继续刷权重没有意义。
6. 每次安装完整三件套，先退出游戏。失败候选不丢弃，移出加载目录留审计。

## 操作环境细节

某些终端偶发CreateProcess access denied，本案例重试相同只读命令、禁用login shell可恢复；不要据此自动提升权限或关闭安全设置。Windows终端Unicode标题可能触发GBK错误，子进程可设置 `PYTHONIOENCODING=utf-8`。

游戏为自绘DirectX窗口。适用时使用窗口控制技能，按exe及唯一HWND定位、验证前台；传输按键成功不等于已进入斗士。菜单会自动切换演示战斗，操作应连续而不是每次等待很久。已知稳定布局不要每键一截图；关键checkpoint和用户截图足够。
