# 手部、上衣比例与腰封连接

由 Karin Y → Rain / Smoke / Scorpion v9 的修复归纳，用户于 2026-09-14 表示“可以了”。[案例](cases/KARIN_Y_TRIO.md)记录版本与证据边界。本页是诊断和构建指导，不是任意角色的一键绑定算法。

## 1. 手指移到了关节，不等于朝向已适配

先看静止手掌，再看屈指。如果静止时已呈手风琴状折点，检查源几何到目标骨架的变换；不要直接重刷权重。Karin Y 旧构建器仅给近端/中段指骨新锚点和全局缩放，方向仍为 identity；末端又继承错误方向。骨名、骨序和 FBX 往返全部一致，仍能得到扭曲的手。

每只手分别执行：

1. 取得求值后的源手腕、食指/小指根、各指节及有效指尖；验证拇指命名和左右映射。不能假定所有源骨尾都是实际指尖。
2. 用手腕与指根建立源/目标掌面。手掌可固定手腕，拟合四个指根及掌面法向辅助点；记录各锚点残差、矩阵奇异值和行列式。多点不一定能被一个仿射变换精确匹配，不能隐藏残差。
3. 为近端、中段、末端分别提供明确的起止点与掌面参考法向。使用沿轴拟合长度、横截面保留共同体型尺度的变换；掌面用于确定 roll，不能只对齐一条轴就认为旋转完全确定。
4. 验证每段起止点残差、正定向、指节过渡及掌腕接缝。前臂横截面与掌面不一致时，在已审查范围内解决腕部扭转。
5. 同视角查看静止、张手、逐指屈曲、组合握拳和武器握持；再做源候选/FBX的同世界轴数值检查及最终包回读。数值一致与变形外观是两条独立证据。

可用正交标架表达方向变换：

```text
u = normalize(segment_end - segment_start)
v = normalize(cross(palm_normal, u))
n = cross(u, v)
B = [u, v, n]
A = B_target * diag(s_axis, s_cross, s_cross) * transpose(B_source)
p_target = target_start + A * (p_source - source_start)
```

轴与法向近共线时须改用有依据的参考方向，不能归一化零向量。保持手的实际影响槽数；查看器只显示四权重不是将八槽数据截断的许可。

本例掌根拟合误差约 0.28–0.45 cm，指段虚拟端点误差接近数值精度。为了原生关节匹配保留了目标指段长度，因此不能同时宣称手是源模型的严格等比复制。此权衡须在新角色重新评估。

### 1.1 末端方向与刚性手掌回退

末端指骨没有命名子节点时，不能因字典中没有`end`就回退为identity旋转。使用该骨实际tail或经源几何证明的虚拟指尖，记录末端轴向与roll；否则近端/中段看似正确，指尖仍会扭曲。

若源与目标逐指rest roll严重不兼容，而任务优先要求手形稳定、未要求逐指屈曲，可采用有界刚性回退：整只手掌和全部指节几何使用同一源/目标掌面变换，并将其目标权重合并到对应Hand骨，仍随前臂/手腕整体运动。几何变换与最终驱动骨必须同时切换；“逐指几何变换 + 单Hand骨权重”会把多套rest pose烘进同一骨，Karin Chrome v5已否定该路线。

刚性回退会减少逐指动作，只能绑定明确验收范围。武器握持、握拳、特写或需要独立指节时仍应完成逐段标架与动作验证。Karin Chrome → Reiko / Liu Kang v6b采用刚性回退后获当前可见效果接受，详见[案例](cases/KARIN_CHROME_REIKO_LIUKANG.md)；这不是新角色默认方案。

## 2. 收头颈以后，同时检查腰封上方的衣长

“头小了、脖子短了”不是上半身整体比例正确的证明。若上胸改用新 Head 锚点，而腰封仍沿用旧 Spine 变换，过渡区可能把衣料挤成很短的一段。

使用源模型的固定顶点集合对比，不能每版各选一个看起来相近的位置：

- 标定腰封上缘、上衣中段、胸口、领口和下巴，记录源坐标及候选坐标。
- 计算源距离乘共同体型尺度后的目标值，再测候选中同一集合的距离。
- 同时检查皮肤、内层和外层衣物；只拉长外衣会造成新的层间错位。
- 头部大小、头肩位置、衣长分别记录。若只改衣长，冻结头组、肩宽、手部和下身，不通过反复改头大小掩盖衣长问题。

本例上衣固定两段源高度集合的预期间距约 6.507 cm，v7仅3.496 cm；内层为6.548对3.663 cm；身体为5.537对2.944 cm。v9在核心躯干采用共同源高度映射，在腰胯和上颈平滑接回保留区域：

```text
z_core = s_body * source_z + d
z_new = old_z + membership * transition(source_z) * (z_core - old_z)
```

`d`来自已审核的共同锚点，不能把它作为凭视觉猜出的固定下移量。身体/衣物/腰封在核心区须共用场，独立挂件和低垂长发则依几何语义排除。仅有相同骨骼祖先不足以决定 membership。

过渡位置、覆盖集合和尺度都是案例参数。C1平滑本身不证明单调或无折叠：新角色检查纵向变化、局部边长、轮廓及弯腰姿势；本例的固定高度跨度检查不等于全空间 Jacobian 证明。横向不需调整时明确断言 XY不变，禁止顺手重做肩宽。

### 2.1 长大衣helper与连续躯干场

源衣物的`Jacket_*`、腰带、拉链或模拟root最终以Hips/Chest为祖先，只说明源控制层级；不能据此把全部helper权重直接合并到最近人体祖先。Karin Chrome v4的静态轮廓正常，游戏动画仍出现从下摆拉到脚边/体侧的长片，说明静态rest检查无法替代运行时驱动语义。

先按顶点实际权重区分躯干主导、袖/肩主导和独立附属物。躯干主导衣物可使用与身体共同尺度一致、沿源高度在Hips–Spine–Chest间平滑过渡的场，并把目标权重改成相同的三骨分布；已经使用此衣物场的顶点不要再叠加body pelvis修正。袖/肩保留手臂影响。检查几何场和权重场成对一致、下摆局部边长、前后片接缝、弯腰与抬臂，而不是只看A/T pose。

该方法不自动适用于尾巴、长发、独立裙片或挂件。它们即使父链也落到Hips/Chest，仍可能需要独立源形和锚点策略。

## 3. 腰封是一组挂件的连接基准

多个相关挂件分别用自己的最高点定位，会让每件都“保持了自己的根部”，却破坏蝴蝶结、绳结、刀饰与腰封之间的关系。单独下移整个腰封、腿部带子和挂件，也不能消除前后方向的空隙。

先查源骨架的真实连接根和源几何，区分属于同一组的附件与独立裙片、袜饰、腿带。对需要共同恢复源相对位置的一组，使用同一相似变换：

```text
d = sum(w_i * (belt_target_i - s_body * belt_source_i)), sum(w_i) = 1
attachment_target = s_body * attachment_source + d
```

锚点取自源连接根附近的腰封表面，并绑定源/候选相同顶点索引。共享平移保证整组相对源位置，不保证每个接缝点精确贴面。记录锚点范围、权重、中心残差、挂件间相对位置及侧视间隙；必要时独立处理根部接缝，不能谎称整条接缝已焊合。

如果随后改变了腰封或躯干，必须从修正后的腰封重算挂件锚点；不要沿用旧版平移。独立尾巴的源形恢复可参照 [附属物指南](APPENDAGES.md)，但不同语义组未必应共享同一锚点。

## 4. 必须保留的交接证据

- 源哈希、活动形态键、求值顶点、当前已安装基线及新候选身份。
- 手掌拟合残差、每个指段方向/长度、静止与组合屈指对照。
- 同源索引的腰封/上衣/胸口/领口距离，身体与内外衣层的结果。
- 挂件组、源连接根、共同锚点和各组空间关系。
- 骨架/权重/UV/拓扑以及范围外几何不变；需要变化的项目明确列出。
- FBX相关动作往返、最终容器几何/UV、非修改chunk一致性、安装哈希及实际用户反馈。

失败候选留在非加载目录作诊断证据。新增用户反馈扩展了修复范围时，更新候选与说明；未安装的版本不得写成部署里程碑。
