# 几何、骨骼与服装规范

新绑定先按 [RETARGET_CHECKS.md](RETARGET_CHECKS.md) 记录实际输出。下面的比例与胯部规则已在两组角色重复验证；共享 [retarget_math.py](scripts/retarget_math.py) 提供轴向/横向分离、显式末端尺度与共同骨盆场，避免再次复制出旧错误。

## 原生骨架是动画接口，不是体型模板

保留目标原生骨骼名称、顺序、父子关系、局部 rest/bind 及引用。角色之间骨数不同：本案例 Sindel221、原 Karin Kitana200，不把任何一个写成通用常量。

源人体主骨链按语义映射；不要仅凭名字近似批量合并所有裙子、袖子、发饰骨骼。本案例原生221骨的展示候选让部分二级骨跟随最近人体祖先，牺牲了完整动态；这是明确限制，不是以后都应该删动态骨的规范。

**源比例默认保留。**案例早期逐段按原生骨长缩放，使头/双马尾与腿的缩放不一致；后续局部修正才达成用户认可。后续项目优先选择统一体型尺度，然后解决关节点兼容，不先套用本案例0.835505头部比例。若必须改变头身比，测量原模型和目标，记录偏移量和用户选择。

## 头颈比例

调整头颈后重新测同源顶点的上衣长度，尤其头组使用新尺度、腰封仍沿旧Spine场的情形。Karin Y v7把预期6.507cm的上衣跨度压到3.496cm；v9以共同高度场恢复身体/内外衣/腰封，同时冻结头肩和手部。不能用“颈长好看”替代躯干检查。

头部尺度正常仍可能脖子过长。新适配及肩宽变更后，分别检查可见下巴→颈根/领口距离和骨架Neck→Head锚点距离，二者不可等同。需要局部缩颈时，冻结已认可体型，头部/长发/头饰统一平移、颈部连续衔接；方法、边界和实际验收见 [NECK_PROPORTIONS.md](NECK_PROPORTIONS.md)。不能通过缩头或修改原生rest pose绕过比例问题。

## 单位与求值

- 本案例的可靠 FBX 中，mesh 与 armature 数据都是厘米量级，scene unit scale为0.01，object transform为identity。
- Blender模型显示正常、glTF关节重合，不足以证明UE可用。UModel/glTF会归一化单位，曾掩盖raw skeleton根缩放100、子骨位移1/100的问题。
- 按原生原始序列化 FTransform 审核：旋转、平移、缩放、骨序及parent都检查。修复root不能只改某个显示比例。
- 烘焙/求值后按 indexed vertices 比较。导出前后改变父级时保护world matrix；防止饰品“飞走”或双重变换。
- 序列化检查通过后若恢复原生FTransform，只允许在已证实同骨序/同层级的候选上替换对应数组，不能扫描到一个同样骨数就盲写。

## 袖子和手

手指本身扭曲还可能来自错误静止朝向。Karin Y旧近端/中段指骨仅移锚点、未旋转源指段，产生手风琴状折点；修复掌面、每段方向及腕部衔接后改善。不得一律按袖子权重问题处理。详见 [手部与上半身](UPPER_BODY_HANDS.md)，包含不精确掌根拟合与原生指长的限制。

Kitana Karin 问题：袖子有手掌/手指后代的权重，导致手指动作牵拉袖口。成功修复是识别独立袖子区域，将那些权重转给现有同侧前臂helper；其余几何、UV和骨架不变。**不是把所有衣物统一刷到前臂。**

raw buffer存在8影响槽，原模型部分顶点用7槽；glTF路径可能只显示最强4个。读写时保留真实影响数，不根据viewer导出来的4权重覆盖原始8槽。

验证：单独转动手掌/手指，袖子不应随手部变形；再检查前臂、肘部动作仍跟随。候选应有“修改集合外完全不变”的断言。

## 平底鞋与高跟骨架

Riptide 补充：源 `Foot_HighHeel=1` 是脚在凉鞋内部的必要形态，不等于整只凉鞋外底应踮起。先正确求值，再保持源鞋形和外底朝向，不能再次按 native Foot→Toe 旋转整个鞋。脚、凉鞋、踝饰必须使用同一相容场，小腿宽范围平滑衔接；相关源形态键缺失与权重问题分开排查。只移动鞋、只恢复脚型、只调地面高度分别都可能留下另一类错误。

本例 v5 以同侧 Foot 保持鞋底刚性并获脚鞋可见效果接受；不是要求所有鞋型都取消 Toe 权重。源 `Hip_OFF` 还需与身体/短裤共同骨盆变换配合。完整回归与案例量值见 [Riptide 三角色](cases/RIPTIDE_TRIO.md)。

目标Sindel高跟参考姿势不能直接扭成源平台平底鞋。案例保持源鞋形、左右分开平移缩放、同侧Foot刚性权重，静止鞋底低点约0.3cm；该值只属于此模型/姿势。

**必须同时检查：**鞋底形状、source ankle到shoe floor距离、native Foot pivot、Toe motion、袜口高度、小腿长度和转动后的地面接触。固定脚底正确不等于脚踝动画轴心正确。

本案例平底几何对应的脚踝约25.21cm，而原生pivot约13.28cm，存在约11.93cm差异；最终用户接受了当前可见效果，但不能宣布这种差异不存在。后续目标应尽量将原生动画pivot与源鞋脚结构协调，并测试抬脚、踢腿、蹲伏。不要为消除静止穿地而把整条腿拖到鞋上。

## 膝盖和袜口的两次教训

1. 原来Sock整个应用鞋部位移，但皮肤是分段衰减，袜口被抬到native knee附近，出现外撇。改为和皮肤使用一致位移场。
2. 线性过渡区太短，即使权重/骨骼正确，也会把小腿上段压成额外折点。沿小腿中心线检查纵向导数，再检查空间Jacobian和posed surface，而非只检查“没有负坐标”。

本案例旧minimum纵向导数3.465，相对原生适配段150.165仅2.3%；更宽平滑过渡后54.02。纯小腿107采样点的最小相对体积Jacobian从0.0271升到0.4025，均非负；非负只排除了局部翻转，**不等于人体形态合理**。

可复用的平滑函数：

```text
t = clamp((source_height - start) / (end - start), 0, 1)
w = 1 - 3*t² + 2*t³
position = native_aligned*(1-w) + flat_foot_adjusted*w
```

start/end必须根据新的源模型、脚踝、膝盖及位移大小选择。案例0.08–0.32米仅用于Nyako；不同单位不能直接使用。鞋、袜、皮肤、脚踝饰物的相关区域使用相容位移场，鞋子本身保持刚性。

## 最低姿势检查

尾巴、长飘带等不要直接套用身体的分段形变场。绑定到人体祖先与静止源形适配必须分开；完整流程和根部锚定公式见 [附属物源形恢复](APPENDAGES.md)。

静止、左右膝30/60/90度、脚踝俯仰、脚趾弯曲、肘部、手指；用侧面和斜侧面检查。比较源与适配后的关节附近网格中心、过渡带和轮廓。FBX重新导入后以相同**世界转轴**施加同一动作，不能仅按各自local X转动就认为角度相同。

posed FBX数值一致证明导出未引入漂移，不证明姿势本来就好看。仍需可见检查和实机反馈。glTF导入器可能建立骨骼显示用的球体mesh；回读统计只包含实际skinned mesh，排除非蒙皮可视化helper。

## 三角色补充：轴向长度与横向体型分开

PicodraTech 旧实现将每段骨长比应用到 XYZ 三轴。源 Spine→Chest 约 8.41 cm，Tanya 对应段约 21.90 cm，约 2.6 倍系数把腹部也撑大。改为仅沿骨段轴拟合长度，横截面采用统一体型尺度，头部末端组使用同一尺度策略。不能只修腹部、却让头沿用隐式 1.0。

本例统一尺度约 1.500348（四肢长度比中位数），仅为案例值。每个新源/目标重新测量；目标关节位置不是源人体横截面形状。

## 骨盆、短裤与大腿根共同适配

径向修复后仍出现大腿根插进盆骨、短裤被挤没：源 Hips 与左右髋关节间距不同于目标，逐权重/逐骨段变换不保证相邻对象一致。

- 以左右髋关节中点对齐，共用体型尺度，平滑调整髋关节间距。
- 皮肤、短裤、皮带附近使用相容空间形变，向大腿与躯干连续过渡；检查同位置跨对象映射，不只看单对象包围盒。
- 量化短裤垂直尺寸、裤口/大腿间隙、边长比，检查屈髋/屈膝。静止无穿插不等于所有动画通过。
- 平底鞋保留源鞋形，不旋转 Foot→Toes 去匹配原生高跟倾角。鞋/袜/小腿连续过渡；按原始腿部权重判定左右，**不能只按 x 正负**，宽松裤脚可能跨中线。必要时由所属连通区域补充判定，并对冲突项报警。

v8 曾出现跨脚连接、异常长边，离线失败，未部署；v9 修正后再入游戏。案例数字与证据见 [三角色案例](cases/PICODRATECH_TRIO.md)。

UnendingFlame V6再次使用共同骨盆场后，用户认可此前大腿根/裤子与鞋部的可见效果。源Hips到髋中点约7.67cm；旧Shorts高度约29.34cm，正确共同尺度后约19.78cm，源约12.89cm。这里裤子是变形且被遮住，不能仅凭截图说几何变短。约24741核心点的共同场残差约1.2e-7m，外层短裤静止近表面代理的明显内穿点比例约6.5%→0。具体尺寸、阈值和游戏反馈范围见 [案例](cases/UNENDINGFLAME_TRIO.md)。

几何归属与骨骼回退必须分开。共同人体场适用于源皮肤及贴身覆盖物；独立尾巴/飘带即使最终跟随Hips，也需检查是否应该采用单一相似变换，不能自动全部纳入骨盆场，见 [APPENDAGES.md](APPENDAGES.md)。

## 单位回读不要产生假阳性

FBX 重导入后的对象 0.01 变换可能只是单位换算。比较须在同一坐标与单位下进行，同时分别审核 mesh/armature 数据与 object transform；不要把未换算 world 距离误报为尺寸错误。Blend 留有源对象也不自动意味着导出了双份，先查 FBX selection 规则及最终包实际网格。
