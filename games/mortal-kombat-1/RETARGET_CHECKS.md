# 新角色重定向：重复故障的预防检查

Karin Y补充：检查 [手指朝向、上衣跨度及附件组连接](UPPER_BODY_HANDS.md)。必须记录每个指段的起止/roll，及收头后同源顶点的腰封→领口距离；仅检查导出前后相同会把错误静止几何也判成通过。

PicodraTech 与 UnendingFlame 两组任务都出现过“头小、躯干放大”和“胯部穿插、裤子被遮住”。这些问题已经有文字经验，仍在另一套构建代码中复发。因此新源模型/新骨架的绑定应把下面的检查写入实际构建报告，而不是只记录“已读 playbook”。用户已有授权仍有效；本页不要求额外确认。仅修已接受版本的附件时，做局部差异检查即可，不重跑完整绑定。

## 1. 分开记录三个尺度

在同一坐标/单位中测量源与目标四肢关节长度，选择有依据的统一体型尺度 `s_body`（两例采用四肢骨长比中位数）。每个骨段沿轴尺度 `s_axis` 用于适配目标关节距离；横截面尺度 `s_perp` 用于保留源宽厚和明确的体型微调。

```text
u = normalize(source_end - source_start)
R = 将源骨段方向旋转到目标骨段方向的旋转
A = R [s_perp I + (s_axis - s_perp) u uᵀ]
p' = target_start + A (p - source_start)
```

头部等末端组必须显式使用共同尺度或已说明的单独尺度；禁止 `else: Identity` 隐式退回1倍。不能因为没有末端关节就把头留在源尺寸。头发/耳朵/头饰使用一致的头组策略。

构建报告应包含实际矩阵及源/目标段长、沿轴尺度、两个横截面有效尺度、头部有效尺度；用垂直于源骨轴的两个单位向量通过实际矩阵求长度，避免仅检查配置值。`Spine` 约2.60倍的骨长比若无理由同时作用到宽厚，拒绝该候选。不能把本例1.53或6%写成新模型通用参数。

至少检查一组等高对照：源、适配前、候选。区分整体尺寸与局部比例，检查头、胸腹、肩宽、骨盆、衣物，不只量总包围盒。若仅局部修下半身，应断言头颈/上半身非修改集合保持一致。

进入下一项前增加头颈检查：记录源/候选的下巴→颈根及领口可见距离、头高、肩宽、Neck/Head锚点；在中立、垂臂和头颈姿势下对照。肩宽修改后重新看颈长，但不要无证据称其改变了颈部Z。局部修复需有头组平移残差、颈部/项圈接口与非修改集合报告，参考 [头颈指南](NECK_PROPORTIONS.md)。本项属于比例检查，骨盆不涉及时无需为它重跑骨盆场。

肩部检查的完整方法见[肩线指南](SHOULDER_CONTOURS.md)：源/目标三维颈根→锁骨/上臂根向量、同源皮肤采样、实际面部与领口、相连衣物及保护区。仅修改肩宽X而沿用原生高差曾使UnendingFlame V8形成长斜坡；V9恢复三维几何锚点后获接受。此项应在上方比例检查阶段完成，不能等到骨盆或实机阶段才首次看肩线。

## 2. 骨盆先建立共同空间场

Umbrella→Homelander/Conan v7再次暴露“报告里写了pelvis_common_space，但实际顶点仍仅使用Hips/UpperLeg独立矩阵”的漏洞。只有记录髋中点与残差不算执行共同场。v8以源索引实际更新皮肤/裤子/上段大腿，并报告核心顶点到同一个映射函数的残差、保护区不变、裤口近表面距离和选定屈髋姿势。离线穿插指标改善，后获当前可见身体/材质效果接受；柯南武器另需修复，见[Umbrella案例](cases/UMBRELLA_HOMELANDER_CONAN.md)。不要将“已读”“存在测量字段”或“FBX回读相同”替代实际场应用与可见性检查。

**先核对真实父链，不能仅按名称拼接脊柱。**9b3d 四目标的旧脚本把 `Hips→Spine→Stomach→Chest` 当作连续链，但源 `Stomach` 实为 Hips 的子级腹部辅助骨，位置低于 Spine。把它映射到原生 Spine2 后，Spine 段方向向下折返，腰腹和腰封出现内陷/挤压；FBX 往返一致也没有发现这个建模错误。骨段端点须核对真实祖先关系和源/目标轴向，辅助腹骨应按局部人体区域处理，不能冒充主脊柱。腰腹修复还须检查腰封与蝴蝶结是否共用几何场及连接权重；长挂带按挂件整体处理，不按其低垂高度套进腿部场。该例 v5b 的当前可见腰部恢复已获用户确认；T1000 后续材质 v8 保持相同 body。见 [9b3d案例](cases/9B3D_QUAD.md)，不扩张为全动作保证。初始 v5 因仅按高度且未完整排除手臂/手指而误包含同高度手指顶点，在最终回读被拒绝；局部修复必须同时按语义范围保护非躯干顶点，不能只把“范围外不变”写成对错误范围本身的自证。

绑定前分别量：源Hips、左右UpperLeg髋关节、Spine/Chest、膝盖，以及目标同类关节。计算两侧髋中点 `C_source/C_target`，对比 `s_body * (source_Hips-C_source)` 与 `target_Hips-C_target`。二者不同意味着独立Hips与大腿变换在同一点会给出不同结果；不能期望归一化权重自动消除空间冲突。

核心区先使用共同映射：

```text
delta = p - C_source
core = C_target + (s_perp*delta.x, s_perp*delta.y, s_body*delta.z)
core.x += (target_half_width - s_perp*source_half_width)
          * smoothstep(clamp(abs(delta.x)/source_half_width, 0, 1))
          * sign(delta.x)
```

此公式假设当前共同坐标框架X横跨髋部、Z朝上；其它轴向须先转换。核心皮肤、裤子、腰带、上段大腿要应用同一场，再以源坐标的高度和明确的几何归属向膝盖/腰部平滑过渡。记录过渡起止及核心范围，验证横向Jacobian和纵向连续性。极端收窄使映射翻转时，修设计，不降低阈值。

**共同人体场不等于所有Hips权重物件都套该场。**长尾巴、飘带等独立附属物须按几何连通区域和锚点选择保源形策略，见 [附属物指南](APPENDAGES.md)。骨骼归属用于运动，不能单独决定静止几何变形范围。

检查与部署条件：

- 记录皮肤/裤子/腰带在核心区的映射残差；同位置跨对象不能因原始权重不同而分离。
- 对比裤子纵向尺寸与源尺寸×体型尺度、裤口位置、裤口与大腿的间隙、边长变化。被遮住不等于几何变短：UnendingFlame旧短裤高度约29.34cm，修正后约19.78cm，源约12.89cm。
- 用近表面距离或碰撞检测辅助定位，但说明方法限制。最近法向符号并不是严格实体内外判断；不要把“负距离比例0”写成完整动画无穿插证明。
- 静止与屈髋/屈膝均做可见检查，再做同世界轴的导出/包回读一致性检查。姿势数值一致只证明导出没破坏模型，不证明原始适配好看。

## 3. 鞋底与脚踝一起解决

记录源左右脚踝、源真实鞋底、原生Foot/Toe枢轴和候选鞋底。用腿部正权重/已审查连通区域判定左右，禁止按顶点x正负归脚。保留源鞋形，并让鞋、脚踝、袜/护腿、小腿共享相容的位移过渡。

不能把整个人抬高到脚不穿地，也不能强行旋转源平底鞋去贴原生高跟姿势。0.3cm静止鞋底目标只是本机候选值；需结合真实游戏地面重新评估。源到目标的补偿量不是实机测得的下陷深度。

## 4. 单位检查在回填RefPose之前

检查源求值结果 → 厘米数据/identity对象 → FBX → Cook中的全部骨名、顺序、parent、局部旋转/位移/scale。原始根scale为1仍可能有子骨位移缩小100倍；UnendingFlame旧骨盆 -0.995 与原生 -99.5 就是这种情况。

只有骨序/层级和单位均已证明相同，才可在已识别数组内恢复原生RefPose。定位器不仅匹配骨数，还须验证骨信息和FTransform；Kenshi的顶点区曾出现上千处整数201，单靠计数模式会误命中。原生文件名也可能标错，必须核对嵌入的包路径/包ID。

## 5. 图集与遗漏部件也建立合同

同一布局清单同时提供面→源材质页、UV矩形和PNG矩形。UV `(u,v,w,h)` 到PNG的顶部坐标为 `(1-v-h)*resolution`，不是省略页高的固定象限公式。逐页比较源像素、对应UV区域和最终Cook回读；“整张图压缩误差低”不能发现图片放对自身但放错UV区域的问题。

盘点实际资源类及引用链，名称只用于搜索：Body、Face、Hair、Gear、ClothMesh及布料替代渲染资源分别列出。不能只匹配`SK_`；本次残留金属发束属于无此前缀的`Sektor_Gear005_Helmet_Cloth_ClothMesh`。不要因名字像cloth就清空物理数据；只改完整索引证据支持的render范围。

## 6. 每种任务的最小变更范围

| 当前工作 | 必查输出 | 允许改变 |
| --- | --- | --- |
| 新源/新骨架绑定 | 尺度矩阵、骨盆/裤口、鞋、raw骨架合同及相关姿势 | 明确计划中的mesh/纹理/隐藏资源 |
| 已认可体型后的胯部修复 | 共同空间场、非修改集合、裤子/鞋、最终body回读 | body + 必须的容器元数据 |
| 已认可肩宽后的颈长修复 | 头组刚性平移、颈部接口/姿势、非头颈集合不变、最终body回读 | body + 必须的容器元数据；肩宽/纹理/隐藏冻结 |
| 图集位置修复 | 同一UV矩形清单、源页与Cook逐页比较 | D及明确要改的UV；其它页/资产冻结 |
| 原发/饰物隐藏尾项 | 原版渲染资源、完整PSK索引、native store及差异 | 单个已审查hider新增/更新 + header/manifest |

每套容器必须独立ID。不同输出目录都使用同名`cooked.utoc`可能派生同一ID；不能以最终文件名不同视为独立。核对当前格式toc/header ID一致及活动自定义包的ID唯一性。已认可纹理/隐藏chunk优先逐字节复用，避免重Cook引入无关元数据变化。

上述几何算子有标准库参考实现与故障回归测试：[retarget_math.py](scripts/retarget_math.py)、[测试](scripts/test_retarget_math.py)。它们是基础算子，**不是自动绑定器**；实际构建器仍需读取源、划定归属范围并输出上述测量。项目记录模板保留每项报告入口，未测写未测，不能用手写passed代替实际检查。
