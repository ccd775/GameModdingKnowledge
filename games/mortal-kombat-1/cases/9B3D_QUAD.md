## 材质合同要追到运行时最终赋值

原生 mesh 的默认 MI 只是一条起始路径。T1000 模板包含 `SetBaseMaterialOverride`，自身 MO_Base 有两组基础材质；此外装备蓝图的默认对象 `ObjectOverrides` 会把 `Body` 绑定到装备身体 MI。源码名称、蓝图 ImportMap、默认对象属性与目标 Export ID 共同构成证据。

只改皮肤 MI、继承另一层自身 Body001、调整 MO_Base、给覆盖目标显式添加纹理，均先后出现离线回读正常但游戏仍灰的结果。最终在原累积候选上补齐装备身体 MI 的 Color／Normal／ART／CSM 图集引用后，用户确认正常。

通用排查顺序：

1. 锁定已安装三件套、进程启动时间与所选皮肤/装备。
2. 从 mesh 材质槽追到叶 MI、父级和纹理。
3. 检查模板蓝图、皮肤蓝图、装备默认对象的 ObjectOverrides、重新赋材质函数，以及 MaterialOverride 表。
4. 对真正被消费的 MI 解析参数 Info/Value，核对纹理对象 ID、包 ID 和图集像素/UV语义。
5. 做单角色最小增量，独立回读后用实际预览或用户反馈验收。

不能把某个父级 ID 相同、ExpressionGUID 不同、UModel 显示图集或光泽发生变化当作单独的成功/失败原因。v8 是含前面改动的累积版本，没有剥离对照，不宣称装备补丁单独足够。细节见 [原生材质指南](../NATIVE_MATERIAL_PATCHING.md)。

## 腰腹辅助骨不是主脊柱

源 Stomach 实为 Hips 子级辅助骨，位置低于 Spine。按名字构造 Spine→Stomach→Chest 会使方向折返，即使骨名、FBX往返和Cook都正确，腰腹仍塌陷。

修复使用共同源比例场统一腰腹皮肤、衣身和腰封，并让蝴蝶结、铃铛、挂带共用连接锚点及根部权重。长挂带按附件语义保持源形，不随高度被纳入腿部场。只按高度排除部分上臂名称曾漏掉同高的手指；最终加入完整手臂/手指语义保护及坐标、权重不变断言。参见 [重定向检查](../RETARGET_CHECKS.md)、[上半身与挂件](../UPPER_BODY_HANDS.md)。

## 其它复用经验

- 黑色眼睛需区分透明反光层与虹膜；统一材质不支持源 alpha 语义时，本例退去反光层并保留蓝色虹膜，不通用删除所有透明面。
- Gear 也可能是战斧等武器。按网格、骨骼与附着点判定，不按目录统一隐藏。
- Cook 的单点零法线可通过完整缓冲匹配、位置/UV/语义权重和同角色有效基线定位，必要时修复完整切线/法线框；不能扫零字节批量替换。
- 材质修复冻结已接受 body，原生 MI/store 保留合同，多 export 蓝图不套单 export normalize。
- 安装工具尚未完成时不能启动测试；并行项目改变其它包时用已保存快照和各工程记录核对，不撤销别人的合法部署。
