# 材质与贴图（v2.0.0.2）

## 1. G1T 存储

- `[I]` 本作的 G1T 是版本 `0066`、存储类型 3：64 KB tile 逐块 zlib，不满一个 tile 的小 mip 放在不压缩的线性尾部。
  完整格式见 [G1T v0066](G1T_FORMAT.md)（8 个原版样本，解码后重新编码能还原原版的解压字节）。
- `[I]` 浪人崛起的大贴图是 DX12 64 KB tile、不压缩（存储类型 1）；tile 内的排布相同，外面多了一层 zlib 分块。按线性读同样会看到「左右两半是副本」的假象。
- 工具：`n3_g1t.py`（decode / encode / constant，按模板容器写回，只改块数据、块表、尾部偏移和文件大小）、`n3_g1t_resize.py`（换尺寸：mip 做到 4×4，
  够一个 tile 的 mip 走 tile，其余进尾部；写之前用解析器读回，逐张和 DDS 比较）。
- 压缩字节与原版不同（Python zlib 在任何级别都和原版流不完全一致），解压后的字节相同。游戏照常加载。

## 2. 运行时贴图：TextureAlias 与染色变体

- `[I]` 静态 KTID（模型自己的贴图表）**不是**运行时用的那张。装备的每个染色变体都有自己的 KTID，对象在 TextureAlias 库 `0xD956E4A2` 里。
  运行时按存档里的染色选变体表，静态表的修改会被盖掉。
- 定位当前染色的方法（build8 用过，可复用）：
  1. ETW 文件读取追踪（`etw_reads.py`），按阶段列出游戏读过的 G1T。
  2. `find_variant.py`：在某个阶段读过的贴图里，找格式、尺寸和 alpha 图案都与参考贴图一致的那张。COLOR 的 alpha 是镂空遮罩，同一件装备的染色共用它。
  3. `alias_ktid.py --tex <G1T>`：找指向这张贴图的别名对象。
  4. `raw_ref.py`：找引用这个对象的变体 KTID。
  5. 把变体 KTID 的槽改指向 Karin 的贴图（`ktid_repoint.py` / `ktid_setref.py`），或直接复制一张已经改好的变体表。
- `[C]` 忍者上衣：静态 KTID `0xa154a11c`，变体 KTID `0x6d86101a` / `0x6e81661f`；存档当前用的颜色变体 `0x411dc165`。
  只覆盖了静态颜色和这一个染色，其余染色没有测。
- `[C]` 武士上衣：静态 KTID `0x1357ac92`，染色变体 `0x9be5f13c`（存档当前染色，ETW 证实）、`0x0690cf8a`、`0x8240560e`、`0x96273b38`、`0x664a0076`。
  当前染色的 COLOR 是 `0xd24c5175`（`find_variant.py` 按 alpha 图案匹配，差 0.3）。5 张变体表的槽 0–6 全部指向 Karin 的图集和常量贴图（直接复制忍者那张变体表，槽序相同）。
- 武士部件在主菜单阶段的追踪里只读到上衣和袴；进关卡阶段才读到手甲、额饰和当前染色贴图。切换流派时不读任何模型：两套装备在进关卡时都已载入。

## 3. 槽位语义

| 槽 | 内容 | 本案例的处理 |
| --- | --- | --- |
| COLOR | 颜色；**alpha 是镂空遮罩** | 4096 BC7 图集（2×2：服装、头发 / 脸、身体皮肤），alpha 255 |
| NORMAL | 法线 | 平坦 (128, 128, 255) |
| SHADING | 着色参数 | 原版均值 (10, 10, 10, 160) |
| 49 号槽 | R = 细节法线数组的层号（×17），G = 强度 | (0, 0) = 不用细节法线 |
| 24 号槽 | 细节法线数组 `0xAD4F6A70`（16 层） | 保留原版（与 UV 无关） |
| DIRT | 实为 AO / 腔体图，按模型 UV 采样 | 指向白色默认贴图 `0x634BDE65` |
| 47 号槽 | 未明 | 指向默认 `0xBBC1ADE7` |

- `[C]` 忍者上衣贴图集 0（KTID `0xA154A11C`）：COLOR `0x8B541440`（BC7 2048 → 4096）、NORMAL `0x7F1EB597`（BC1 2048）、SHADING `0xE0739E0C`（BC7 2048）、
  49 号槽 `0x52244783`（BC5 1024）。用 `ktdata.py usage` 审计过，这四张没有别的模型在画。
- `[C]` DIRT `0xAF626E1D` 和 47 号槽 `0xE3E99A7E` 与同贴图的兄弟上衣 `0x6EC977DE` 共用：不改贴图内容，只把 Karin 那件的槽改指向默认贴图。
- `slot_defaults.py` 统计每种槽类型最常见的小尺寸默认贴图，以及指向它的对象（KTID 里存的是对象，不是贴图哈希）。

## 4. 图集

- `n3_build_g1m.py` 写 G1M 时把各部件的 UV 映射进图集的四个区域，并写出用到的区域（`atlas_uv.json`）。
- `n3_textures.py` 按这份区域表拼 4096 BC7 图集，UV 覆盖范围以外做 push-pull 填充，避免 mip 和 BC 块把背景色混进岛边缘。

## 5. 教训

- build2 / 3：以为 COLOR 是 `0x8b541440`，实际运行时用的是变体 `0x411dc165`。ETW 证明前者在启动时根本没被读。
- build4：手臂子网格只改了 shader / material，没改 +12 的材质组，仍然用紫色网眼袖子的贴图（[技术合同](TECHNICAL_CONTRACTS.md) §3.2）。
- build5 / 6：嘴部出现「牙齿框」和边缘虚线 = 原版 DIRT（AO）按 Karin 的 UV 采样。改静态 KTID 无效，必须改变体 KTID。
- build8 第一版：只改了武士上衣的静态 KTID 和两张变体，运行时用的是第三张变体，所以仍显示武士盔甲的花纹。
