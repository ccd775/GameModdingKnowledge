# 表情（v2.0.0.2）

读写：`fpose.py`（g1fpose / g1frani）、`face_bones.py`（每根骨的权重质量和质心）；拟合：`n3build/n3_face.py`；检查：`checks/facecheck.py`、`checks/blinkgap.py`。

## 1. 面部系统

- `[I]` 面部完全由骨骼驱动：骨号 400–737，其中 718–737 是控制骨，不蒙皮。
- `[I]` **每个玩家模型都带完整的面部骨**（基础身体、头、忍者 / 武士上衣、头发……），这些骨号属于基础身体的骨架，全角色共享。
  所以 Karin 的脸放在上衣里也会被表情系统驱动。
- `[I]` 各模型的面部骨绑定姿势不完全一样（头与身体 / 忍者上衣有 162 根骨差到 0.9 cm，武士上衣又不同），但眨眼、下巴、眉毛的主驱动骨在身体、头、两件上衣里完全一致。
- `[I]` 面部数据都在 fdata `0xeb8ece01`。

### 1.1 g1fpose（姿势库，magic `1FPO0011`）

- 头：`+16 u16 记录大小（48）, u16 姿势数, +20 u32 骨数, +24 u32 记录数, +28 u32 1`；然后每根骨 `(u32 骨号, 姿势数 × u32 记录偏移（从 +32 算，0 = 这个姿势不动这根骨）)`；
  然后是记录：`f32 缩放 xyz, pad, 旋转向量 xyz（弧度，骨局部）, pad, 平移 xyz（父空间，cm）, 1`。
- 姿势 0 不用。面部骨在绑定姿势下与世界轴对齐（骨 400 挂在头骨 12 下）。
- `[B]` 女性用 `0xc76b3a43`（389 个姿势，骨号到 737）；男性 / 其他：`0x2af2b5dd`、`0xa5cd5c80`、`0xb44b4394`（388）、`0x63a63830`（327，骨 320–453）。

### 1.2 g1frani（姿势权重动画，magic `1FRA0020`）

- 头：`+12 u16 32, u16 4, +16 u16 4, u16 60（fps）, +20 u32 通道上限, +24 u32 帧数, +28 u32 对数`；`+32` 起 `(帧数 + 1) × u32` 帧数据偏移（从 +32 算）；
  帧数据 = 若干 `(u16 姿势号, f16 权重)`。
- `[B]` `0x5ca044ef`：600 帧，游戏中的待机脸；姿势 41 / 42 在第 81、443 帧到 1.0（**眨眼**，41 = 左 / +X，42 = 右）。
- `[B]` 26 个单帧文件是表情预设，大量用到 5/6 皱眉、3/4 压眉、59/60 嘴角上扬、87/88、135/136、139/140、145/146。`0x0f31a047`（1001 帧）属于另一套骨架。

## 2. 方法：逐顶点拟合面部骨权重

`n3_face.py [--extended]` → `face.json`，`n3_build_g1m.py … --face` 写入。

1. Karin 的脸（`Body` 网格，3633 个顶点）移进裙摆所在的子网格（主体调色板已用到 83 / 85 项）。
2. 每个映射的游戏姿势取最多 6 根驱动骨：平移最大、旋转 ≤ 0.25、在基础身体 / 女性头 / 两件上衣里绑定姿势一致、不是控制骨。
   结果因此不依赖游戏从哪个模型取面部骨的静止姿势。
3. 对每个顶点做非负岭回归：「姿势 × 权重」≈ Karin 对应形态键的位移（形态键位移来自 `blender_shapekeys.py`）。
4. Karin 的脸约为原版的 1.7 倍（眼在 ±6.3 对 ±3.8；满眨眼时上眼睑移动 3 cm 对 1.2 cm），面部骨权重会大于 1（最大约 4–7），
   头骨吃负的剩余。全部量化到同一个 f16 网格，**总和精确为 1**（离线复算静止漂移 < 1e-4 cm）。

映射：

| 构建 | 游戏姿势 → Karin 形态键 | 残差 |
| --- | --- | --- |
| build10（基础，已装） | 41/42 → `blink_L/R`；1/2 → `mayu_up_L/R`；3/4 → `mayu_down` × 0.4；187 → `kuchi_A` | 眨眼 RMS 0.22 cm（目标最大 4.5），下巴 0.09，眉 0.2 |
| build10b（扩展，未实机） | 再加 27/28、39/40 → 眨眼；59/60 → `kuchi_smile_1`；160 → `kuchi_A` × 0.4（优先级 0.3） | 眨眼 0.27，下巴 0.11 |

不映射：5/6（驱动骨横移，Karin 的怒眉是下压，残差 60%）、147/148（左右驱动骨不对称）。

## 3. 证据

- `runtime-load-pass`（build10，主菜单，agent 实机）：静止脸正常；40 张面部连拍里第 15 张抓到眨眼，右眼闭成一条线，左眼剩一条缝（眨眼曲线只在第 81–83 帧满 1.0，加上视角斜）。
  说明上衣里的面部骨确实被驱动，**大于 1 和负的权重照常生效**：若被截断到 [0, 1]，眼睛只会合上约 1/4；若丢了负权重，静止时就会变形。
- `runtime-confirmed`：用户「表情尚可」（build10）、「目前游戏中是有表情的」（build11 测试时）。
- 离线（`checks/blinkgap.py`）：满眨眼时位移最大的 205 个顶点沿目标方向走到 92–100%，缝最大 0.25 cm，左右对称；待机脸第 0 帧的整套姿势混合
  （含未映射的 147/148 0.32、5/6 0.19）只让 Karin 的脸移动 0.14 cm。
- 张嘴只有下颌带动下唇；Karin `kuchi_A` 里上唇上抬的那部分没有驱动骨（沿目标平均 48%）。
