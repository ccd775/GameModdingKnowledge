# 仁王3（Nioh 3）

## 范围

本目录整理 PC 版《仁王3》（光荣特库摩 Team NINJA 的 KT 引擎，`Nioh3.exe` v2.0.0.2）用 Karin_Original 替换女性主角的可复用合同。
资料来自 2026-10-28 → 10-31 的一个项目，共 24 个构建：

| 交付 | 内容 | 最高证据级 |
| --- | --- | --- |
| 里程碑 1：模型替换（build1–8） | 整个 Karin（头、头发、耳朵、尾巴、衣服、鞋袜）写进忍者 / 武士两件上衣。主角的基础身体、捏脸头、发型和测试存档的其余装备共 13 个模型隐藏。贴图走装备染色变体自己的贴图表 | `runtime-confirmed`（用户：「看起来模型和材质可以了」，build7 忍者）；武士流派 build8 由 agent 实机自测 |
| 表情（build10） | Karin 的脸蒙到游戏共享的面部骨（骨号 400–737）上，由游戏自己的姿势库驱动：眨眼、抬眉 / 压眉、张嘴 | `runtime-confirmed`（用户：「表情尚可」「目前游戏中是有表情的」）；关卡内的喊声、受伤、过场表情没有单独检查 |
| 里程碑 2：次级物理（build9–21） | Karin VRM 自带的 37 条弹簧链改成 NUNO type-4 骨链：耳朵、刘海、侧发、双马尾、丝带、裙摆 16 条、尾巴、鞋标 | build20 关卡里第一次有物理；build21 `runtime-confirmed`（用户：「其他都看起来挺好的」） |
| 袜子里的皮肤（build22–23） | 源模型的换装形态键按高度遮罩，把袜子里面的大腿皮肤收进去 | build22 `runtime-rejected`（「袜子末端能看见锥形」）；build23 `runtime-confirmed`（「锥形没了，袜口也正常」） |
| 裙摆碰撞（build24） | 裙摆单独一组碰撞体：原版腿部的 5 个椭球加 2 个按 Karin 臀部拟合的椭球 | `offline-accepted`，已装进测试机，等用户实机 |
| 可再部署包 | `install / verify / uninstall`，只带自制文件；13 个隐藏模型由安装器从玩家自己的游戏数据生成；按原版 sha256 拒绝不符的版本 | 测试机上安装 → 校验 → 卸载 → 重装通过；build23 包由用户实机确认 |

哈希名、骨号、子网格号、偏移和计数都是 `build-sensitive` 快照，只对 v2.0.0.2 有效。拟合参数、链参数、碰撞椭球是 `case-derived`。

### 与 KT 引擎其它目录的关系

- 和《浪人崛起》（`games/rise-of-the-ronin/README.md`）、《真三国无双 起源》共用 `_DRK` 资源表 `root.rdb/rdx`、IDRK fdata、
  KTID / kidsobjdb 和 G1M / G1T。浪人便携包的 `g1m_tool.py`、`g1t_tool.py`、`ktdata.py` 在这里逐字节原样可用，本作便携包里带了同样的副本。
- **哈希名和浪人有一部分相同**：女性捏脸头 `0xB24CAC84`、基础身体 `0x4BA258DF`、TextureAlias 表 `0xD956E4A2`、
  CharacterEditor 库 `0xB290631C`。内容是本作自己的，不能照搬浪人的结论。
- 和浪人**相反**的地方：
  - 调色板里存的是骨架**存储序号**，不是骨号；
  - 加载走资源表注入，不用散装文件加载器；
  - G1T 是 v0066 存储类型 3（逐 tile zlib）；
  - 次级物理是新增的 NUNO type-4 骨链，要同时改 SM1G / ONUN / LLOC / MESH_LOD 和两个外部资源。浪人的规矩是「SM1G、LLOC、ONUN 保持原样」。

## 主要结论

- **不用 DLL 加载器**。把覆盖文件不压缩地放进一个新 fdata 容器，给 `root.rdx` 加一个容器槽，再重写 `root.rdb` 里被覆盖的记录，让它们指向新容器。
  - 这和社区工具 yumia_fdata_tools 的做法相同（[技术合同](TECHNICAL_CONTRACTS.md) §1）。
  - 首次使用时备份原表；游戏更新以后旧备份会过期，要能识别出来。
- **运行时贴图走 TextureAlias**。装备的每个染色变体都有自己的贴图表，静态贴图表的修改会被它盖掉。
  - 用 ETW 文件读取追踪看游戏真正读了哪些贴图，再按 alpha 图案找出当前染色的那张（[材质与贴图](MATERIALS_AND_TEXTURES.md) §2）。
- **隐藏原版部件 = 三角形塌缩成零面积**，文件长度不变。被替换模型里原有的子网格、材质和 MESH_LOD 组一个都不能删，
  也不能挪到别的材质：每个材质的计数资源必须和实际子网格数完全相等（[技术合同](TECHNICAL_CONTRACTS.md) §5）。
- **次级物理要四样东西齐全**，缺一样就不显示、不模拟或者崩溃（[物理](PHYSICS.md)）：
  1. 模型里的 type-4 骨链和关节、FM1G 统计；
  2. 每个骨链条目一个 MESH_LOD 类型 2 网格组，指向这个条目自己的网格；这个网格要有独立的顶点缓冲和调色板；
  3. 装备的物理注册表；
  4. 和模型完全一致的每材质计数。
  - 只看主菜单不能判断物理是否生效：主菜单里在模拟，关卡里可能完全不动。
- **表情是骨骼驱动的**。每个玩家模型都带一整套面部骨，由游戏的姿势库和权重动画驱动。
  - Karin 的脸大约是原版的 1.7 倍，按姿势拟合出的权重会大于 1，头骨权重为负，量化到同一 f16 网格后总和恰为 1。游戏照常执行这样的权重（[表情](FACE.md)）。
- **超过 85 根骨的调色板可以用 u16 骨骼索引**（BLENDINDICES 类型 7，原版女性头就是这样），上衣着色器认这种格式，上限 128。

## 核心方法

- 先用 ETW 追踪按阶段（主菜单、载入、关卡、换流派）列出游戏读的资源，确定玩家装备、当前染色、面部和物理相关的资源。
  然后再决定改哪个模型（[构建流水线](BUILD_PIPELINE.md) §1）。
- 不改骨架、动画。Karin 写进一件上衣，其余部件塌缩。原版子网格全部保留，Karin 的各部分插在最后一个材质 0 子网格之后。
- 每一个格式假设都先去远端 430 个原版模型、13259 个计数资源、2101 个注册表里做统计，再动手。
  build13–20 的突破都来自这类统计（例如「没有一个计数记录全为 0」「type-4 id 都很小且连续」）。
- 每次写回都用独立解析器读回：块差异、权重和、调色板、绑定漂移、每条链单独摆动时只带动自己的顶点。
- 一个构建只改一类东西，进实机让用户判断。

## 证据纪律

沿用本库五级：`reference-inferred` / `offline-accepted` / `runtime-load-pass` / `runtime-rejected` / `runtime-confirmed`。

- 主菜单 / 标题画面里的角色不算关卡内证据（物理只在标题画面模拟，就是这样被误判的）。
- 低分辨率的跑动截图分不清动画和物理。看物理是否在跑，要看静止时耳朵、裙摆有没有下垂。
- 用户在测试机上玩的时候，agent 不发任何桌面动作，截图也不行。

## 公开边界

本目录不含源模型、游戏资源、提取出的文件、构建产物、发行包、存档和测试机信息。
便携包里的脚本是项目脚本去掉本机路径后的副本。Karin 专属的链表、拟合常量、碰撞椭球和形态键遮罩是案例值，换模型时要按当前资源重新测量。
