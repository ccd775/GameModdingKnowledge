# 存档与外观设置（换装器）

标注同 [技术合同](TECHNICAL_CONTRACTS.md)：`[I]` = 格式不变量（在本作样本里成立），`[B]` = 随版本变化，`[C]` = 本案例数值。
工具是便携包的 `scripts/n3_miaomiao.py`（图形界面 + 命令行，用法见[便携包说明](../../portable-kits/nioh-3/README.md)「存档外观（换装器）」一节）。

## 1. 为什么要改存档

Mod 把 Karin 写进两件上衣的模型，其余部件塌缩。玩家换上别的护甲时，画面会变成别的装备，因为两件上衣的模型不再显示。
游戏有自己的「外观设置」（主城久远之隙北边建筑二楼的镜子「整理仪容 → 外观设置」）：每个部位单独选一件装备的样子，属性仍按身上的装备算。
换装器把这套设置直接写成 Mod 用到的那几件，玩家穿什么都显示 Karin。

**Mod 替换的模型来自外观设置，不是身上穿的装备。** 测试存档原本就设了外观：身上穿的是射手装束胸甲，显示的是暗行忍者装束上衣。
用 ETW 定位到的上衣模型，正是外观设置里那件的模型。把「角色必须穿哪件上衣」写成前提是错的（`rejected`，见 §5）。

## 2. 文件与加密

- `[I]` 存档在 `%LOCALAPPDATA%\KoeiTecmo\NIOH3\Savedata\<SteamID64>\SAVEDATA00\SAVEDATA.BIN`，0x9001B0 字节；同目录的 `BACKUP.BIN` 是游戏载入时复制出来的。
  `SYSTEMSAVEDATA00\SAVEDATA.BIN` 是系统存档（0x39978 字节），换装器不碰它。
- `[I]` 加密沿用《仁王》（1 代）的算法：自定义 S 盒的 AES-128-CTR、148 字节根密钥块、两层密钥流异或。实现参照 pawREP 的 Nioh Savedata Decryption Tool（MIT），根密钥块和 S 盒与它逐字节相同。
  - 头 0x158 字节用根密钥块直接派生的固定密钥；解密后是 `RNNUSR\0\0`（与浪人崛起同一套存档代码，浪人的 PC 存档不加密）。
  - 存档体的子密钥在**解密后的头 0x49 起**（k1、iv1、k2、iv2 各 16 字节）；1 代在 0x40。这个偏移是从社区编辑器 alfizari/Nioh-3-Save-Editor 附带的解密程序静态反汇编得到的（没有运行它）。
  - 计数器是 128 位大端递增；CTR 只用加密方向，S 盒不可逆也没关系。
- `[I]` 头字段：+0x08 版本、+0x10 SteamID64（游戏会核对，换账号的存档要改它）、+0x18 头长 0x158、+0x1C 体长 0x900058、+0x20 保存时间（Unix 秒）、+0x28 等级。
  `[B]` 版本字节：2026-02 的游戏写 `01 00 03 01`，2.0.0.2 写 `02 00 00 02`。
- `[I]` 校验和：明文 0x190–0x900190 每 0x400 字节求 u64 和；`total = ((total + 块和) ^ seed) mod 2^64`，seed 是 0x900190 的 u32；
  折叠 `(total // 0xFFFFFFFF + (total & 0xFFFFFFFF)) & 0xFFFFFFFF` 写到 0x900194。两种版本的存档复算都一致。0x900198 起的 24 字节不是哈希，不用动。
- **写回只异或差量**：CTR 下密文 = 明文 ⊕ 密钥流，所以新密文 = 原密文 ⊕ 旧明文 ⊕ 新明文。改动的只有目标字段和校验和，头和其余字节原样保留，不需要重新生成子密钥。

## 3. 明文结构

- `[I]` 明文从 0x198 起是扁平的记录流：`u32 标签, u32 长度, 内容`；末尾用零长度记录（标签 0、长度 0）填满。数组型记录的内容是 `u32 个数` 加若干子记录或定长结构。
- `[B]` 2.0.0.2 写出的存档记录比 2 月的多，背包从 0x240355 挪到 0x270066。**一律按标签找，不要写死偏移**（社区编辑器写死偏移，换版本就读错）。

| 标签 | 内容 | 用途 |
| --- | --- | --- |
| `0xCE1DB6CF` | u32 2；武士、忍者各一条 `0x8E43B27C`：u32 40 + 40 个 u16 物品 ID | **外观设置**。下标 0–31 按武器类型；32–36 = 头、胸、手、腰、腿。0 = 显示身上的装备，0xFFFF = 不显示该部位 |
| `0x6B52DB66` | u32 2；每种流派一条 `0x54B78304`：u32 17 + 17 个 u32 背包格序号（-1 = 空） | 真正的装备表。0/1 近战，4–8 头胸手腰腿，9/10 饰品，13 远程 |
| `0x938A61DD` | u32 0x927C0 + 2500 格 × 0xF0 | 背包。+0 物品 ID，+2 社区插件叫 transmogItemId 的字段，+0xE8 / +0xEC 武士 / 忍者装备位（0x11 未装备） |
| `0xB4801375` | u32 0x1000 + 4096 × 0x40 | 物品收集表：每项是物品 ID 和 6 个 1 字节标志 |

- `[I]` 背包 +0xE8 / +0xEC 只是装备表的缓存：只改它们，载入后装备不变，游戏按 `0x6B52DB66` 重建。
- `[I]` 背包 +2 不决定画面：改成别的装备 ID，游戏读写都保留它，画面不变。在镜子里改外观时，背包一个字节都没变。字段名来自 kassent/Nioh3-Plugins 的 `GameType.h`，不能照字面理解。
- 结构的定位方法：在游戏界面里做一次操作（镜子里换一件胸甲），保存，再和操作前的存档逐字节对比。改的只有 `0xCE1DB6CF` 里忍者那条的下标 33（2 字节）、校验和和几个计时类记录。

## 4. 换装器

- 写的值 `[C]`：测试存档原来的外观设置，Mod 换掉的正是这几件的模型：
  - 武士：头 0xFFFF、胸 0x65C0 Vassal's Cuirass、手 0xFFFF、腰 0x524B Swallowtail Waistguard、腿 0x4A28 Warrior of the East Greaves；
  - 忍者：头 0x6251 Shinobi Hood（忍者装束 头巾）、胸 0x53A0 Shadowstep Vest（暗行忍者装束 上衣）、手 0xD7C7 Sage's Sleeves（圣人旅装 臂甲）、
    腰 0x8266 Heir's Shinobi Waistguard（世嗣忍者装束 膝甲）、腿 0x61FF Flying Kato's Greaves（嶌加藤忍衣 腿甲）。
  - 两件 Karin 上衣 `0x5548953f` / `0xed9b4309` 是这两件胸甲外观的模型。名称库里这两个模型叫 Tirador: Coraza / Tropa irregular: Coraza（射手 / 杂兵胸甲），
    画面上却来自暗行上衣 / Vassal's Cuirass：几件装备可能共用一个模型、只换染色贴图。物品 → 模型的对应没有逐件核对。
  - 武士的手甲 `0x805e4050` 和 Kusanagi 头盔 `0x6a0d18db` 进关卡时会被读取，Mod 也塌缩了它们；但外观设置把头和手设成了不显示，所以画面上本来就没有。
- 只改 `0xCE1DB6CF` 两条里的下标 32–36，武器外观不动。「改回显示身上装备」把这五个值清 0。
- 检查：解密后头为 `RNNUSR`，头长 / 体长正确，校验和正确，`0xCE1DB6CF` 恰好一条、2 种流派 × 40 槽、子记录标签和长度都对。任何一项不符都拒绝。
  写出前重新解密、重算校验和、复查结构，并核对改动的字节都在允许范围内。
- 文件操作与浪人崛起的换装器相同：游戏在运行就拒绝写；先在存档旁的 `MiaomiaoBackups\` 写备份和 JSON 记录（前后 sha256）；用同目录临时文件替换；
  恢复时核对当前存档仍是那次修改的结果，有了新进度就拒绝整档回滚。只接受 `SAVEDATA.BIN`。
- 加解密用 numpy 按块向量化，整份存档约 1 秒；打成单文件 EXE（PyInstaller + NumPy）约 23 MB。

## 5. 证据与已否定的假设

- `runtime-load-pass`（agent 实机，2026-11-02，v2.0.0.2，测试机装的是替换同一批资源的伊切尔包）：
  1. 在镜子里把忍者胸甲外观换成修验者装束 → 角色消失，只剩那件衣服；
  2. 快速旅行触发存档，退出游戏；
  3. 换装器 `apply --in-place`：改 1 个部位、5 个字节；
  4. 重进关卡，角色模型回来。用户自己还没用过。
- 两种格式的存档都能解析：2 月的游戏写的、2.0.0.2 写的。
- 已否定：
  - 「写背包物品的 +2（transmogItemId）就能幻化」：游戏保留这个值但不显示（第一版换装器就是这样写的，已推翻）；
  - 「改背包的 +0xE8 / +0xEC 就能换装备」：载入后被装备表覆盖；
  - 「角色必须穿射手装束 / Irregular Troop's Cuirass」：决定画面的是外观设置。
- 做对照时，换上的外观要选模型明显不同的装备（本次用修验者装束：Karin 消失、只剩那件衣服，一眼可辨）。
- 未测：
  - 别人的存档，以及从没拿到过这些装备的存档（不知道游戏载入时会不会核对是否已解锁）；
  - 在游戏里改武士的部位，以及「忍者 / 武士风格优先」的共用开关；
  - Steam 云同步。

## 6. 测试机操作要点

- **退出游戏不存档**（会提示「尚未保存的游戏进度将会遗失」）。要存档：神社菜单按 K「保存」，或者快速旅行（会自动存档）。
- 游戏内交互（参拜神社、照镜子）的键要按住约半秒（`down e` → 等 600 ms → `up e`）；菜单里单击就行。
- 找镜子：地图上北边建筑的「整理仪容」人形图标，光标移上去按 E 设路标；或者在地图上快速旅行到「久远之隙」神社，再上楼。
- 改存档前先把整个账号存档目录复制一份；测试完放回，核对哈希。
