# 案例：Lenko → 仁王3 女性主角（2026-11-02 → 11-03）

游戏 v2.0.0.2。源模型：MMD 模型 `Lenko06.pmx`（模型注释署名 Kinsama）和 10 张颜色贴图，文件夹里没有使用条款，不随本库发布。
替换的资源和 Karin 完全相同（两件上衣写进模型，其余 13 个模型塌缩，共 33 个覆盖），几个角色的包互斥，后装的覆盖先装的。

**用户需求**：「装配表情和物理，把腰带以下的外套均匀缩短使得外套下摆末端略微高于短裙末端」。
每一版都由用户自己进游戏测试，agent 只做离线检查和 SSH 安装，不碰测试机桌面，也不截图。

脚本：便携包 `scripts/n3lenko/`，复用 `scripts/n3build/`（写入、注册表）和 `scripts/n3ichel/`（贴合函数、PMX 读取）。
构建顺序：`lenko_source.py` → `lenko_conform.py` → `lenko_physics.py` →（链点变了才需要）`lenko_coll.py` → `n3_face.py --vanilla-lids` →
`lenko_build.py textures / g1m / registry` → 校验和离线检查。

## 1. 直接读 PMX

- `lenko_pmx.py` 读几何、BDEF1/2/4 权重和顶点表情，不经过 Blender。
- 坐标：(x, y, z)_blender = (x, z, y)_pmx。这是一次镜像，所以三角形顶点顺序要反过来：PMX 原顺序下几何法线与顶点法线同向 66305 个、反向 649 个，反转后在 Blender 轴里保持同样的比例。v 坐标翻转。
- 单位保持 MMD 单位，贴合时按颈高缩放（约 9.17 cm / 单位）。
- 骨名：MMD 人形骨改成贴合脚本认的名字。
  - 她的腿部皮肤刷在 D 骨上，所以 `左足D / 左ひざD / 左足首D / 左足先EX` 映射为 LeftUpperLeg / LowerLeg / Foot / ToeBase，FK 腿骨上的 36 处权重并过去。
  - 胸部物理骨 `Chest*` 和人形骨 `Chest`（上半身2）重名，改叫 `Bust*`。
  - 捩骨不单独映射，跟随上臂 / 前臂。
- 网格按材质和三角形的主导骨族拆成 12 个部位：脸（含眼睑和口腔内部、眼睛和眉）、头皮、皮肤、头发、头饰、衣服、腿、腰带、短裙、丝带、领带、外套。
  - 一条带子（一股垂到膝盖，一股绕到左胯打成蝴蝶结）按连通块整块分出来。
  - 原模型 `Coat_Hide` 开关对应的另一版（不穿外套）没有放进去。

## 2. 版本轨迹

| 版本 | 改动 | 用户实机反馈 |
| --- | --- | --- |
| lenko1 | 40 条链：头发 12 + 长发 4、头顶饰物 4、短裙 11、外套 8、领带 1；碰撞借原版的 `legs` / `torso` / `head` 组。外套腰带以下按每个 15° 扇区「下摆比裙摆高 0.2 单位」取压缩比 k = 0.59。眨眼只拟合姿势 41/42 | 四个问题：眨眼时眉毛动、眼皮没盖住眼睛；短裙正前方鼓起一块；领带始终翘起悬空；长发整块在动 |
| lenko2 | 眨眼闭合线下移；长发每节切到 ≤ 4.5 cm，换原版长发参数；领带换头发模板；三组碰撞体按她的身体重新拟合 | 关卡里：「1、眨眼时可以看到眉毛落下了，但是没有盖住眼睛；2、外套缩得有点过短了，但是即便如此……某些地方短裙依然在与外套互相穿插」（截图：左后胯，深色裙片穿出外套的白色下摆）。另加要求：「胸部也要添加一些物理，不需要太大的强度」。长发、领带、裙前的问题没有再提 |
| lenko3 | 外套按统一比例放长到盖住短裙（k = 0.8654）；腰带以下的外套改为跟着短裙的骨链摆，外套链不再用；胸部 2 条链，权重减半；三组闭眼姿势按原版比例一起拟合 | 「身后的臀部附近的外套下摆鼓起来了一块」（截图从背后和左前侧拍；红线描出的背面轮廓是「竖直 → 斜着往外 → 竖直」） |
| **lenko4** | 外套背面腰带以下往里收，贴着短裙往下垂 | **「这次都挺好了」**（`runtime-confirmed`，用户自己在游戏里看的；没有逐项说明看了哪种流派、哪些动作） |

用户在 lenko2 之后对几处的说法做了确认：「眉毛」指的是那条粗的深色上睫毛线，在关卡里看到；外套长度选「统一比例，盖住短裙」；防穿插选「外套跟着短裙摆」。

## 3. 每一轮的原因和做法

### 3.1 短裙前鼓、领带悬空：借来的碰撞组太大（lenko1 → 2）

- 借来的原版组按原版身体做，比她大得多。静止时链点就在碰撞体里面，被推出去：
  - `legs`：胯椭球在她小腹前多出约 8 cm，大腿椭球在大腿前多出约 7 cm，前片裙链的归一化半径 r 0.64–0.66；
  - `torso`：脊柱骨上有一个半径约 25 cm 的球，中心在肚脐，在她胸下鼓出 14–28 cm，领带尖 r 0.99；
  - `head`：胸骨上的椭球是前后 118 cm 的长条，长发第 2、3 点 r 0.59 / 0.83。
- 再加上 lenko1 的领带用的是腰带垂饰模板（纯摆锤），从领结竖直下垂，就搭在那个大球上。
- 做法见 [物理](../PHYSICS.md) §4.4：保留原版图元的骨和旋转，只改中心和半轴，约束是这组所有链的非根点在静止时都在外面。领带改用头发模板（保持建模形状）。

### 3.2 长发整块在动（lenko1 → 2）

PMX 的长发每条只有 6 节，每节约 12 cm，用的又是短发参数，静止时还卡在 `head` 组的长条里。做法见 [物理](../PHYSICS.md) §3.5：每节切到 ≤ 4.5 cm，权重按顶点在链上的投影位置重新分配，换原版 50 cm 长发的参数块。

### 3.3 眨眼盖不住眼睛（lenko1 → 2 → 3）

- lenko1：原模型的まばたき要把眼睛下缘（虹膜底、下睫毛线）往上抬 0.42 cm，游戏的眨眼姿势里下眼睑骨只上移 0.02 cm，非负拟合做不出这一下，92 个顶点完全没拿到权重。
  模拟渲染里虹膜下半截露在上睫毛线下面。lenko2 把闭合线下移（[表情](../FACE.md) §2.2），渲染里满眨眼完全盖住。
- lenko2 在关卡里仍然只闭到一半。离线排除了背面剔除、构建写错（从成品 g1m 读回权重模拟，与拟合结果差 ≤ 0.001 cm）、图集 UV 越界。
  剩下的差异：游戏有三组闭眼姿势，原版女性头在 27/28、39/40 下闭到 41/42 的 82% / 85%，lenko2 只拟合了 41/42，另外两组只有 72% / 61%。
- lenko3 三组按原版比例一起拟合（[表情](../FACE.md) §2.3），之后用户没有再提眨眼。关卡里实际用的是哪一组，始终没有直接确认。

### 3.4 外套和短裙互相穿插（lenko2 → 3）

- 静止时两层之间最小隔 1.7 cm，并不穿插。穿插来自两套链各自摆：游戏不计算布和布之间的碰撞。
- lenko3 去掉外套自己的 8 条链，腰带以下的外套顶点取它下面最近的短裙表面点的权重（[物理](../PHYSICS.md) §5）。
- 用户同时觉得外套太短，长度规则改成「统一比例，盖住短裙」：取每个扇区「外套下摆至少比裙摆低 0.1 单位」所需压缩比 k 中的最大值，k = 0.8654。
  贴合后背面比裙摆低 1.1–1.7 cm，两侧和前襟低 6–8 cm（原模型的短裙后片更长）。

### 3.5 背后外套鼓起一块（lenko3 → 4）

- 不是物理。贴合后的静止姿势从截图的角度渲染出来，背面轮廓和用户画的红线一致。
- 原因：PMX 外套背面本来就离短裙 4–7 cm、离臀部 9–13 cm，在臀部下方还往外跨一级（间隙在 y 97 处 4.0 cm，在 y 91 处 5.9 cm）。这一级在缩短之前的源文件里就有，左右对称。
  lenko1 / 2 的外套短，这一段在短裙以上看不见；lenko3 放长以后露了出来。
- 排除过的另一个怀疑：左侧有两条短裙链一直延伸进蝴蝶结（到 y 78）和垂到膝盖的长丝带（到 y 40），杠杆很长，而且只在左边。
  但它们只带外套左侧（方位 20–100°）；背后 100–180° 跟的是普通裙链。
- 做法见 [物理](../PHYSICS.md) §5.2：外套背面按格径向往里收，最里层离短裙 / 丝带 1.5 cm，腰带处不动。动了 359 个顶点，最多收 3.7 cm。
  背面的径向间隙中位数从 3.10 cm 降到 2.21 cm，最小值仍是 0.91 cm。

### 3.6 胸部（lenko3）

PMX 的两条胸部物理骨各 3 骨，约 8 cm，挂胸骨 10，头发模板，不加碰撞体（点在胸腔里面）。链只拿作者胸部权重的一半，其余给胸骨，幅度因此较小（[物理](../PHYSICS.md) §3.6）。

## 4. 流程上的教训

- **先确认用户说的是哪个部位。** 「眉毛落下」其实是粗的上睫毛线。问一句比按字面去查眉毛省事。
- **用户的要求要换成可测量的规则。** 「下摆略高于短裙」→ 每个扇区的高差；被否以后，「统一比例，盖住短裙」→ 每个扇区的覆盖量取最大压缩比。
- **布料「鼓起来」先看静止形状。** 把贴合后的静止姿势按截图角度渲染一遍，和截图对比，再决定查碰撞还是查几何。
- **两层布不能各摆各的。** 只要两层用的是不同的链，静止时隔得再开，实机也会穿插。
- **主菜单的眨眼不代表关卡里的眨眼。** 关卡里可能混用别的闭眼姿势；每一组都要按原版的比例闭到位。
- **借来的碰撞组要先在绑定姿势下核对链点。** 链点在碰撞体里，就会被推出去，表现为鼓包或悬空。
- **共用测试机**：用户可能在机器上，装包前先问；远端操作只走 SSH，不碰桌面。
- **打包脚本不要整个删除发布目录。** 一个 shell 的工作目录在发布目录里时 rmtree 删不掉目录本身，脚本中途报错退出，目录被清空、README 丢了两次。
  改成先把 README 备份到目录外，然后只清空目录里的内容。

## 5. 未完成

- 关卡里眨眼实际用的是哪组闭眼姿势、权重到多少，没有直接确认（用户没有再提，lenko4 时说「这次都挺好了」）。
- 左侧连着蝴蝶结和长丝带的两条短裙链带着外套左侧。相邻裙片朝不同方向甩得很开时（离线模拟后侧被推 30°），左胯一带仍有几处外套被短裙穿过。
- 外套侧面和前襟比短裙长 6–8 cm，抬腿很高时可能碰到大腿。
- 原模型的 `Coat_Hide`（不穿外套）版本没有做。
- 过场、死亡、隐藏头盔 / 下身、NPC 与被隐藏的模型、其它游戏版本未测；Karin 案例里列的共用资源风险同样适用。
