# 案例：Karin_Original → 仁王3 女性主角（2026-10-28 → 10-31）

游戏 v2.0.0.2。源模型：Karin_Original 的 FBX（另有 VRM，物理链从它取），与本库其它 Karin 项目同源，不随本库发布。

**用户需求**：用 Karin_Original 替换主角；第一个里程碑是模型替换，之后装配次级物理和表情。用户提供了测试存档，授权在测试机上打开游戏做简单测试，
可以参考社区资料、自行下载和使用工具。后来要求「提供可再部署的mod包」。

## 1. 工具链

- 浪人崛起项目的 `g1m_tool.py` / `g1t_tool.py` / `ktdata.py` 原样可用；Blender 4.0.2 跑浪人项目的 `ko_extract_source.py` 导出源模型。
- 新写：资源表注入器 `n3inject.py`（与 yumia_fdata_tools 同一方案，不用 DLL）；G1T v0066 编解码 `n3_g1t.py`；ETW 读取追踪 `etw_reads.py` 和一组定位工具；
  NUNO type-4 读写、面部姿势库读写、每材质计数 / 注册表写入。
- 游戏在另一台测试机上：命令和文件走 SSH，界面操作走用户会话里的计划任务；截图在远端转 JPEG 再拉回。

## 3. 流程上的教训

- **在原版样本上统计，比猜格式快得多。** build13 → 20 之间的每一步都来自一次统计：430 个模型里 type-4 / type-5 id 的分布、24 个不按材质排序的模型、
  13259 个计数资源没有一条全为 0、同款带物理的原版上衣 `0xa2fd65db` 的计数与注册表。
- **物理要在关卡里静止时判断。** 主菜单在模拟、跑动截图里头发在动，都不能说明关卡里的物理在跑；这个误判让 build9f → 11 走了弯路。
- **用户描述的部位要换成可测量的量。** 「臀部穿出裙片」被换成「背面皮肤到碰撞椭球的距离」和「静止时裙摆链点到皮肤的距离」，再按这两个量拟合椭球。
- **换装形态键作用到衣服开口时，开口那圈不能动。** 一次被拒绝（build22）后按高度遮罩，下一版就通过了。
- **测试机是用户自己也在用的机器。** 用户在玩的时候不发桌面动作，截图也不行；需要的时候先问。
- 每个构建一个目录，已确认的发行包（build23）留着回退。
