# 不用 ZModeler 生成 char01.xbg

日期：2026-10-03。证据等级：**实机确认（分范围）**，范围见 §6。游戏 build 未记录，与 1.3.0 项目为同一安装；ModManager 满足 `minTntVersion 1.1.1`。

## 1. 结论

角色替换**不再需要 ZModeler**。项目自写的纯 Python 写出器可以直接从 FBX（或从 VRM/glTF 直接取网格）生成游戏可用的 `char01.xbg`。由它生成、并经用户实机认可的版本有三个：

| 版本 | 内容 | 实机结果 |
|---|---|---|
| Karin 1.4 | 1.3 的 FBX 加手指/脚跟修复，无 ZModeler 写出 | 手指、脚跟修复被认可 |
| Karin 1.5 | 在 1.4 基础上修改 XBG 骨架（锁骨缩短 4 cm） | 肩宽明显改善，骨架修改生效 |
| Karin_Original 0.1.2 | 从 VRM 直接构建，整副骨架贴合模型 | 正常读档；脸和眼睛被认可（身体细节未单独确认） |

此前的理由是"ZModeler 有 XBG 插件，自写格式风险大"。ZModeler 3 每台设备只有几天试用，这条路线难以长期维持。旧的 ZModeler 链（[操作清单](ZMODELER_OPERATOR_CHECKLIST.md)）作为历史和对照保留。

写出器脚本目前在项目工作区，**尚未迁入本仓库的便携包**。§2–§4 的格式和约定足以重新实现。

## 2. 方法：模板 + 重写网格

写出器不从零构造 XBG。它取一个**已被游戏接受的 char01.xbg 作模板**，原样保留以下内容，只重写网格相关部分：

- 文件头常量；
- 材质路径表和材质名表，即 4 个材质槽：头、外套、头发、睫毛；
- `char01` 骨架；
- 逆绑定矩阵表；
- 外套物理骨的常量块。

模板来自上一版运行包解出的 XBG（本项目为 1.3.0 包中的 `E886A8DB` 条目），其中已包含私有中性头发材质。

### 2.1 文件布局（ZModeler 布局，游戏接受）

| 区段 | 内容 | 随网格变化 |
|---|---|---|
| `0x00–0x8C` | 文件头 | 部分字段（§2.2） |
| | 材质路径表：`u32 n` + n ×（`u32 FNV`, `u32 len`, 含 NUL 的字符串，4 字节对齐） | 否 |
| | 材质名表：`u32 n` + n ×（名字, `u32 slot`） | 否 |
| | `u32 1`, 骨架名 `char01`, `u32 1` | 否 |
| | **调色板**：`u32 n` + n × `u16`（节点的 `b` 序号），补齐到 4 字节 | 是 |
| | `u32 1`, `u32 424`, 424 个节点：`u32 0x64`, 位置 3f + 四元数 4f, `u16 parent`, `u16 b`, 名字 | 改骨架时 |
| | `u32 382`, `u32 424`, **补零到文件绝对偏移的 16 字节对齐**, 382 个逆绑定矩阵（按 `b` 索引，行向量 4×4）, 第二矩阵表, 物理块 | 补零随调色板长度变；改骨架时改矩阵 |
| LOD 表 | 每个 LOD：`u32 描述符数` + 描述符 × 176 字节；然后 `u32 0` | 是 |
| GPU | `u32 缓冲区数`；每个：`u32 vbytes`, 顶点, `u32 ibytes`, `u16` 三角形列表, 补齐 4 | 是 |
| 尾部 | `u32 0`, `u32 0` | 否 |

ZModeler 还会在尾部附加 JPEG 缩略图和签名字节，游戏不需要，不写也能正常读档。

### 2.2 文件头中随网格变化的字段

| 偏移 | 含义 |
|---|---|
| `0x28` | 位置量化比例 `max(|坐标|) / 32766`（float32） |
| `0x2C` | z 半高 `aabb.max.z − center.z` |
| `0x38` | 包围球：AABB 中心 + 半对角线 |
| `0x48` | AABB min/max：全部 LOD、全部子网格的并集 |
| `0x60` | `max|x|`, `max|y|`, `0.4 × 高度`, `0.16 × 高度` |

### 2.3 描述符（176 字节，每个材质一个）

```
10 f32  包围体：中心 xyz, 半径, AABB min xyz, max xyz
u32     0
u32     tag = material | vertex_type << 16
u32     stride
u32     0
u32     vertex_offset（缓冲区内字节偏移）
u32     face_count
u32     index_count
u32     first_index
u32     vertex_count | first_vertex << 16
u32     last_vertex
u32     1（子批次数）
8 u32   子批次：0, 0, vertex_offset, face_count, index_count, first_index, packed, last
10 f32  同上包围体
name    u32 0xCC97FA4A, u32 7, "char01\0\0"
u16 0, u16 0xFFFF
```

索引相对该描述符的顶点块。每个描述符可以使用独立的顶点块。LOD1 直接复用 LOD0 的网格也能被游戏接受（Karin_Original）。

### 2.4 顶点格式

| 顶点类型 | 步长 | 用于 |
|---|---|---|
| `0x17BA` | 44 | 头部 |
| `0x179A` | 40 | 外套、头发 |
| `0x11BA` | 36 | 睫毛（无切线/副法线） |

```
0   i16×3  位置 / 比例(0x28)，i16 第 4 分量恒为 1
8   i16×2  UV0 × 32766（v 已翻转：(u, 1 − v)）
12  i16×2  UV1；常量 0 被游戏接受
16  u8×4   权重，和为 255
20  u8×4   调色板槽位（未用槽位写 0）
[24 u8×4   仅 0x17BA / 0x11BA：恒为 0]
+0  u8×4   法线 B=z G=y R=x，byte = (int)(127n + 127 + 0.5)，A = 0x40
+4  u8×4   顶点色 BGRA；FE FE FE FF 被游戏接受
+8  u8×4   切线 80 80 80 00（ZModeler 也不写切线）
+12 u8×4   副法线 80 80 80 00
```

- 三角形为**顺时针**绕序。
- 每个顶点最多 4 个权重：按权重降序取前 4 个，用全部影响的总和归一化；非最大的权重取 `(int)(w × 255)`，最大权重取 `255 − 其余之和`。
- 调色板最多 255 根骨骼（槽位是 u8）。每个子网格最多 65,535 个顶点（u16 索引）。

### 2.5 从 FBX 转换时的约定

从三组 FBX/ZModeler 输出对中拟合得出：

- **坐标**：用 FBX 网格的局部坐标，`xbg = (−x, −y, z)`，缩放 1.0。
- **绕序**：FBX 逆时针转为 XBG 顺时针，交换每个三角形的第 2、3 个索引。
- **材质**：FBX 材质名就是模板材质表中 `.material.bin` 的文件名。
- **顶点拆分**：按（控制点、法线字节、UV、顶点色）去重，保持首次出现的顺序。

从 VRM/glTF 直接取网格时，坐标轴换算为 `xbg = (−x, z, y)`。glTF 是左 +X、上 +Y、前 +Z；XBG 是左 −X、前 +Y、上 +Z。

## 3. 必须遵守的合同

1. **矩阵表必须对齐到 16 字节。** 节点表之后的逆绑定矩阵表必须从文件绝对偏移的 16 字节边界开始（char01 为 `0x6CF0`）。补零长度取决于调色板长度：v1.3 的调色板有 66 根骨骼，补 12 字节；另一份 ZModeler 样本有 68 根，补 8 字节。写出器只要照抄模板的补零，调色板一变长（66 → 70），矩阵表就偏 8 字节，**游戏会在读档进度条过半时直接崩溃**（Karin_Original 0.1.0）。重新计算补零即可修复。调色板长度不同于模板时，必须检查 `矩阵表起点 % 16 == 0`，并确认 LOD 表偏移与模板一致。
2. **只能用模板中有逆绑定矩阵的骨骼**（`b < 382`）。调色板里加入眼骨、脚趾骨等原版也蒙皮的骨骼没有问题；原版调色板有 196 根骨骼，包括这些。
3. **写完要回读**：重新解码写出的文件，逐值核对所有量化结果（位置、法线、UV、颜色、三角形、权重、骨骼）。再用项目原有的 GPU 缓冲区审计核对面数。这两道检查替代 ZModeler 链的"全新进程回读"。
4. **物理块不用重建**：只要网格不蒙皮到外套物理骨（`Ph_*`/`PL_Coat*`），从模板原样复制物理块即可。代价是没有次级物理。

## 4. 骨架可以改：身体骨骼采用绑定位置，面部骨骼不采用

| 骨骼 | 游戏行为 | 证据 |
|---|---|---|
| 身体骨骼（锁骨、手臂等） | **采用** XBG 里的绑定位置，动画只驱动旋转 | 1.5 缩短锁骨后实机肩宽变窄 |
| 面部骨骼（`Facial_Hook` 下，如 `L_Eye`/`R_Eye`） | **不采用**：面部动画把局部位置重置为 Aiden 的 | Karin_Original 0.1.1 的瞳孔被拉向鼻子、穿到眼睑前；本地渲染模拟"眼骨位置重置"后与实机截图一致 |

因此对新模型应**让骨架贴合模型**，不要把网格拉到 Aiden 的骨架上。旧 Karin 走的是拉伸路线，留下了宽肩、细长躯干和手指错位等问题。脸部顶点只蒙皮到 `Head`。

改骨架的做法：

- 节点局部平移：`t_i = R_parentᵀ (p_i − p_parent)`；骨骼朝向保持 Aiden 的不变。
- 某个节点的世界位置平移 `delta` 时，它及子树对应的逆绑定矩阵更新为 `inv' = inv · T(−delta)`。
- 改完逐个检查 `bind · inv ≈ I`。Aiden 自带的面部和外套物理骨本身就有约 0.04 的残差，这些骨不要改。
- Karin_Original 保留了 Pelvis 到 Spine2 的 Aiden 位置，因为根部和盆骨高度可能来自动画。腿部关节已移到她的位置，读档正常，但脚是否悬空或陷地还未单独确认。

## 5. 相关做法与教训

- **方向修正的支点错误**（项目特有，1.4 修复）：交接 FBX 时的方向修正步骤，用骨架空间的骨骼头 Y 在网格空间做镜像，而两个空间的 Y 方向相反。结果每个顶点沿前后方向偏移 `−2·Σ wᵢ·headYᵢ`：手指偏离指骨，握拳时扭曲拉长，脚相对小腿前移约 7 cm。修复方法是只在局部链内撤销偏移：手和手臂以锁骨为锚，脚以小腿为锚。以后若重新从 Blender 导出，必须重新应用这一修正。
- **从 VRM 直接构建**（Karin_Original）：
  - 整体缩放到 Aiden 的腿长；
  - 用双四元数蒙皮从 T 字形摆成 Aiden 的绑定姿势，并对齐手掌法线；
  - 把 char01 的关节移到她摆好姿势后的关节位置；
  - 权重按人形骨骼映射。扭转骨的比例沿用旧 Karin 的分布；长双马尾逐级把一部分权重分给胸骨；裙摆逐级把一部分权重分给同侧大腿。
- **XBT 不用 texconv**：保留 donor XBT 及其 DDS 头，逐个 mip 级用 Pillow 的 DXT1/DXT5 编码，尺寸、格式、mip 数必须与 donor 一致。见 [XBT 管线](XBT_TEXTURE_PIPELINE.md)。
- **FAT v8**：路径哈希为小写反斜杠路径的 FNV-1 64 位哈希取低 32 位。重打包时，未改动的条目逐字节保留。新 mod 换用新的 `friendlyId` 和 pack 名，就能与旧版并存于 ModManager，但同一时间只能启用一个。

## 6. 适用范围与未观察场景

已确认：

- 默认服装 `char01` 槽位的读档和外观；
- 1.4 的手指与脚跟；
- 1.5 的肩宽；
- Karin_Original 0.1.2 的读档、脸部和眼睛。

未观察：

- Karin_Original 身体的逐项检查：
  - 脚是否悬空或陷地；
  - 双手持枪：她的肩每侧比 Aiden 窄 7.3 cm，左手可能对不上枪身；
  - 走路、下蹲时尾巴和裙子是否穿模。
- 过场动画。
- 面部表情：脸是刚性的，嘴不会动，眼睛不会转。
- 次级物理。
- 其他服装槽位，以及 char01 以外的骨架。
- 超过 4 个材质槽的模板。

写出器的限制：

- 只支持模板中的 4 个材质槽；
- 每个顶点最多 4 个权重；
- 与 ZModeler 输出语义一致，但不逐字节一致：取整的最低位、调色板顺序、LOD1 共用顶点块的方式都不同。

## 7. 被推翻的假设

- "做 Watch Dogs 角色替换必须用 ZModeler"：已被三个实机认可的版本推翻。
- "动画决定所有骨骼位置，改 XBG 骨架没用"：对身体骨骼不成立（1.5），对面部骨骼成立（0.1.1）。
- "眼睛斗鸡是视线转动角度太大"：VRM 把转动限制在视线的 10/90，瞳孔只有 30% 权重在眼骨上；渲染模拟显示，只转动眼骨时瞳孔几乎不动，真正的原因是眼骨位置被重置。

## 8. 最小检查步骤

1. 写出后重新解码，逐值比对量化结果（回读通过）。
2. 用 GPU 缓冲区审计核对各 LOD 的面数。
3. 检查矩阵表起点：`(节点表结束 + 8 + 15) & ~15` 处应是第一个矩阵，且该位置 `% 16 == 0`。
4. 改了骨架时，检查所有骨骼的 `bind · inv ≈ I`，并与模板对比，确认只改动了预期的节点。
5. 渲染预览：直接用写出的 XBG 和 XBT，逐像素按 UV 采样贴图；对可疑部位模拟游戏会施加的骨骼变化，例如面部骨骼位置被重置。
6. 实机：读档、外观、基础动作，见 [SOP](SOP_WATCH_DOGS_CHARACTER_REPLACEMENT.md) §8。
