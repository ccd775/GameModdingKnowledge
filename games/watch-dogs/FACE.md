# 看门狗 char01 面部表情：面部定义 dpdx

**证据等级：**

- 2026-10-24，PC 版游戏。格式按游戏数据反推，回写原版文件逐字节相同。
- 控制名在 `Disrupt_b64.dll` 里查不到，含义是按它们动哪些骨骼推断的。
- 实机只测过一轮：Karin_Original 1.1.0-test。
  - 游戏读取了包里新增的 dpdx 条目，嘴会动；
  - 眨眼闭不严，眼珠几乎看不出在动。
- 修正版是离线验证的，**尚未实机**：Karin_Original 1.1.1-test，以及蓝白 Karin 1.7.0-test（用 `xbg_face.py` 加在 1.6.0 上）。

脚本在[便携包](../../portable-kits/watch-dogs/README.md)：`dpdx_format.py`、`vrm_face.py`、`xbg_face.py`、`face_preview.py`。

## 1. 为什么以前脸只能是刚性的

`Facial_Hook` 下的面部骨骼，局部变换由面部定义 `char01_facial_definition.dpdx` 重建，不用 XBG 里的绑定位置。

所以只在 XBG 里挪面部骨骼没用。Karin_Original 0.1.1 把眼睛绑到挪过的眼骨上，实机眼睛被拉回 Aiden 的眼位，成了斗鸡眼。之前的版本都把脸只蒙皮到 `Head`。

要让面部骨骼落在新模型上，就得**同时改 dpdx 里这根骨骼的静止平移**，并把改好的 dpdx 作为新条目放进 mod 包。底包里原本没有这个条目，要用 `package_mod.package(..., transform=)` 添加。

## 2. 格式

- 路径：`graphics\characters\char\char01\char01_facial_definition.dpdx`，FAT 哈希 `28E502D9`。
- 原版在 `windy_city.fat` 里，XMemCompress 压缩。`graphickit_parts.lib` 把它登记为 char01 的姿势定义。
- 原版 19,612 字节，100 根骨、1,169 条增量、184 个控制。

```text
0x00  u16 version (2), "Dp", u32 0
0x08  u64 文件大小, u64 骨骼表偏移 (0x30), u64 增量表偏移, u64 控制表偏移
0x28  u16 骨骼数, u16 增量数, u32 控制数
骨骼 48 字节：f32 静止四元数 (x,y,z,w)，f32 静止平移（父空间，米），u32 骨名 CRC-32，
              u64 第一条增量的偏移，u64 增量条数
增量 12 字节：u32 旋转（smallest-three：2 位最大分量序号，其余三个分量各 10 位，范围 ±1/√2），
              3 × s16 平移（1/8192 米），u16 控制序号
控制：u32 名字哈希（名字未知）
```

- 骨名是 CRC-32，99 根对得上 char01 的骨名，另一根 `8CB05FD5` 不在骨架里。
- 与 Aiden 的 XBG 对比：99 根骨的静止平移和 XBG 局部平移相差都小于 0.5 µm；旋转只有瞳孔骨不同。
- 增量按骨骼连续存放。改写时每根骨的条数可以增减，`dump()` 会重算偏移。
- 原版"无旋转"写成 `0xDFF7FDFF`，即三个小分量都是 511。不要用 `encode_quat` 编恒等旋转：它给出 512，等于 0.08° 的转动。
- `Wrinkle*` 骨用平移带皱纹贴图权重，8192 表示 1.0。

## 3. 约定（推断）

控制权重为 1 时：

- 局部旋转 = `R_rest · R_delta`，即增量按骨骼自身坐标作用；
- 局部平移 = `t_rest + t_delta`，即增量按父空间作用。

依据：

- 控制 50/51 让两眼一起转、眼睑跟着转 18°。只有按骨骼自身坐标解释，才是向下 / 向上看；
- 按同一约定，控制 55 让下巴下移 2.2 cm、后移 2.8 cm，正好是张嘴；
- 眉毛上扬的平移只有按父空间才朝上；
- 1.1.0-test 的离线渲染（按这个约定、控制权重 1）复现了实机看到的"眨眼露出一条虹膜"，间接支持这个约定，也说明游戏的眨眼权重能到 1 附近。

中间权重怎么插值没有观察到。离线预览假定旋转按角度线性插值、平移线性插值。

## 4. 控制

| 控制 | 动作 |
|---|---|
| 32 / 36 | 左 / 右上眼睑闭合：`_ELid_U` 39°，`_EPuf_U` 70°（眨眼） |
| 55 | 张嘴：`_Jaw` 20°，另带 41 根唇骨和颈部骨的修正 |
| 42 / 45、46 / 49 | 左眼、右眼左右看（约 30–36°，眼睑轻微跟随） |
| 50 / 51 | 两眼向下 / 向上看（眼睑跟随 18° / 12°） |
| 43 / 44、47 / 48 | 瞳孔骨转 90°（不是视线） |
| 35 / 39 | 上眼睑睁大（相对眨眼轴为 −0.58） |
| 14–27 | 眉毛 |
| 109/116、112/119、113、114… | 嘴角、上唇、下唇（笑、拉伸、撅嘴等） |
| 168–183 | 皱纹贴图权重 |

Aiden 的眼睑骨和眼骨基本同心（`_ELid_U/D` 共用一个枢轴，在眼球中心附近），下巴骨下面挂着唇骨和舌头。

## 5. 做法（`vrm_face.py`，配置文件的 `face` 段）

```json
"face": {"blink": {"L": "blink_L", "R": "blink_R", "gain": 1.0, "follow_scale": 0.5},
         "jaw": {"key": "kuchi_A", "gain": 1.0},
         "gaze": {"keys": ["LookLeft", "LookRight", "LookUp", "LookDown"], "gain": 2.0}}
```

1. **眼骨**：`L_Eye` / `R_Eye` 放到模型自己的眼骨上。
2. **眼睑：写成纯平移。**
   - 上眼睑用 `_ELid_U` 和 `_EPuf_U` 两根骨。平移方向取模型眨眼键位移在主平面内的两个边界方向。长度取到没有顶点需要份额之和超过 1。
   - 形态键里往反方向动的顶点归下眼睑 `_ELid_D`，用一个平移。Karin 的下眼睑会上抬约 5 mm 去迎上眼睑。
   - 每个顶点解非负份额（和不超过 1），不做平滑。
   - 平移与骨骼位置无关，所以眼睑骨不用挪。
3. **下巴**：在头部的上 / 前平面里网格搜索 `_Jaw` 的枢轴，使控制 55 最接近张嘴键。每个顶点解 0–1 的份额，再在网格上平滑两遍。
4. **视线**：
   - 每只眼用一个固定的眼骨份额，逐顶点的份额会把虹膜撕开；
   - 份额由 Look 键拟合。动漫眼是多层面片，只用最前面一层（可见的那层）拟合；
   - 每个 Look 键自动配到动作最像的视线控制，相关系数低于 0.5 就报错；
   - 拟合结果再乘 `gaze.gain`。
5. **眼睑跟随其他控制**：
   - 对 Aiden 上眼睑有动作的每个控制，取它绕眨眼轴转的角度，算出相当于眨眼的几分之几：向下看 50 为 0.445，左右看约 0.05；
   - 上眼睑在该控制下平移"这个比例 × `follow_scale` × 眨眼平移"；
   - 睁大的方向（35/39、51）不做：动漫眼睑在静止时已经全开，再往上会露出下面的东西；
   - 眼睑骨原有的其他增量全部去掉。
6. **写出 dpdx**：
   - 挪动过的骨骼（眼骨、下巴）取打好补丁的 XBG 的局部平移；子骨（瞳孔、唇骨等）保持局部偏移；
   - 写完检查每根有名字的骨的静止平移都和 XBG 一致（误差 ≤ 10 µm），不一致就让构建失败。

只有眼睑骨、`_Jaw` 和眼骨带权重，其余面部骨仍跟着头走。没有 `face` 段时，构建与此前逐字节相同。

```powershell
python -B $Kit/build_from_vrm.py --vrm model.vrm --profile profiles/karin_original_face.json --base-fat base.fat `
  --colliders colliders.json --facial-definition char01_facial_definition.dpdx --out-dir out --package ...
python -B $Kit/face_preview.py out --controls 32 36 55 42 50
python -B $Kit/dpdx_format.py out/char01_facial_definition.dpdx --xbg out/char01.xbg
```

原版 dpdx 要从游戏的 `windy_city.fat` 解出来（XMemCompress 压缩），仓库不收录。

## 6. 不是 VRM 构建器做的 XBG（`xbg_face.py`）

蓝白 Karin 1.6.0 来自 FBX 交接，FBX 里没有形态键。`xbg_face.py` 直接在发布版的 `char01.xbg` 上加表情：

1. 用相似变换（ICP + Umeyama）把源 VRM 的脸对到 XBG 的脸子网格上。1.6.0 的结果：
   - 缩放 1.657，转了 15.7°；
   - 3,254 个顶点全部对上，中位误差 0.04 mm，最大 0.09 mm。
2. 每个 XBG 顶点取最近 VRM 顶点的形态键位移，经同一变换带过来，然后按第 5 节拟合。
   - VRM 的接缝处，同一位置有几个顶点。Karin 眼睑边缘有 4 处，这几个顶点在 blink 键下会分开，最多差 7 mm。
   - 所以在这几个顶点里，取网格邻点与 XBG 顶点的邻点重合的那个。
   - 只按位置取的话，结果取决于最近邻搜索怎样处理并列：KD 树和暴力搜索给出的 XBG 不同。
3. 眼骨取"在头部这一侧、承担 Look 键顶点权重最多的关节"。
   - VRM 的 humanoid 眼骨可能是错的：`karin_picodra.vrm` 把它们指到 `Hair_tail_L` 和 `Ahoge`；
   - 脸也可能蒙皮在 humanoid 头骨的副本（`Head_3`）上；
   - 也可以在配置里用 `eye_nodes` 指定。
4. 输出：
   - 骨架：只挪眼骨和下巴（子孙随之刚性移动，逆绑定同步改）；
   - 网格：每个顶点相同的 LOD 都重写脸的权重，调色板追加新骨骼；
   - 用 `nearest` 取整重新编码，网格数据和原文件逐值相同，只有包围盒浮点差约 0.1 mm。

```powershell
python -B $Kit/xbg_face.py --xbg old_char01.xbg --vrm model.vrm --profile profiles/karin_pt_face.json `
  --facial-definition char01_facial_definition.dpdx --out-dir out
```

## 7. 实机与迭代

| 版本 | 做法 | 结果 |
|---|---|---|
| Karin_Original 1.1.0-test | 眼睑按 Aiden 的方式转动，枢轴网格搜索，份额平滑；视线份额 0.17 | 实机：读到了包里的 dpdx，嘴会动；眨眼闭不严，眼珠几乎不动 |
| Karin_Original 1.1.1-test | 第 5 节的平移眼睑；视线 ×2 | 离线：眨眼相对残差 0.18 → 0.067，眼睑边缘到位 99.5%；**未实机** |
| Karin 1.7.0-test（蓝白，基于 1.6.1-test） | `xbg_face.py`，同一 `face` 段 | 离线：眨眼相对残差 0.068 / 0.071，边缘到位 99.6%；**未实机** |

1.1.0 眨眼闭不严，有三个原因，离线渲染都复现了：

- 蒙皮份额插值的是转动的弦。份额约 0.4 时，眼睑边缘比目标高 3–8 mm；
- 网格平滑把边缘份额和不动的邻居平均，进一步拉低了边缘；
- 部分眼睑皮肤沉到虹膜层后面，闭眼时还露着一条虹膜。

动漫眼睑的行程（Karin 约 46 mm）是 Aiden 的约 6 倍。

1.1.0 眼珠看不出在动：拟合份额让控制满权重时虹膜走完 Look 键的全程（约 6 mm），按毫米算和 Aiden 自己的眼珠差不多。可是 Karin 的虹膜约 45 mm 宽，是 Aiden 的 4 倍左右，同样的位移几乎看不出来。

模型自带的 VRM lookAt 是骨骼型：眼骨权重 0.3，最多转 10°。说明模型本来就只设计了很小的眼动。

## 8. 被否定或被替换的做法

- **按 Aiden 的方式转眼睑**（1.1.0）：见上。缩放其他控制里眼睑转角的 `other_lid_scale` 随之作废，改为第 5 节的跟随比例。
- **对平移拟合的份额做网格平滑**：会把眼睑边缘往回拉；下巴仍然平滑。
- **逐顶点的眼骨份额**：会把虹膜撕开。
- **用整组眼睛面片拟合视线**：藏在头里的替换眼层离眼骨很近，转动时和可见层反向移动，相关系数掉到 0.42。只用最前面一层后为 0.88–0.96。

## 9. 离线检查

- `face_preview.py`：按第 3 节的约定，在构建好的 XBG 和 dpdx 上施加控制，用 XBG 的逆绑定蒙皮。打印静止时的绑定误差（应为 0）、每个控制移动了多少顶点、最多多少毫米。`--obj` 写出 OBJ。
- 项目里还用一个小渲染器，从正面渲染贴图后的眼睛：按位置把顶点对回 VRM，取 UV 和贴图，画家算法。1.1.0 实机看到的缝，它能复现。仓库没有收录这个渲染器，因为它绑死了本项目的路径。上实机之前先用这种办法看一眼睛，省一轮实机。

## 10. 范围与未观察

- 只做了眨眼、视线、张嘴。上唇不动：张嘴控制抬不动上唇，张嘴的相对残差约 0.6，残差全在上唇。眉毛、嘴角（笑）没有做。
- 平移眼睑、视线 ×2、`xbg_face.py` 都**未实机**。待确认：
  - 眨眼能否闭严。如果还差一点，说明游戏的眨眼权重到不了 1，可以把 `blink.gain` 调到 1.05–1.1；
  - 眼珠动得够不够。乘 2 以后还看不出，就说明那些场景里游戏没有驱动她的眼骨；
  - 向下看时眼睑压得多不多（`follow_scale`）。
- 中间权重的插值方式、游戏是否还有程序化的视线 look-at，都没有观察到。
- 只做过 Karin 的两张脸：两个 VRM 用的是同一个脸网格，同一套形态键名。
