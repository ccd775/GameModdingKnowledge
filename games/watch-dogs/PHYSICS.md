# 看门狗 char01 物理：不用 ZModeler 给替换模型加物理

**证据等级：** 两个替换模型实机测试，2026-10-06。Karin 1.6.0（FBX 路线，蓝白服装）和 Karin_Original 1.0.0（VRM 路线）都经用户实机验收并发布。所有结论都基于这台 PC 版游戏的实测；参数名没有官方来源（引擎 DLL 加了 VMProtect 壳，无法静态分析）。

脚本在[便携包](../../portable-kits/watch-dogs/README.md)：`smu_format.py`、`xbg_physics.py`、`vrm_physics.py`。VRM 构建器的配置文件里加 `physics` 段即可使用。

## 1. 物理块格式

`char01.xbg` 里，逆绑定矩阵表之后、LOD 表之前是物理块：

```text
u32 has_fcb [u32 size, FCB "nbCF"]   RFX_Legs：腿部球关节碰撞（Gibbed ConvertBinaryObject 可转 XML）
u32 n_objects, objects                 Aiden 原版 27 个对象
u32 n_table, table                     Aiden 原版 12 项
```

块内所有 4×4 矩阵都按**文件绝对偏移** 16 字节对齐（补零）。写新块时，要按对象在文件中的实际位置补零。

对象（`smu_format.py` 能读写链和 jiggle；布料对象只能读开头和碰撞表，其余没解开）：

| 字段 | 内容 |
|---|---|
| 头 | `u32 0`，`f32 params[12]`，`u32 type, sub, flag`。sub：1 链、2 jiggle、0 布料 |
| 碰撞 | A 球（骨骼名、矩阵、半径）、B、C 胶囊（`r0,0,0,r1,0,0,长度`，轴是矩阵的局部 **+Z**）、D |
| 点 / 定向记录 | E、F（空）、G |
| 节点 | 名字、半径、`u32 flags`、2 个浮点 |
| 挂点 | 骨骼名列表 |
| 连接 | `u32 0, u32 0, u32 n`，每项 `u16 a, b, kind` |
| 尾 | `u32`（0、1 或 4） |

- 名字记录：CRC-32（区分大小写）、长度（含 NUL）、字节，补到 4 的倍数。
- **节点 flags**：第 0 位表示"固定到动画姿势"（链根、布料顶排）；高 16 位是该对象挂点列表里的序号，也就是节点参考的骨骼。序号越界的节点**不会被模拟**。
- 表的项有两种：种类 2（12 字节：`u16 粒子, u16 2, u16 目标粒子, u16 0, f32 权重`）和种类 6（24 字节）。粒子按对象顺序全局编号。
- Aiden 原版的 27 个对象依次是：
  1. 11 个 jiggle（袖子、领后）；
  2. 4 条袖子链；
  3. **大衣布料**：头 `2,0,1`，130 个粒子 `PL_Coat_SMUNode_*`，挂点列表 `[L Thigh, R Thigh, Pelvis, Spine, Spine1, Spine2]`；
  4. 3 块领子布料、2 条腰带链；
  5. 拉链和口袋的 jiggle、1 条拉链链。

## 2. 游戏实际怎样用（实测）

- **链只跟随挂点骨骼的转动。** 挂在头上的链，转头时会摆；挂在骨盆或脊柱上的链（尾巴、裙子）几乎不动。匀速跑动时，没有任何参数能让头发或尾巴往后飘；急停时也只有很小的反应。
- **大衣布料会跟随身体运动**：跑动时摆动，急停时有反应，会被腿顶起。
  - 静止形状取自粒子的**绑定位置**：粒子可以随意外推或改挂，布料不会被拉回 Aiden 的形状。
  - 下摆前侧 72 个粒子挂在 `Rfx_L/RThigh_Back` 下，挂点是大腿，每一步都跟着腿走，看起来是高频抖动。
- **布料和网格之间的距离会放大抖动。** 网格顶点离所挂粒子越远（杠杆臂越长），粒子帧的每一点晃动都被放大。
  - 大衣顶点比粒子环宽 8–10 cm 时，抖动明显；把粒子外推到大衣表面后，抖动明显减轻。
  - 尾巴伸出体外 65–84 cm，直接挂到粒子上会被扭坏。
- **短裙要整块挂在胯部。** 大衣顶排固定在 Spine/Spine1/Spine2 上，转身时脊柱扭转，会把裙子顶部拽向腰带和尾巴根，两者"黏住"后不停抖动。

## 3. 做法

**链**（头发、耳朵、发带、耳机线、尾巴）：

1. 选闲置物理节点：去掉不用的原版对象后，它们的节点就空出来了。领子布料的节点有 58 个可蒙皮，另有腰带、拉链、口袋节点。
2. 节点必须 `b < 382`（才有蒙皮矩阵），并且序号大于新父节点（节点表父在子前）。
3. 节点作为挂点骨骼的子节点，放到源骨骼位置，局部 +Y 指向下一个节点，并重写逆绑定。
4. 链对象用游戏马尾的头 `4,1,1`。挂在头上时挂点列表为 `[Facial_Hook, Head]`，否则为 `[挂点骨骼]`。链根固定，自由节点挂点序号取 `min(1, 挂点数-1)`。
5. 源骨骼与节点 1:1 映射，顶点权重按源模型。

**大衣或裙子挂到大衣布料上：**

1. 保留 Aiden 的前 16 个对象（到大衣布料为止），去掉后面 11 个（领子、腰带、拉链、口袋），表里引用它们的项也去掉。
2. 粒子沿径向外推到衣服表面。
3. 挂在大腿辅助骨下的粒子改挂 Pelvis，挂点序号改为 2（Pelvis）。裙子还要把挂在脊柱骨下的粒子也改挂 Pelvis。
4. 每个顶点按"源链根以下骨骼的权重"算出摆动份额，分给按"绕身体角度＋高度"最近的 8 个粒子（高斯衰减），不跨前开口。根骨份额保持刚性。
5. 挂在链骨下的小件（口袋绳、背后蝴蝶结）整体取挂点位置的粒子权重。
6. 布料参数：重力 -2，阻尼为原版的 0.12。更轻（重力 -1、阻尼 ×0.06）会挤成一团、站着也狂抖。
7. 短裙下蹲露大腿时，可以把布料的大腿胶囊半径从 10.5 cm 调到 12.5 cm，并把静止时落进胶囊的粒子推出去。

**尾巴：**

- 蓝白 Karin：链的自由节点挂到下摆高度的背后粒子下（骨架父节点和挂点都改），拉力 0.1。
- Karin_Original：短裙在下摆处被腿踢得最厉害，尾巴只挂 Pelvis，阻尼 0.5。

**双面渲染：** 游戏剔除背面。裙子要从里面也能看见，就加一份背面副本：同样的顶点、权重和 UV，三角形绕序反转，法线取反。

## 4. 实测参数（链）

| 部件 | 重力 | 阻尼 `params[2:5]` | 拉力 `params[9]` | 结果 |
|---|---:|---:|---:|---|
| 双马尾 | -4 | 0.15 | 0.1 | 保持原形，转头时晃动 |
| 耳朵、呆毛 | -2 | 0.15 | 0.3 | 轻微晃动，不下垂 |
| 侧发、前发、脸颊发、发带 | -4 | 0.15 | 0.1 | 晃动，有脸部碰撞 |
| 尾巴（挂 Pelvis） | -4 | 0.5 | 0.1 | 稳定，摆动小 |

- 阻尼越低越柔软：0.5 比 0.9 好，1.5 太硬。
- 拉力 0.02 会明显下垂，0.1 能保持形状。

## 5. 被否定的假设

以下都**没有**产生运动跟随（匀速跑动时向后飘）：

- `params[5]`、`[6]`、`[8]`、`[10]`、`[11]` 设为 1；
- 物体头部改为 `2,1,1` 或 `1,1,0`；
- 换用不同家族的闲置节点。

尾巴和裙子早期不动，是因为挂点序号越界（自由节点用了 `0x10000`，挂点列表却只有一项），跟节点家族无关。

## 6. 范围与未观察

- 只在 Aiden 原版物理块上验证。模板必须带这块（ZModeler 或本便携包写出的 char01 都带）。
- 碰撞体：实测版本用的是 Nicky（char10.xbg）马尾和刘海的胶囊，由 `xbg_physics.py export-colliders` 从游戏文件导出，仓库不收录。不给导出文件时，用骨架推出的胶囊代替，这些胶囊**未实机验证**。
- 只有 Karin、Karin_Original 和 Karin City Noir（§7）做过实机测试。面部表情见 [FACE.md](FACE.md)。

## 7. 披肩：把大衣布料改成短外套（Karin City Noir，2026-10-07）

**证据等级：** 用户实机测了 0.1.0–0.1.2 三轮。0.1.3、0.1.4 还没有结果。

Karin City Noir 的夹克是披在肩上的短外套，下摆到臀部：背片挂在 Chest 下，两侧各两片下垂面板挂在上臂下。

**a：整件挂在大衣布料上。**
- 9 行粒子按高度线性压到夹克上：`remap_z`，把 0.566–1.326 m 映射到 0.975–1.50 m，下摆行对齐夹克下摆，固定行对齐肩线。然后沿径向外推到夹克表面。
- 130 个粒子的挂点全部改成 Spine2（`anchor_bone`）。节点顺序允许的 58 个，骨架父节点也改成 Spine2；其余 72 个改成 Pelvis。
- 前臂和手的胶囊半径从 0.2/0.15 改成 0.07/0.06（`capsule_radius`），静止时落进胶囊的粒子推出去（`clear_capsules`）。
- 重力 -2，阻尼为原版的 0.12，与大衣相同。

**b：只有背片挂在布料上，两侧四片做成上臂上的链。** 链用上臂、前臂胶囊做碰撞组 `{"arm": "L"|"R", "radius": r}`。

**辅助改动：**
- 重摆姿势时，挂在上臂下的面板保持 T-pose 的朝向，在 A-pose 绑定姿势里仍然竖直下垂（`hang`）；面板向外 2 cm、向后 3 cm（`hang_offset`）。
- 夹克上的前臂权重全部改到上臂（`weight_remap`），每侧 500 个顶点。否则弯肘时它们被拉向肘窝，肘尖露出来。

实测：

| 版本 | 结果 |
|---|---|
| 0.1.0a/b | 两种风格都保留。两者都有手肘从披肩里穿出的问题 |
| 0.1.1a | 只有跑动摆臂时手肘会露出，站立、掏枪、插兜都不穿；用户认为可以接受 |
| 0.1.1b、0.1.2b | 站着手肘也会露出（0.1.2b 的链拉力 0.3，胶囊 0.06） |

被否定：
- 整块向后倾（`hang_tilt`）：手肘间隙只从 2.9 cm 增加到 3.4 cm，下摆却往后翘很多。

单节链：模型优化器删掉了无权重的末端骨，只有一节的链（前发、耳朵）要用 `pin_parent` 把父关节作为固定根，才能摆动。
