# 排障手册

除标注外均为本项目在游戏 1.25 + Mod Enabler 1.1 上的实测。buildN 指 [Karin 案例](cases/KARIN_ORIGINAL.md) 的版本。

## 1. 显示与隐藏

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 开着 Mod 整屏发黑，`F2` 关掉就正常（build1） | 挂了全屏后处理的像素着色器；全屏 pass 沿用上一次的 IB（见过马尾的 IB），被 `handling = skip` 跳过 | 只挂角色网格自己的 11 个 PS（[技术合同](TECHNICAL_CONTRACTS.md) §2） |
| 原版的头盔 / 面罩、护膝等硬质护甲件还在（build1 早期） | 它们是单独的 IB（隼头带两个，刚体件四个，刚体件用 VS `d637f756…`） | 帧分析里逐个绘制看，补进 `HIDE_IBS` |
| 裆前挂着两条深色布条，拔刀后还在（build4） | 隼套装原版的两片布料挂件（IB `c03cb62d`、`dfeb63e0`，约 9 × 18 cm），由布料 VS `24f9a3d0d0d9c367` 画；这个着色器没挂钩，`TextureOverride` 对它不生效，所以虽然 IB 能找到也藏不掉 | 给这个 VS 加 `ShaderOverride … run = CommandListN2General`，两个 IB 加进隐藏表；影子由 Mod Enabler 的影子挂钩覆盖（build5） |
| 某个场景里角色变回原版 | 那次绘制用了没挂钩的着色器，或者换了 IB（别的发型 / 脸 / 护甲外观） | 在那个场景抓一帧，查画原版角色的 VS / PS 和 IB |
| 「半透明情况下还是原来的形象」（build4，用户报告一次，随后说已经好了） | 未复现，原因不明 | 没有改动。再出现时抓那一帧（`hypothesis`：半透明 / 抖动淡出用的着色器没挂钩） |
| Karin 整体过亮、发白（build1） | 直接用了源模型的颜色贴图和偏亮的高光常量，没有细查游戏光照 | 颜色贴图在线性空间乘 0.55–0.65；高光换成哑光常量 `spec_a`（[构建流水线](BUILD_PIPELINE.md) §6） |
| 换了 Steam 新版本后显示原版角色，不崩溃（推测） | 补丁重新编译了着色器或改了模型，哈希变了 | 抓一帧装备界面，把新哈希加进去（[验证与发布](VALIDATION_AND_RELEASE.md) §4） |

## 2. 绘制顺序与蒙皮

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 跑动时刘海整片飘进脑袋，露出额头；装备界面正常（build2b 及以前） | 关卡里右护手（宿主 A，画头发）先于其它护甲画，拿到的头骨是上一帧的；脸（宿主 B）用本帧的。跑动时差约 8 cm，脸皮挡在刘海前面 | 帧计数 + 每件护甲帧戳 + 过期的匀速外推 `M = C · P⁻¹ · C`（build2c；偏差中位 8.3 → 0.5 cm） |
| 起跑、急停的那一帧头发和脸错开 1–2 cm | 匀速外推在加速度大的那一帧不准 | 已知限制 |
| 加鬓发和裙摆的模拟骨时骨数超过 85（build4 开发，构建断言） | u8 BLENDINDICES 预乘 3，一个调色板最多 85 个条目；build3 已用 80 根 | 拆成两个合并调色板，两次 `drawindexed` 之间切 `vs-cb0`；两个影子 VS 的 cb0 布局各不相同，每个调色板在影子里也各配一份（build4，[技术合同](TECHNICAL_CONTRACTS.md) §5） |

## 3. 物理

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 转身时双马尾被瞬间剧烈拉长（build2b） | 双马尾借左右围巾的物理骨，围巾从胸口挂下来，绕身体甩大弧 | Mod 自己的弹簧链，从头挂下来，每节长度固定（build2c，[物理](PHYSICS.md) §2） |
| 狐耳、尾巴没有可见物理（build2b） | 刚性挂在头、骨盆上 | 同上，加进弹簧链（build2c） |
| 站定时裙子耷拉，穿过骨盆和大腿；走动时大腿根的皮肤从正面、侧面、后面大面积穿出（build2c） | 裙子前片借袴飘带的骨骼，站定时飘带下垂；腰胯皮肤有一部分跟脊椎转（相对骨盆中位 12°、最大 30°），裙子只跟骨盆 | 裙子权重从下面的身体抄，越往下越跟大腿（build3，[构建流水线](BUILD_PIPELINE.md) §5） |
| 只抄身体权重时，跑步抬腿把裙子前片顶穿（build3a，离线复现） | 游戏里跑步抬腿超过 50°，纯身体权重的裙摆跟不上大腿 | 往裙摆渐变到同侧大腿（Y 112 → 80 cm，最多 0.85） |
| 狐耳离线摆 10° 以上，游戏里几乎不动（build3 第一版） | 按「瞬间停下」调；游戏的停步是约 0.3 s 的减速 | 按录到的减速曲线重调（`checks/eartest.py`），30 fps 录像确认 |
| 加了裙摆物理后静止时大面积穿模（build4 开发，离线） | 每节长度取了 Karin 原骨架的关节距离，而不是权重场蒙皮后的静止位置 | 段长取静止粒子之间的距离，并沿这一节拉伸到下一个粒子 |
| 侧闪、冲刺时裙摆被甩进腿里（build4 开发，离线） | 惯性太大，大位移一帧就甩开很远 | 每帧滞后上限 `CH_LAG`（裙子 1.8 cm）、最大偏角 40°、大腿胶囊半径 9 → 11 cm |
| 尾巴「好像没有物理」（build4） | 参数太硬，跑动时尖端只偏 3°；离线测试台把骨盆固定，尾巴又挂在骨盆上，所以没测出来 | 测试台加胯部扭动，尾巴调软到跑动约 15°，碰撞体加臀和大腿（build5） |

## 4. 加载器、着色器与工具

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 自定义着色器加载失败，日志里 X3676（build2c 开发） | Mod Enabler 的 `d3dcompiler_46.dll` 拒绝 `RWBuffer<float4>` 这类多分量类型 UAV 的读取；fxc 10 放行 | 状态和镜像改用 `RWStructuredBuffer` / `RWByteAddressBuffer`；用 `c46.py` + 同一个 DLL 编译检查 |
| 帧分析里看不到 Mod 自己的缓冲 | Mod Enabler 在帧分析时跳过各 Mod 的覆盖 | 临时 `$dump_modded_meshes = 1`，用完改回 |
| 装上 3DMigoto 后启动卡住（开发时） | `d3dx.ini` 的 `[Profile]` 立体显示项 | 开发时注释掉；交付用原版 `d3dx.ini` |
| 每次启动弹 UAC「Windows 主进程 (Rundll32)」 | 3DMigoto 想更新 NVIDIA 驱动配置 | 点「否」不影响游戏（左上角提示 `Profile update failed!`）；是否允许由用户决定 |
| 启动即崩溃，崩在 `d3d11.dll` 的 std::map 解析里（2026-11-09） | 不是代码问题：测试机 SSD 前一晚 I/O 故障，把 `d3d11.dll` 的 8 KB 清零，`d3dcompiler_46.dll` 和三个 Mod 文件也坏了 | 和已知好的副本比哈希后替换；归档逐块解压校验（`n2verify.py`，20 个归档全部完好） |
| 帧分析文件夹删不掉，提示「文件或目录损坏且无法读取」 | 同一次磁盘故障留下的 NTFS 损坏 | 由用户决定是否 `chkdsk`，修复后再删 |

## 5. 存档

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 改了存档没效果 | 游戏还开着，或改的是 `BACKUP.BIN` | 换装器拒绝在游戏运行时写、只接受 `SAVEDATA.BIN` |
| 退出游戏后改存档，进游戏发现进度回退 | 退出游戏不存档 | 先在神社存档 |
| 某个部位还是原版样子 | 那个部位的外观不是隼套装（外观由装备的 +2 字段决定），或者在游戏里换了那个部位的护甲 | `inspect` 看五个部位，`apply` 重写；换装备后再用一次工具 |

## 6. 已被否定的假设

- 「玩家装备模型在归档的 G1M 包里，可以取出来改写后重打包」：按顶点数和指纹都没匹配到（[技术合同](TECHNICAL_CONTRACTS.md) §1）。
- 「3DMigoto 加不了物理，只能借原版的物理骨」：Mod 自己用计算着色器模拟（build2c 起）。
- 「仁王3 的放大眼睑骨权重也适用」：只闭到约 1/3（[表情](FACE.md) §2.1）。
- 「眨眼骨是条目 16 / 17」：它们不动；是 24 / 25（[表情](FACE.md) §2.2）。
- 「裆前两条是腰间的武器（刀鞘尖、刃）」：用户拔刀后它们还在（build4 → 5）。
- 「护胫必须是楯无护胫」：Mod 认外观，五件都是隼套装的外观（[存档与外观](SAVE_AND_APPEARANCE.md) §5）。
- 「启动崩溃是 Mod 的 ini 写错了」：是磁盘损坏了加载器 DLL（§4）。
