# 仁王2（Nioh 2 Complete Edition）

## 范围

本目录整理 PC 版《仁王2 完全版》用 3DMigoto（Nioh 2 Mod Enabler 1.1，内含 3DMigoto 1.3.16）替换女性主角的可复用合同。
主体来自 2026-11-07 → 11-10 用 Karin_Original 做的 KarinN2（build1 → build5），以及配套的存档换装器。

| 交付 | 内容 | 最高证据级 |
| --- | --- | --- |
| 模型替换（build1） | 不改游戏文件。挂钩角色着色器，按 IB 哈希跳过原版角色的全部绘制；Karin 的身体、衣服、头发、耳朵、尾巴、裙子由右手护手那次绘制代画，用每帧拼出的合并骨骼调色板蒙皮；脸由原版脸那次绘制代画 | build1d agent 实机自测（装备界面、关卡）`runtime-load-pass`；build2 起用户多次在关卡里看过，反馈都针对细节（刘海、马尾、裙子、布条、尾巴），没有再提整体外观 |
| 眨眼（build2a → 2b） | 眼睑顶点随头骨刚性移动；计算着色器读游戏眼睑骨的下落量，按比例加上 Karin 自己的闭眼形态键 | 用户：「眨眼是正常了」`runtime-confirmed`（build2b）；张嘴等其它表情没有单独检查 |
| 次级物理（build2c → 5） | Mod 自己的弹簧链（计算着色器，每帧一次）：双马尾、狐尾、狐耳、鬓发、裙摆 16 条，23 条链、58 根模拟骨；碰撞体是头、下巴、胸、骨盆、胯、臀和两条大腿 | 双马尾不再拉长、刘海不再飘进脑袋由 agent 实机确认；裙子不穿模、狐耳回弹（build3）agent 30 fps 录像确认；鬓发 / 裙摆（build4）和调软的狐尾（build5）只做了离线测试，用户实机看过 build5 后说「不错」 |
| 隐藏裆前布条（build5） | 两片原版布料挂件用单独的布料着色器绘制，按 IB 跳过不生效，要先挂钩那个顶点着色器 | 用户在 build4 指出、build5 修复后未再提出 |
| 可再部署包 | 一个 `KarinN2` 文件夹放进 `<游戏目录>\Mods\`：`karin.ini`、7 个计算着色器、网格、贴图 | 构建包重建逐字节一致；测试机上 26 个文件与发行包一致 |
| 换装器（2026-11-09 → 11-10） | 解密存档，把当前穿着的五件护甲的外观（铁匠「外观变更」写的字段）改成隼套装，清零 4 个完整性标志；自动备份、可回滚 | `runtime-load-pass`（agent 实机：改回原版护胫外观 → 画面变成原版；再改回 → Karin 恢复；游戏自动存档后标志恢复为 1） |

所有哈希（着色器、IB）、常量缓冲布局、骨号和调色板条目号都是 `build-sensitive` 快照，只在游戏 1.25（2021-02-05 首发版）上验证过；Steam 当前版本（1.27 / 1.28.x）未测，见 [验证与发布](VALIDATION_AND_RELEASE.md) §4。链参数、碰撞体尺寸、裙子权重参数是 `case-derived`。

### 与 KT 引擎其它目录的关系

- 和《仁王3》（本库 `games/nioh-3/`）、《浪人崛起》同属光荣特库摩 KT 引擎，但**本作的玩家装备模型没有在归档里找到**，所以不走 G1M 改写 / 资源表注入，而是走 3DMigoto 在绘制时替换。
- 方法上沿用仁王3 / 浪人的：骨骼仿射贴合、按原版脸迁移面部权重、一个构建只改一类东西。仁王3 那种「放大眼睑骨权重」的眨眼做法在这里只闭到约 1/3，被换成了形态键（[表情](FACE.md) §2）。
- 存档加密与仁王1、仁王3 相同（pawREP 的自定义 S 盒 AES-CTR），存档体子密钥在头 0x40（仁王3 是 0x49）；明文是固定布局，不是仁王3 的标签记录流（[存档与外观](SAVE_AND_APPEARANCE.md)）。

## 主要结论

- **按绘制替换，不改归档**。3DMigoto 的 `TextureOverride` 按 IB 哈希匹配绘制：原版角色的每个 IB 都 `handling = skip`；Karin 挂在两个宿主绘制上，用 `drawindexed = auto` 画自己的缓冲。
  - 游戏把模型存在 20 个 K300 归档的 MDLTEXPK / G1M_PACK 里，按顶点数和顶点指纹都没找到玩家装备（`rejected`，[技术合同](TECHNICAL_CONTRACTS.md) §1）。
- **Mod Enabler 只在被挂钩的着色器上匹配 IB**。`TextureOverride` 只有在运行 `CommandListN2General` 的 `ShaderOverride` 之后才生效（影子走它自己的 `CommandListN2Shadows`）。
  所以**每个画了要隐藏部件的着色器都要挂钩**：裆前两片布料用的是布料顶点着色器 `24f9a3d0d0d9c367`，build4 没挂它，布条就一直在（[技术合同](TECHNICAL_CONTRACTS.md) §2）。
  - 不要挂全屏后处理的像素着色器：它们沿用上一次绑定的 IB，会被当成角色跳过，整屏变黑（build1）。
- **一个调色板最多 85 根骨**。蒙皮顶点着色器 `73278b6e` 的 BLENDINDICES 是 u8 且预乘了 3。Karin 用两个合并调色板：A（身体、衣服，60 根）和 B（头发、耳朵、尾巴、裙子和全部模拟骨，66 根），在同一个 `TextureOverride` 里两次 `drawindexed` 之间切换 `vs-cb0`。
- **合并调色板要每帧对齐**。关卡里游戏先画右手护手（宿主 A），再画其它护甲；直接拷贝会拿到别的护甲上一帧的骨骼，跑动时头发和脸差约 8 cm（刘海「飘进脑袋」）。
  用每帧一次的计数着色器 + 每件护甲的帧戳，过期的骨骼按匀速外推一帧，误差中位数降到约 0.5 cm（[技术合同](TECHNICAL_CONTRACTS.md) §4）。
- **3DMigoto 写不出游戏自己的物理链，但可以自己算**。一个计算着色器每帧一次模拟 23 条弹簧链，结果写进调色板 B 的模拟骨。每节长度固定（不会拉长），带惯性、限幅和碰撞体（[物理](PHYSICS.md)）。
  - 最初的方案是借原版围巾 / 袴飘带的骨骼，结果双马尾转身时被拉长、裙子站着时耷拉（`rejected`）。
- **自定义着色器由 Mod Enabler 的 `d3dcompiler_46.dll` 在运行时编译**，它拒绝 `RWBuffer<float4>` 这类多分量类型 UAV 的读取（X3676），fxc 10 却放行。读写状态用 `RWStructuredBuffer` / `RWByteAddressBuffer`，提交前用同一个 DLL 编译检查。
- **眨眼用形态键，不用骨骼权重**。游戏的眼睑骨绕原版眼球转，推着 Karin 更大的眼睑往前而不是往下。眼睑顶点改为刚性跟头，计算着色器按眼睑骨（调色板条目 24 / 25）在头部空间里的下落量加 Karin 自己的闭眼形态键（[表情](FACE.md)）。
- **离线测试的动作要比游戏更狠，每条链都要单独测**。游戏里跑步抬腿超过 50°、停步是约 0.3 s 的减速；按「瞬间停下」调的狐耳在游戏里几乎不动，build4 的离线报告漏了尾巴，用户看到的就是「尾巴没有物理」。
- **画面上的护甲由「外观」字段决定，不是身上穿的装备本身**。存档每件装备 +2 是外观 ID（铁匠「外观变更」写的就是它）；换装器把五个护甲部位的这个字段改成隼套装，不要求拿到过（[存档与外观](SAVE_AND_APPEARANCE.md)）。

## 核心方法

- 用 3DMigoto 帧分析（F8）抓装备界面的一帧，解出每次绘制的顶点、IB 和 `vs-cb0` 骨骼矩阵；跨绘制按矩阵认出同一根骨（全局骨号 `g<n>`），由父子矩阵解出关节（[构建流水线](BUILD_PIPELINE.md) §1–2）。
- 把 Karin 仿射贴合到解出的骨架上，权重写成全局骨号；构建时每根骨从携带它的那件护甲的调色板里取矩阵，拼成合并调色板。
- 原版角色的绘制全部跳过；不改骨架、动画和游戏文件。
- 每一处着色器、物理、权重改动都先离线复现：Python 版蒙皮叠加截图、按着色器逐行移植的物理模拟、合成的跑 / 停 / 转身 / 侧闪动画，再进游戏。
- 一个构建只改一类东西；用户在关卡里看过才算确认。

## 证据纪律

沿用本库五级：`reference-inferred` / `offline-accepted` / `runtime-load-pass` / `runtime-rejected` / `runtime-confirmed`。

- 装备界面里的角色不算关卡内证据：绘制顺序不同（装备界面里宿主 A 是最后一件护甲，关卡里是第一件），帧对齐问题只在关卡里出现。
- 隔 0.4 s 的截图看不出弹簧回弹；看物理用 30 fps 录像逐帧跟踪耳尖、尾巴尖。
- 用户在测试机上的时候，agent 不发桌面动作，截图也不行。
- 测试机磁盘曾有一次 I/O 故障，悄悄把 3DMigoto 的 `d3d11.dll` 清零了 8 KB，表现为启动即崩溃。先按哈希核对文件，再查逻辑（[排障](TROUBLESHOOTING.md) §4）。
