# Agent 入口（仁王2 Nioh 2）

先读 [README](README.md)，再按当前问题进入对应文档。项目当前状态写在独立工程的 `PROJECT_STATE.md` 里，不在这里。
本目录只提供方法、合同和已被否定的假设。

## 接手一个新任务前

1. **核对游戏版本**：标题画面左下角的版本号和 `nioh2.exe` 的日期（本目录快照是 1.25，2021-02-05 首发版）。
   - Mod 靠着色器哈希和 IB 哈希识别部件，版本变了要先抓一帧装备界面的帧分析，和 [技术合同](TECHNICAL_CONTRACTS.md) 里的哈希逐个对照。
   - 对不上时 Mod 不会崩溃，只是显示原版角色。新版本的哈希加进去，旧的保留，一个包可以同时支持两个版本（[验证与发布](VALIDATION_AND_RELEASE.md) §4）。
2. **核对加载器**：游戏根目录有 Mod Enabler 的 `d3d11.dll`、`d3dcompiler_46.dll`、`d3dx.ini` 和 `Mods\`。
   - 制作时用的是 Mod Enabler 1.1（3DMigoto 1.3.16）。Mod 依赖它的 `CommandListN2General`。换了加载器版本先确认这个命令列表还在。
   - 开发时改过的 `d3dx.ini` 项（`hunting`、`export_shaders`、`analyse_options`、`$dump_modded_meshes`）交付前要改回原版。
3. **确认角色符合 Mod 的前提**：女性主角、长马尾发型、制作时那个存档的脸，五件护甲的**外观**都是隼套装（头带、战袍、护手、袴、护胫）。
   - 外观不对的部位显示原版模型。用换装器 `n2_miaomiao.py inspect` 看五个部位的装备和外观，`apply` 改成隼套装（[存档与外观](SAVE_AND_APPEARANCE.md)）。
   - 改存档前先备份整个账号存档目录。
4. **测试机是共用的**：用户可能正在上面玩，别的会话也可能占着桌面。
   - 发桌面动作之前先读桌面锁，确认游戏窗口在前台、用户不在用。**用户在玩的时候什么桌面动作都不发，截图也不行。**
   - 每次启动游戏，3DMigoto 都会请求管理员权限更新 NVIDIA 驱动配置（UAC「Windows 主进程 (Rundll32)」）。不要替用户点「是」；拒绝后游戏照常运行，左上角提示 `Profile update failed!`。
5. **一个构建只改一类东西**（隐藏 / 挂钩、权重、物理参数、碰撞、表情、贴图），新构建放新目录，不覆盖已有构建和已交付的包。

## 硬性规矩（本项目已付过学费）

- **挂钩每一个画了要隐藏部件的着色器**。`TextureOverride` 只在运行了 `CommandListN2General` 的着色器之后匹配 IB。新增隐藏目标时，先在帧分析里查它的 VS / PS，不在已挂钩列表里就加一个 `ShaderOverride`（布料挂件用的是 VS `24f9a3d0d0d9c367`，build4 漏了）。
- **不挂全屏后处理着色器**：它们沿用上一次绑定的 IB，会被 `handling = skip` 跳过，整屏变黑（build1）。只挂角色网格自己的 PS。
- **一个调色板 ≤ 85 根骨**（u8 BLENDINDICES 预乘 3）。超了就再拼一个调色板，在两次 `drawindexed` 之间切 `vs-cb0`；影子 pass 要各自的一份。
- **合并调色板要处理绘制顺序**。关卡和装备界面的绘制顺序不同；在关卡里看头发和脸有没有错位，装备界面看不出来。
- **自定义着色器用 Mod Enabler 自带的 `d3dcompiler_46.dll` 编译检查**（便携包 `c46.py`），fxc 能过的它不一定过。
- **改了物理参数，每条链都单独离线测**，并且用比游戏更狠、带减速的动作（抬腿 70°、0.3 s 停步、120° 转身、侧闪），再用 30 fps 录像在游戏里看。build4 漏测尾巴，用户报「尾巴没有物理」。
- **裙子的权重从身体抄，不从衣服挂件的骨骼借**。借袴飘带的骨骼，站定时飘带下垂、裙子跟着耷拉；只跟骨盆走，腰胯皮肤跟着脊椎转就会穿出来（build2 → build3）。
- **用户问「这是什么东西」时，先在帧分析里定位到具体的绘制再回答**：build4 的「裆前布条」先被猜成腰间的武器，用户拔刀后它还在，才查到是没挂钩的布料着色器。
- **眨眼骨要实测**：按位置猜的眼睑条目 16 / 17 根本不动，用连续抓取的面部调色板才找到真正下落的 24 / 25（build2a → 2b）。
- **3DMigoto 的帧分析默认跳过 Mod 自己的覆盖**：要转储 Mod 的资源，临时打开 `$dump_modded_meshes = 1`，用完改回。
- **frame analysis 文件夹很大**（带 vb / ib / 贴图转储时一次上万个文件）。抓完先打包再拉回，不要在游戏开着时移动正在写的文件夹。
- **启动即崩溃先查文件完整性**：测试机磁盘故障曾把 `d3d11.dll` 的 8 KB 清零。按哈希和已知好的副本对比，再查代码。
- **退出游戏不存档**。改存档的工具都要求游戏已退出，要先在神社存档。
- **社区编辑器的偏移和名字要在实机上验证**：做一次铁匠「外观变更」、存档、前后对比，或者用工具改一个部位后进游戏看画面。
- **不把离线检查、装备界面截图说成实机通过。** 用户在关卡里实际玩过、给了反馈才算 `runtime-confirmed`。
- **modding 工作的审计默认降档**：用户没要求时不派审计，自查后交付，报告里写明。

## 报告口径

结论归入 `invariant` / `build-sensitive` / `case-derived` / `hypothesis` / `rejected` 之一。
历史失败不删；后来的证据只用来收窄旧结论的适用范围，并写明哪条取代了哪条。例如：

- 「3DMigoto 加不了物理链，只能借原版围巾 / 飘带骨」被推翻：Mod 自己用计算着色器模拟弹簧链（build2c）；
- 「裆前两条是腰间的武器」被用户证伪：拔刀后还在，实际是没挂钩的布料着色器画的原版挂件（build5）；
- 「护胫必须是楯无护胫」被推翻：测试存档穿的楯无护胫早已改成隼护胫的外观，Mod 认的是外观。
