# 验证与发布

## 1. 工具级往返闸门（开工前）

| 对象 | 闸门 |
| --- | --- |
| mesh（raw 模式） | 原生/参考 mesh 读入写出，载荷一致（编辑器改写的 4 处版本头字段由构建器回填） |
| mdf2 | 生成物读入 → `GPUBufferOffset` 清零 → 重写，逐字节一致 |
| chain2.15 | 原生文件读入写出逐字节一致 |
| pfb.18 / RSZ | 150+ 个原生 prefab 读入写出逐字节一致 |

## 2. 构建后回读闸门（`VERIFY: PASS` 才允许打包）

验证器独立于构建器，从产物文件回读：

- **骨架**：骨表顺序与层级；原生 rest 路线下原生骨 rest 未变；refskel 路线下 refskel 的位置、旋转、
  缩放与新 rest 一致（缩放与**原生**缩放比较）；世界矩阵与局部矩阵自洽。
- **网格**：三角形数、权重和为 1 且索引有效；mdf 与 mesh 的材质名一一对应；头部 `lodGroupNameHash`
  与原生供体相同（身体与所有屏蔽件）。
- **贴图**：头部格式/标志位；Null 贴图槽正确。
- **chain2**：group 数与构建报告 1:1（链尖、节点数、沿父链走到链根、锚点、链族 setting）；
  碰撞体数量、关节可解析、静止最小间隙 > 0（含胶囊段）、裙高皮肤覆盖率 > 90%；胶囊节点数与报告一致。
- **prefab**：每个引用该 mesh 的 GO 上都有 Chain2（资源路径、`UpdateTiming 4`、碰撞开关、ChainWind、
  重置注册器）；剔除插入实例后与原文件逐字段对齐。

## 3. 确定性与增量

- 构建前清空输出目录（否则旧产物被打包）。
- 两次完整重建逐文件 SHA-256 相同（本项目 36 个文件）。
- 新版本与上一发行包逐文件比对，只有预期的文件变化。例如 v0.3.0 相对 v0.2.0 只有两个 chain2 变了；
  这份比对就是「这一版只改了一个变量」的证据。

## 4. 打包（Fluffy Mod Manager）

- 打包器先跑验证器，失败则拒绝打包；拒绝覆盖已存在的版本目录（必须升版本号或显式 `--force`）。
- 内容：`natives/stm/...`、`modinfo.ini`（name / version / screenshot / description / author）、
  `README.txt`、`showcase.jpg`（离线预览截图）、`manifest.sha256`，另出同名 zip。
- `README.txt` 写：安装（先禁用替换同一角色的其它 mod，并点名冲突 mod）、回滚（禁用即可，不覆盖原文件）、
  每版的更新说明（累积）、内容、范围与已知限制，以及**一行运行时状态**（「vX 已实机加载；本版改动实机未测试」）。
  每次发版同步改这一行，不要让随包文档声称未经实机的改动已通过。
- 修改了原生 prefab 的 mod：游戏更新这些 prefab 后必须重新生成。

## 6. 审查

双轨独立审查（原生 + 外部模型）抓到过实质缺陷：头部固定偏移写坏、验证器覆盖缺口、PFB 插入不平移
`parentId`、背部缎带锚点与大衣脱开。审查包要带冻结文件的哈希；**审查进行中不要改被审文件**，
否则审查者会以快照不符拒绝，整轮作废。
