# 角色替换：配方、骨架路线、几何与材质

## 1. 从参考 mod 反推配方（invariant 方法）

手上有一个实机可用的同类 mod 时，先把它逐字段拆开，而不是从零设计：骨表与原生的差异、
rest 改了哪些关节、refskel 是否跟着改、材质用哪个 mmtr 和哪些标志位、被屏蔽的部件长什么样、
贴图头。每条都有实机先例，后续出问题时只需怀疑自己**偏离配方**的部分。

本作从 Gamer JP 的两个 mod 反推出的配方（`case-derived`，已实机可用）：

| 项 | JP Karin → Hugh | JP Minahoshi → Diana |
| --- | --- | --- |
| 身体骨表 | 235 骨（原生 229 + 发骨） | 185 骨（= 原生） |
| 骨 rest | **改成 Karin 比例**（T-pose 手臂、手指/腿/颈/头移位）；Hip、Spine、Shoulder 保持原生 | **原生 rest**（只有 z −1.66 cm 的工具残差） |
| refskel | 随 rest 一起改（过场 `ch0091.refskel.8` 直接拷 ch0000 的） | 不改 |
| 屏蔽件 | 12 个三角形塌缩到一点的 stub mesh，材质名用原生名，不带 mdf | 同 |
| 材质 | 全部 `Env_Emissive`：BaseColor 黑、Metallic 1、Roughness 1、Emissive = 漫反射图 ×35 → 无光照卡通观感；双面 + AlphaTest 标志 | 同 |
| 贴图 | BC7 sRGB，GDeflate | 同 |
| 整体缩放 | VRM × 1.5531（= 肩高对齐，见 §2） | VRM × 1.1552 |

参考 mod 的网格与源 VRM 的对应：相似变换（缩放 + 绕 Y 180° + 平移，残差 0），UV 100% 对应
（Hugh 245,452 顶点）。所以在参考 mod 上加东西（例如加物理骨与权重）时，可以把 VRM 的
spring、权重按顶点一一搬过来。

## 2. 两条骨架路线

### refskel 路线（Hugh）

- **缩放按肩高（上臂关节高度）对齐，不按臀高。** 臀高对齐（×1.29）时 Karin 的躯干只有 Hugh 的
  57%，原生 `Spine_2` 落在她的脖子上；参考 mod 的 ×1.553 正是肩对肩（另一个角色 Diana 骑在 Hugh
  背上的位置也因此成立）。本项目 ×1.459，腿比 Hugh 长（与参考 mod 相同）。
- 映射骨的 rest 移到源模型关节位置；`Hip`、`Spine_0-2`、`L/R_Shoulder` 保持原生（与参考 mod 相同）。
  非映射原生骨随最近的映射祖先刚性移动。
- **关节坐标系 = 原生坐标系 × 分层最小对准旋转**：子骨先随父骨的旋转一起转，再做把骨方向对准
  源模型的最小摆动。直接对每根骨独立求最小旋转会让前臂出现扭转；分层后前臂局部旋转 ≈ 单位。
- `ch0000.refskel.8` 按新 rest 重写局部 TRS（本 build 改动 48 个关节，与参考 mod 集合相同）。
  过场的 `ch0091.refskel.8` 用它自己的原生 refskel 加上同样的增量改写（参考 mod 是直接拷贝）。
  四元数从矩阵提取用 Shepperd 法（数值稳定）。
- 验证器检查 refskel 的位置、旋转、缩放全部与新 rest 一致；缩放项要和**原生**缩放比，不是和 1 比。

### 原生 rest 路线（Diana）

- 骨表与 rest 完全原生，几何按目标骨逐骨做 `T(原生关节) · R(对准) · S · T(-源关节)` 的 LBS 重定向；
  非人形源骨用最近人形祖先的矩阵。整体缩放按臀高对齐（Q 版 kipfel：1.214）。
- 鞋底比原生脚厚时，把脚部几何整体抬高（本例 4.48 cm），再把小腿绕膝压缩（×0.807），接缝保持连续
  （鬼武者同一做法）。
- 非均匀缩放后法线用**逆转置**变换。

## 3. 读源模型（invariant）

- **glTF/VRM 的蒙皮网格不应用节点变换**，世界坐标 = Σ w · (关节世界矩阵 × inverseBindMatrix) · 顶点。
  kipfel 的 VRM 节点上有 0.8929 的缩放，按节点变换算会整体错位。
- 骨集合 = 所有 skin 的 joints，再向上补齐祖先（补进来的是场景节点，改名避免与真骨冲突）。
- VRChat 导出可能出现**重名节点**：保留第一个，其余加后缀。
- 形态键（morph target）的 accessor 常是**稀疏**的（没有 `bufferView`，只有 `sparse`），读取器要支持。
- VRM0 与 VRM1 的人形映射、SpringBone 结构不同，分别解析；按规范化名字匹配到 FBX 转出的骨。
- FBX 源：Blender 后台（`--background --factory-startup`）转成 npz（游戏坐标，按「顶点 × UV × 角法线」拆点），
  不要用 Blender 退出码判断成败，检查输出文件。
- 「优化版」头像常删掉 spring 链尖骨（`*_end` / `VRCLeafTipBone_*`）：链尖用该骨自身权重顶点估计
  （单节链取最远的权重顶点）。

## 4. 用源模型自带的形态键收起被遮住的素体（case-derived 值，invariant 做法）

症状：膝盖附近的素体从袜子里露出来。很多头像作者为换装准备了「把某段肢体向内收」的形态键
（本例 `kisekae_*`，每个收 25–60 mm；kipfel 是 `Foot_OFF` / `Toe_OFF`）。在蒙皮前按权重 1 烘焙即可，
不用自己改网格。

- **按绑定姿态高度加遮罩。** `kisekae_UppeLeg 2` 如果整片烘焙，袜口上方那一圈（30 个顶点）也会被收进
  约 5 cm，形成一道折痕；只烘焙 y 低于袜口的顶点（本例 y < 0.52）。
- 指定的形态键在源里找不到时直接报错，不要静默跳过。

## 5. 材质与屏蔽件

- 默认全部 `Env_Emissive`（照参考 mod，无光照卡通）；只有真镂空的贴花（本例 Karin_Alpha / Body_alpha）
  用 `Env_AlphaTest`，镂空取 ATOS 的 R 通道。
- 原生 `Env_Emissive` 条目带着环境 NRRC 等贴图；除 Base / Emissive 外的贴图槽全部换成参考 mod 的 Null 贴图。
- AlphaTest 贴花是受光照的，而其余材质不受光照，理论上可能有亮度差（本项目实机未被报告）。
- 屏蔽件：12 三角形塌缩到一点，材质名用原生名，不带 mdf；头部拷原生供体的 `lodGroupNameHash`。
- 脸绑在 `Head` 上：没有表情和眼动（与参考 mod 相同）。

## 6. 离线预览

用文件**自身**的权重与逆绑定矩阵做贴图预览（静止 + 测试姿态：手臂放下、膝盖弯曲）。扭转、塌陷、
权重漏绑能在进游戏前看到；这是 `offline-accepted` 证据，不是实机证据。
