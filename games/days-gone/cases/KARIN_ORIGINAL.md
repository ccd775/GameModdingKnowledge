# 案例：Karin_Original → 迪肯（2026-10-15 → 10-16）

游戏：Steam 1259420，`days_gone_classic` 分支 build `10034136`。源模型：Karin_Original 的 VRM 1.0（10 个网格、6 个材质、207 个关节、
39 条 spring 链、脸上 237 个形状键），与本库其它 Karin 项目同源；不随本库发布。用户已有一个参考 mod（Karin 的夹克装，全部几何放在
头部网格、4096 图集、无物理、无表情），装法是 `~mods` + 改名 `startuppackages.pak`。

**用户需求**：在经典版分支上用 Karin_Original 替换迪肯；先做物理，再做表情；之后按实机反馈修。
授权：研究、提取、离线构建、在测试机上装 UE 4.11.2、部署到 `~mods`、启动游戏测试。规矩：绝不存档。

## 1. 工具链

- DgExport（CUE4Parse 1.2.2）读游戏包；自写 pak v3 读写、uasset 读写（`upkg.py`）。
- 测试机装 UE 4.11.2，建 `BendGame` 内容工程（占位骨架 + Karin 网格 + 贴图），只用来导入 FBX 和 cook。
- Blender 4.2 + UEFormat 插件做全部几何、权重和面部工作。

## 3. 关键判断

- **全部放进头部网格**（跟参考 mod 一样）而不是逐部件替换：头部网格是所有 look 的主姿势组件、跑动画蓝图，换装、闪回都绕不开它。
- **PhysX 路线放弃得晚了**：t12–t19 八个版本都在调约束参数；更早做「锁死一节、看它会不会动」的二值探针，可以早几轮发现约束根本不生效。
  同样的教训在 t28 用上了：眨眼没生效时直接上常数位移探针，一轮就确认 BoneDrivenController 不执行。
- **面部改动先模拟再进游戏**：Blender 里按游戏的叠加规则模拟面部动画（眨眼、口型、情绪），把「没效果」拆成「蒙皮问题」还是「驱动问题」。
- **一版一类改动**：物理、眨眼、口型、物理参数分别进实机，用户的反馈才能对上原因。
