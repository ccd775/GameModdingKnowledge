# 骨骼与几何

本作主角替换在几何侧的核心矛盾：源角色按自身比例建模，而游戏的动画、IK 与 helper
joint 按原角色的骨骼比例编写。本文记录最终被实机接受的折中方案，以及四个被实机
**拒绝**的前代方案 —— 后者同样重要。

## 1. 被拒绝的四条路（保留，不要重走）

| 版本 | 做法 | 实机结果 |
| --- | --- | --- |
| 全身逐骨 directional transfer | 每根骨都做源→目标方向重定向 | 拒绝 |
| 分段平移合同 | `M_native @ inverse(M_baseline)`，baseline 已用 donor 轴 | 外袖压成长条、前臂层顶出、袖口错层 |
| source-proportion 腿部局部矩阵 | 腿保持源比例 | 脚相对小腿前移、脚后跟断层、前脚掌外撇 |
| 往无关槽位追加身体骨 | 把身体几何绕到头发槽 | 材质正常但身体 T-pose，占位网格裂成黑片 |

共同教训：**离线闸门全绿不等于实机通过。** 这四版都是离线全部通过后被实机拒绝的。

## 2. hybrid rest 闭包（现行，实机确认）

思路：与原生动画/IK 冲突最严重的区域**整体交还给原生 rest**，其余保持源比例。

- 手臂闭包 **132 骨**（双臂/手指/HJ/twist/武器辅助）恢复为原生全局 rest。
- 腿部闭包 **40 骨**（左右 `Thigh` 的 30 个后代 + 10 个同 `Hip` 父级的 HJ sibling）
  同样恢复原生 rest。
- 两者**不相交**，并集 172 骨；其余 145 骨保持 source-proportion baseline。
- 闭包内必须与 reference / native / FBXSKEL 匹配 `< 1e-5`，闭包外与 baseline 匹配
  `< 1e-5` —— 这两道闸门是这套方案能被审计的原因。

代价（已接受）：手臂和腿的局部比例是原角色的，不是源角色的。这是为兼容 IK 的必要
妥协。

## 3. 方向几何重定向（46 骨）

对**实际加权**的 38 个手臂/手指骨 + 8 个腿骨（`L/R Thigh, Shin, Foot, Toe`）做局部
aim 方向修复。集合外影响**严格 identity**，不新增 helper / twist / Knee / Instep / HJ /
链骨的可见权重。

```text
absolute = T(native_target_head) @ R(source_aim -> native_aim)
           @ S(source_global_scale) @ T(-source_head)
relative = absolute @ inverse(source_global)
```

一个有用的恒等式：因为 `source_global` 是**均匀**缩放，`relative` 矩阵的 3×3 部分
**恰好就是旋转 `R`**。本项目正是靠这一点，得以在生产构建器之外做后乘修正而不必改
构建器。

## 4. 末节指骨反曲：aim 表缺了终端项

**症状**：手指最后一个关节反向弯折；渲染里指尖像脱开的胶囊从握拳中戳出来。

**根因**：aim 子骨映射表只写了 `{side}_{finger}1 → 2` 和 `2 → 3`，**没有 `3 → …`**。
于是 10 根末节指骨拿到 identity 旋转，而它们的父骨 `*F2` 旋转了 61°–75°。

**修法**（不改冻结的生产构建器，在 runner 里注入）：让每根末节指骨**继承父骨的旋转**，
绕自身 head 施加：

```text
parent_3x3 = matrices[parent].to_3x3()
# 先断言它是纯旋转：parent_3x3 @ parent_3x3.T 与单位阵的最大残差 <= 1e-6
rotation   = parent_3x3.to_quaternion().to_matrix().to_4x4()
head       = world @ bones[distal].head_local
correction = T(head) @ rotation @ T(-head)
matrices[distal] = correction @ matrices[distal]
```

`invariant` 教训：**「链末端没有子骨」这类结构缺口会静默退化成 identity**，而
identity 在数值闸门里完全合法。为终端项显式声明策略（继承 / 报错），不要让它落进
`else` 分支。

## 5. 鞋底埋进地里：几何修正而非骨骼位移

**症状**：常态站立时整只鞋埋进地面。

**先测量，再相信眼睛。** 第一次看截图时我判断为「悬空」，实测是「下陷 62.5 mm」。
测量口径是 rest 姿态下**脚部加权顶点**的最低点：

| | 脚跟 | 前脚掌 | 低于地面的顶点数 |
| --- | ---: | ---: | ---: |
| 替换角色（修正前） | `-68.75 mm` | `-48.26 mm` | 每只脚 1408 |
| 原角色（草鞋） | `-5.35 mm` | `-6.22 mm` | 0 |

**根因**：腿部闭包把踝关节**钉在原生位置**（`88.08 mm`），但源角色的运动鞋从踝到
鞋底有 `156.83 mm`，原角色的草鞋只有 `93.43 mm`。骨骼不能动，差额就只能由几何吸收。

**修法**：绕原生踝关节做几何修正，并把抬升量沿小腿摊开。

```text
ANKLE_Z = 0.08808   # 原生 Foot head 的 Z
KNEE_Z  = 0.47428   # 原生 Shin head 的 Z
VERTICAL_SCALE = 0.8        # 竖向压缩（用户在「动画正确」与「保形」之间选的折中）
PITCH_DEGREES  = 5.9639
LIFT           = 0.025935   # 25.9 mm

foot = T(0,0,ANKLE_Z + LIFT) @ Diag(1,1,VERTICAL_SCALE) @ Rot_X(PITCH) @ T(0,0,-ANKLE_Z)

shin_scale = (ANKLE_Z + LIFT - KNEE_Z) / (ANKLE_Z - KNEE_Z)   # = 0.93285
shin = T(0,0,KNEE_Z) @ Diag(1,1,shin_scale) @ T(0,0,-KNEE_Z)
```

关键性质：小腿的 Z 缩放在**踝处恰好等于脚的抬升量、在膝处恰好为 0**，因此
**两道接缝都是构造上连续的**，不需要事后缝合；25.9 mm 摊在 386 mm 小腿上只有 7.8%。

结果：脚跟 `-7.642 mm`、前脚掌 `-6.830 mm`、倾斜 `0.811 mm`（原角色自身的倾斜是
`0.87 mm`），左右完全对称。

接缝闸门要留 `1e-6` 量级的容差：一次 `RuntimeError: ankle seam would tear ...
7.45e-09 m` 其实是 `0.4 m` 尺度上的 float32 舍入，不是撕裂。

## 6. 闸门重定基要靠测量，不能靠放宽

这类几何修正会碰到一堆冻结的数值闸门。正确处理是**开一次探针跑**，把所有相关闸门的
实测值打出来，再决定改哪一条：

本项目的探针结果是「几乎全部改善」—— 鞋最大边长比 `1.1266 → 1.0957`、自交对数恰好
不变、镜像 p95 `1.29e-4 → 1.09e-4`、跨物体 BVH 不变、膝部超限计数普遍下降。**只有
一项**（一个早已被记录为异常的右侧踝部计数）从 7 升到 13，而它的最大边**长度**同时
从 `0.0667` 降到 `0.0628`、超 `2.0` 的计数从 4 降到 3。于是只重定基那一项。

同类做法见 [chain2 文档](CHAIN2_PHYSICS.md)：当一根新增骨越过全局公差而它的**镜像
孪生**没有越过时，那是 float32 往返舍入噪声，不是建模问题 —— 正确处理是**把新增骨从
全局最大值里摘出来单独给一个仍然强制检查的上限**，而不是整体放宽。

## 7. 生产构建器冻结 + 版本化 runner

一旦某个构建器产出过被实机接受的产物，就**字节冻结**它，后续能力扩展全部走 runner：
加载时对构建器源码做**定点文本替换**后 `exec`，磁盘上的文件不动；注入集合为空时行为
与原版完全一致。

本项目在这条规矩上犯过错：直接改了冻结的构建器（11 处），发现后全部还原，并靠**重跑
上一版构建、比对三个 Mesh 的 SHA-256 逐位相同**来证明还原是行为等价的 —— 还原之后
必须给出这种证明，而不是声称「我改回去了」。

用 runner 撞上冻结闸门时的三种正确处理（都不放松闸门）：

1. 闸门检查的子树被新骨污染 → 检查期间把新链锚**临时脱离父级**，检查后立刻还原，
   原函数看到的仍是原生结构。
2. 闸门按某个 `action` 标签折算合成骨，而新骨用了新标签 → 把标签改回既有值，另加
   一个**仅用于报告**的布尔标志来区分。
3. 数值公差越界 → 见上一节，分集合给上限，不整体放宽。
