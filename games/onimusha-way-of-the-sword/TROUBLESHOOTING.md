# 排障手册

## 症状 → 定位表

| 实机症状 | 最可能的成因 | 先查什么 |
| --- | --- | --- |
| 身体/服装近黑，头发和脸正常 | PFB 的 `*_mmi/mpi.user.3` 按 Murmur3 材质名命中并覆盖写参 | 对全部消费者做名字与哈希扫描；换一个 0 命中的材质名 |
| 材质正常但身体 T-pose | 加权骨在该部件的运行时骨架里**按名字不存在** | 逐骨名核对目标槽位骨架，不要看骨序 |
| 零位置占位网格在动画后裂成黑色破片 | 异构权重的退化占位几何 | 不要留占位网格 |
| 双臂在武器姿态下分段折叠 | 源 T-pose 上肢 rest 与原生 FBXSKEL / 武器 IK 差 `0.37–0.51 m` | 改 hybrid 原生 rest 闭包，不要逐骨重定向 |
| 外袖压成长条、袖口错层 | 几何 delta 退化成零旋转的分段平移（baseline 已用 donor 轴） | 检查相对矩阵的 3×3 部分是不是恒等 |
| 脚相对小腿前移、前脚掌外撇 | 腿部保持源比例，与原生动画/IK 冲突 | 腿部改原生 rest 闭包 |
| 整只鞋埋进地里 | 踝被钉在原生位置，而鞋的踝-底距离比原鞋大 | 量 rest 姿态下脚部加权顶点最低点，不要看截图 |
| 末节指骨反曲、指尖像脱开的胶囊 | aim 子骨映射表缺终端项 → 末节拿到 identity | 检查映射表是否覆盖每一节 |
| 次级部件完全不动（被读作「很硬」） | 力平衡偏向弹簧几百倍：重力被削、弹簧被抬 | 算 `gravity.y × gravityCoef` 对 `springForce`，与原生对照 |
| 次级部件卷曲 + 僵硬 | `angleLimitDir` 沿用供体，静止目标落在限制锥外 | 逐节点算静止指向误差；`75°–152°` 就是这个病 |
| 尾巴/链条朝天，且每节都像拿了上一节的姿态 | `angleLimitDir` 参考系用成了骨骼自身系 | 改父骨系：`d_bone @ R_bone_local` |
| 站立不动时持续轻微抽动 | 环境风耦合（`envWindEffectCoef` 耦合的是**场景**风） | 与同尺度的原生链对照风字段；`windSettingCount = 0` 不代表没风 |
| 「整条一起动、没有段落感」 | 阻尼梯度太平（≈ 均匀阻尼 ≈ 刚性杆）；或节点数太少 | 比 `damping → minDamping` 的倍数与原生；再看节点数 |
| 归位太慢 | `springMaxVelocity` 被从 `0` 改成了非零（速度钳位） | 查该链族的原生值 |
| 一侧「硬、不跟随」 | 根部 `collisionRadius` 太小，被头部胶囊夹住 | 把**整条链**的逐节点半径排开看，别只看 node 0 |
| 左右表现不同，但数据完全对称 | **角色动画本身不对称**，不是数据缺陷 | 停止查数据；改两侧共有的那一半反馈 |
| 装 PAK 后 `file looks corrupted` 启动中止 | 本 build 拒绝未加密 Mod PAK，完整性绕过已失效 | 改走散装文件 |
| 几何/材质正常但贴图不生效 | `LooseTextureLoader` 报 `Could not find DirectStorage file open function!` | 核对已加载散装文件清单 |

## 已被证伪的捷径

- **「借原生链骨但不改 chain2」**：链骨被移到新角色位置后，原生 chain2 的
  `basePos` / 角度限制 / 重力 / 恢复设置仍是原角色数据，不会回到源姿态。
- **「靠调 `gravity` / `springForce` / `damping` 修卷曲」**：卷曲是**约束**问题。
  在求解器近乎静止时仍然存在的形变，不可能是力的参数问题。
- **「为长链补 Chest/Spine/UpperArm 碰撞体」**：原生身体链的 `modelCollisionCount`
  是 **0**，约束靠角度限制 + 回拉项。穿模的正确手段不是补碰撞体。
- **「用脚骨角度当鞋底贴地的代理」**：脚骨方向、鞋底平面、地面接触是三个不同命题。
- **「插件读不了就是格式不支持」**：先查第二个实现。本作 v17 与 v15 的唯一差异是文件头。
- **「退出码 0 = 构建成功」**：Blender 无头模式抛异常也返回 0。

## 两个反复出现的元错误

1. **用无分辨力的样本确认假设。** 两次连续误判同源：一次拿「仿真近乎关闭时仍存在的
   形变」去调力的参数；一次拿「local basis 恒等的链条」去确认参考系 —— 对恒等 basis
   的骨骼，两种竞争解释在数学上就是同一个东西。
   立规矩前先问：**这批样本能否证伪竞争假设？** 不能就换样本。

2. **跨链族/跨部件搬运档位。** 本项目三次返工全由此而来。默认应当是**从原生出发，
   只改已证明必须改的**；要搬运之前，先把目标族的原生取值逐字段打出来。
   全程唯一没出过问题的那条链，恰恰是「只关了风、其余全保留原生」的那条 —— 它一直是
   现成的对照组，只是当时没意识到。

## 环境相关

- 项目产物若位于云同步目录，部分文件会是云占位符，**首次读取可能失败**
  （Windows 上表现为 `OSError 22`）。重试即可，不要当成文件损坏；但构建前应确认源
  文件已水合。
