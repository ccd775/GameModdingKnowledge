## 关键转折

### 转折一：材质是被 PFB 按名字哈希覆盖的

身体近黑连续拒了四版。根因不在贴图、不在 MDF，而在 Body PFB 加载的
`*_mmi/mpi.user.3` —— 它内含原角色身体/服装的贴图路径，并精确命中四个 `00` 槽材质名
的 Murmur3 哈希。头发槽的 PFB 没有 slot-specific MMI，所以头发一直是正常的。

绕过方式是让所有非脸表面共用一个**原生消费者从不命中**的材质名。正式版复验 0 命中，
两套服装均实机确认。

### 转折二：骨绑定按名字，不按索引

早期把「三个可见槽必须使用各自原生骨序」当硬约束。正式版新增的第二套服装
`ch001_01_00` 是 269 骨、骨序完全不同 —— 把 317 骨的身体 Mesh **原样**部署上去，
实机完全正常。真实约束只是**加权骨按名字存在且 rest 一致**。

这条直接把「为新服装做替换」的成本从「重建」降到「复制」。

### 转折三：chain2 v17 从 BLOCKED 翻成 PASS

判 `BLOCKED` 的依据是 Blender 插件不支持且上游已归档。同日推翻：另一个实现早就写了
v17 的 header 分支，而 v17 与 v15 的唯一差异就是文件头。闸门（逐 section 重序列化后
与原字节比对）4 个原生文件全部逐字节一致。

完整格式与调参方法见 [chain2 次级物理](../CHAIN2_PHYSICS.md)。

### 转折四：`angleLimitDir` 的参考系

判错过一次（骨骼自身系 → 实为父骨系），实机症状是「每个四元数沿链上移一节、根节点
指向正上方」。修正后 10 条链全部 `0.00000°`。方法论教训（无分辨力的样本）见
[排障手册](../TROUBLESHOOTING.md)。

### 转折五：物理调参三次返工，全部同源

「跨链族搬运档位」。最贵的一次是把长链档位整包套到头发链上，净效果 `214×` 偏向弹簧，
链条**完全停止仿真**，而用户反馈的「软绵绵」与「很硬」其实是同一件事的两个阶段。

## 最终形态（v1.11.0）

- 几何：hybrid rest 闭包（132 骨手臂 + 40 骨腿部，并集 172，其余 145 骨保持源比例）
  + 46 骨局部方向修复 + 末节指骨继承 + 绕原生踝的鞋底修正。
- 物理：29 个被驱动的 chain2 group，覆盖尾巴、双马尾、侧发、耳、呆毛、缎带、大衣、
  耳机线、腰带/绑带类。
- 交付：散装文件 ZIP（**唯一可用**），另保留 PAK 与 Fluffy ZIP 供将来。
- 安装：解压使 `natives/` 直接落在游戏根目录；卸载 = 删除该目录，不覆盖官方文件。

## 已知未解决 / 未验证

- **腿部绑带**（6 条 22 骨）：腿是全身唯一的 hybrid 区域，按原角色比例构建。绑带静止
  姿态来自源曲线，落点与原生腿对不上，触发真实的几何冲突（不是可绕过的闸门）。需要
  先把绑带静止姿态变换到原生腿坐标系。runner 里留了开关。
- **`Back_Ribbon` / `Tail_Ribbon` / `Pocket_String`**（6 条）：源父级映射到**已被其他
  chain 模拟的骨**，而 Capcom 全作 22 个原生 group 里没有嵌套链的先例；改锚到刚性骨
  又会让它们脱离所依附的部件。两条路都要决策。
- **拉链**：用户明确要求不做。
- **大衣与耳机线的穿模**：从未在游戏内检查过。
- **残留供体不对称**：耳与侧发各有一个根节点的 `collisionRadius` 是左 `0.005` /
  右 `0.010`。已定位，**刻意未随手修** —— 用户当时正在给手感反馈，混进一个没被投诉过
  的部件会让下一轮反馈无法归因。
- **脸**：稳定绑 `Head`，没有表情与独立眼动；这是已接受的边界。
- **四分区图集**把每个表面组的水平分辨率从 4096 降到 1024。
- 非脸表面共用一个 lookup，服装/皮肤法线为中性 fallback，湿润/血渍/近距离光照响应可能
  与原生不同。

## 工作方式上的两条项目约定

- **生产构建器字节冻结**，能力扩展走版本化 runner（加载时对源码定点文本替换后 `exec`）。
  曾直接改过冻结构建器，发现后全部还原，并通过**重跑上一版并比对产物 SHA-256 逐位
  相同**来证明还原是行为等价的。
- **每个发行版有自己的打包器**，旧打包器保持冻结，使旧版本永远可复现。
