# 案例：Karin PicodraTech / Karin Original → 玩家角色（2026-09-23 → 10-11）

游戏 build `24831693`（TU3.2）→ `25290080`（2026-10 更新 + DLC）。源模型：Karin_PicodraTech（Blend / FBX / VRM，10 网格、
47,052 顶点、237 骨、4096 图集，与鬼武者项目同源）、Karin_Original（FBX）。源模型不随本库发布；用户允许破坏性处理源模型副本。

**用户需求**：用 Karin 做 DD2 玩家角色替换；**无论穿什么装备都完整显示 Karin**。

## 1. 工具链与方案（09-23）

- 新整包格式让社区工具全部失效 → 以 REE-Lib 写 DD2Tool（TOC、路径表改写、提取、mesh 转换），Win10 上 .NET 10 先绕 CET。
- 社区调研 + 只读探针 dump 玩家层级后选定「运行时只改玩家」，否决替换共用身体网格。

| 版本 | 改动 | 结果 |
| --- | --- | --- |
| v1_test（09-26） | 棋盘格材质；DD2 骨名 + Karin 比例骨架 + `K_*` 次级骨；运行时 `setMesh` | 几何、蒙皮、双马尾 / 猫耳 / 外套 / 尾巴随动画运动 |

## 3. Original 版本轨迹

| 版本 | 改动 | 反馈 |
| --- | --- | --- |
| o2 → o4（09-28） | 同一代码库的第二个 profile（构建脚本、贴图、MDF、chain、Lua 全部参数化，PicodraTech 构建逐字节不变）。按反馈依次：裙摆翘太高 → 裙组只碰大腿胶囊；双马尾 / 尾巴不动、尾巴水平或下垂 → 发现 `K_*` 骨没有逐帧回位，加 `CHAIN_REST_POSE`；双马尾和尾巴零重力、加大摆幅 | 「裙子差不多刚好了」；最后一次加大摆幅（o4）未单独确认 |
| v1.0.0（10-10） | 表情（左右眨眼分开）；撤回给 `Cheek_*` 加的链（它们带脸部皮肤） | 测试机实机验证 |
| f4（10-11，本机） | 裙片对称 LimitCone 0.26 | 「好了很多，只有一点点裙片最下端会露出来了」 |
| **v1.0.1 = f5** | 外倾 LimitCone 0.45 / 外倾 0.25 rad；只改 chain，脚本只改版本号 | 「这次好了」 |

v1.0.1 的诊断过程（[chain 物理](../CHAIN_PHYSICS.md) §5）：用户截图 → 逐帧录制裙节点与大腿骨 → 定量出「前片向内翻 18 cm、40–60% 的帧在身体里」→
在线对照阻尼 / 运动力 / 弹簧 / 角度倍率，只有角度有效 → f4 后再录，定位到「大腿从两片之间穿出」→ 改为非对称限制。
审查：modding 降档 + 单一配置值改动 → 主控自查，未派审查席。

## 4. 事故与教训

- 盲按键的重读档脚本误触「中途保存并继续游戏」，覆盖了一次中途存档（有备份）。此后游戏菜单自动化每次确认前截图核对，
  所有测试只读档。
- 一次在线调参基线因 Lua 整数传给 float setter 作废。
- 两次 REFramework 异常处理递归崩溃（栈在 dinput8）未定位，未见与 Mod 相关。
