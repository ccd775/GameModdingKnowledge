# 表情：形态键 → 平移骨，从原生面部骨驱动

agent 在测试机实机自测：两个模型各通道强制满幅截图 + 实时录制，各 3 轮压力测试；用户未单独确认，幅度常数是估计值。

## 1. 原生面部仍在跑

- 玩家 `head` 子 GO（如 `head_214_f`）自带 `via.motion.Motion`、206 根骨的面部骨架（`FacialJnt_Face` 下 `L/R_Eye`、`C_Jaw`、
  上下眼睑 `*_UpperLid_01..05` / `*_LowerLid_01..04`、唇、颊……）、LipSync、`app.TowerFacial`。
- **头部网格被隐藏后面部动画照常播放**——这是驱动源。
- 面部骨的 base 旋转都是单位（`FacialJnt_Face` 系：x = 角色左、y = 上、z = 前；它相对 `Head_0` 为 Rz(−90°)）。
- 闲置实测：每 150 帧眨眼一次，上眼睑 `UpperLid_03` 下移约 11.4 mm（睁眼时上下睑间距 14.1 mm）；眼球扫视约 5°；
  打招呼时下颌只转 1.65°。

## 2. 编码（构建时）

源模型脸部有形态键 `blink` / `blink_L/R`、`VRC.v_aa`（张嘴）、`LookUp/Down/Left/Right`。游戏不播放自定义网格的形态键，
所以把它们变成骨：

- 形态键增量在烘焙前存成顶点属性（随删面、摆姿势、按材质拆分一起走），再按统一缩放乘 `s`。
- 每个表情通道变成 `Head_0` 下的平移骨 `KF_<通道>_<k>`，各带一根不加权子骨 `_End`（偏移 = 满幅位移 `D·t_k`）。
  平移骨移动 `a × (End 偏移)` 时，权重 `w_k` 的顶点移动 `a·Σ w_k·D·t_k`；线性蒙皮下这正好等于「形态键 × a」。
  - **4 根**（正四面体方向，`t_0` = 主方向）：任意增量都能用非负系数精确表示（`Σ t_i t_iᵀ = 4/3·I`，系数整体平移到最小为 0）。
  - **2 根**（±主方向）：丢掉垂直分量（PicodraTech 张嘴最多丢 1.6 mm）。
  - **瞳孔**：Look 键对绝大多数顶点是刚性平移 → 一根 `KF_Iris`（权重 0.5）+ 四个方向子骨（偏移 = 满幅 / 0.5）。
- 每个顶点的权重预算：瞳孔占 0.5，其余由涉及该顶点的通道平分；`D` 取最大需求；8 位权重量化误差约 0.1 mm。
- 骨数：加权骨上限 256。PicodraTech 原有 249 → 把最大权重 < 0.12 的两根弱骨并回父骨，左右眨眼合并为一个 4 根通道，
  张嘴 2 根，瞳孔 1 根 = 254；Original 164 → 左右眨眼各 4 + 张嘴 4 + 瞳孔 1 = 177。构建时断言 ≤ 256。
- 运行时脚本不含模型专属数据：它从 `_End` / 方向子骨的偏移读出满幅。

## 3. 驱动（运行时，每帧 UpdateScene 前）

- 眨眼 =（上睑下移 + 下睑上移）/（0.75 × 睁眼间距），减 0.15 死区（原生眼睑静止时会轻微漂移）。
- 张嘴 = 下颌张角 / 12°。
- 视线 = 两眼 yaw / pitch 平均 / 20°（分别到 Left/Right、Up/Down 子骨偏移）。
- `KF_*` 骨不受动画系统驱动，写入后保持。
- 失效与重收集：身体重建、非 Karin、读档、对象消失、KF 或原头部骨地址变化 → 丢弃，3 s 后重收集。原生头部失效时要把表情归零
  （审查发现过「表情卡住」）。
- 开销：7 次原生读取 + 7 次写入，约 0.016 ms/帧。

## 4. 验证

- 拍照模式（暂停菜单 Photo，镜头以角色为中心正对脸，`P` 隐藏说明）下用开发脚本强制各通道满幅截图：闭眼、单眼眨、「あ」口、瞳孔四向。
- 实时驱动用逐帧录制脚本（每帧记眨眼 / 张嘴系数与瞳孔偏移）对照原生动画。
- 脚本改相机 transform 只在弹窗暂停的那一帧生效，REFramework Camera 模块的 FOV 也不行；看脸用拍照模式。
