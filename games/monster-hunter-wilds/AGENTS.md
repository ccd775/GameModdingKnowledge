# Agent 入口（Monster Hunter Wilds）

先读 [README](README.md)，再按当前问题进入对应文档。项目的当前状态在独立工程的
SOP，不在这里；本目录只提供方法、合同和已被证伪的假设。

## 接手一个新任务前

1. 核对 Steam appmanifest 的 `buildid`、游戏 exe 版本与日期，**以及 REFramework 的
   commit / nightly 号**（日志第 2–4 行）。本作每次 exe 更新都可能让旧 REFramework 的
   加载能力失效，症状与「mod 内容有错」完全一样。
2. 按官方 PAK 索引反查当前资源后缀（mesh / mdf2 / chain2 / clsp / tex / fbxskel），
   不要信任第三方文件名列表里的版本号。
3. 确认这一版改的是**加载 / 几何 / 材质 / 物理 / 挂点**中的哪一项；同一版混改会让
   实机反馈无法归因。

## 硬性规矩（本项目已付过学费）

- **黑屏先查环境，再查内容。** 先确认「只装 BoneSystem 能进标题」，再用**原版字节原样
  放回原版路径**的负对照测试加载器本身；负对照也黑，就是 REFramework / 游戏 build
  的问题，不要再改 mod 文件。
- **二分时注意引用链。** MDF 引用贴图：只放 MDF 不等于隔离了 MDF。需要一个「MDF 只引用
  原版贴图」的对照组，才能区分「MDF 字段」与「MDF 引用的贴图」。
- **隐藏部位不能做成空骨架。** 占位件必须保留该部位的引擎挂点骨（武器挂点、投射器骨
  等），否则武器消失、离开大集会所即崩溃。先抽样多套原版装备，求「每套都有」的骨名。
- **不要把 Fluffy 记录和游戏目录搞分叉。** 手工部署测试后，按 Fluffy `installed.ini`
  逐文件哈希还原，或明确告诉用户当前目录与 Fluffy 记录不一致。
- **不要自动读档。** 自测停在标题画面；进存档、野外、战斗由用户验收。
- 临时抽取原生文件时总是显式指定报告路径，避免覆盖项目的输入锁报告。

## 报告口径

结论归到 `invariant` / `build-sensitive` / `case-derived` / `hypothesis` / `rejected`
之一；运行时证据用本库五级词汇。历史失败不删除，后来的证据只**收窄**旧结论的适用
范围，并写明 supersedes 关系。
