# 验证与发布

## 1. 离线闸门（按依赖顺序）

每一道都拦过真实错误或被审查要求加上：

1. **输入锁**：源 blend、源贴图、原生提取件、参考 mod、工具副本全部按 SHA-256 锁定；
   每步脚本复核。
2. **工具往返**：RE Mesh Editor / RE Chain Editor 对原版与参考文件往返，骨、父级、rest
   完全一致。
3. **Mesh 闸门**（失败即非零退出，打包前再断言一次）：文件头 magic/版本与原版一致；
   骨集合/父级/世界矩阵与 rig 一致；共享骨绑定 == fbxskel rest；各材质三角形数 == 源；
   权重归一、影响数上限；9 根表情骨都有权重；**挂点骨存在**。
4. **MDF 合同**：MMTR、属性名列表、贴图槽列表、GPBF 与当前原版模板一致；除自己拥有
   的槽与参数外，与已实机配方逐项相同（写后回读断言）。
5. **chain2 / clsp**：解析、终端骨存在、设置/风 ID 可解析；静止最大穿透 ≤ 0。
6. **打包复验**：ZIP 解到临时目录重新解析每个资源；每个 MDF 贴图引用在包内或官方
   PAK 索引中可解析；部位 Mesh 的材质与同目录 MDF 同名；**不含 6 号部位**；挂点骨在
   解包后的 Mesh 里仍存在。
7. **确定性**：ZIP 固定 `date_time` 与条目顺序，两次打包 SHA 相同；新 run 名称不得复用
   旧目录（构建器拒绝覆盖）。

离线闸门全绿只代表 `offline-accepted`。本例 r1–r5 五版离线全绿、实机全部黑屏。

## 2. 自测夹具（用户授权部署/启动后）

只在用户明确授权「自行部署并做简单测试」后使用；**只测到标题画面，不读档**。

- **部署/还原**：从一个 stage 目录拷贝 `natives/`、`reframework/`（以及测试用的游戏
  根目录文件）到游戏目录；不在 Fluffy 记录里的新增文件写入台账，清理时一并删除并清掉
  空目录；拒绝覆盖任何已有 `.pak`。还原时按 Fluffy `installed.ini` 放回原文件并逐个
  核对 SHA-256。
- **启动与判定**：用 `steam://rungameid/2246340` 启动；约 48–55 s 截图（对话框）；
  聚焦游戏窗口后用 SendInput 扫描码发 F 关闭对话框；再等 25–30 s 截图，计算平均亮度
  （排除左侧 20% 的 REFramework 菜单与右下角系统水印区域）。本例阈值 20：标题约 67，
  黑屏 < 5。随后结束进程，收集 `re2_framework_log.txt`、
  `reframework_accessed_files.txt`、`reframework_loose_files.txt`。
- **心跳探针**：一个只写 JSON 的 REFramework autorun 脚本（在
  `re.on_pre_application_entry("UpdateBehavior")` 里计数），用来区分「游戏卡死」与
  「游戏循环在跑、只是某个构建挂起」。测完删除。
- 截图要做 DPI 感知并缩放后再读，避免高分屏截到错误区域。

## 3. 负对照矩阵的设计

每个变体只改一个变量，并同时准备三类对照：

| 对照 | 本例变体 | 用途 |
| --- | --- | --- |
| 正对照 | 只装 BoneSystem | 环境与插件本身能进标题 |
| 负对照（加载器） | 原版贴图**逐字节**放回它自己的原版路径 | 黑 = 加载器/环境问题，与 mod 内容无关 |
| 参考对照 | 旧的、曾经可用的 mod | 黑 = 环境回归 |
| 引用隔离 | 所有 MDF 只引用原版 PAK 贴图 | 区分「MDF 字段」与「MDF 引用的贴图」 |

本例矩阵：正对照 TITLE；r5 BLACK；「MDF 只引用原版贴图」TITLE（Karin 模型与骨骼正常，
仅贴图是原版）；任何散装 `.tex`（包括原版字节原样放回）BLACK；贴图打成 PAK 无论放
哪个槽位都被忽略。据此把问题从 mod 转到 REFramework。

## 4. 运行时状态分层

- 标题自测通过 = `runtime-load-pass`（仅标题画面、仅冷启动）。
- 武器、野外地图、奔跑物理、表情、光照都需要用户在存档中验收；未被单独报告的项目
  写「未单独签收」。
- 手工部署供用户查看时，逐文件比对 stage 与游戏目录的哈希，并在交接中写清 Fluffy
  记录是否同步。

## 5. 发布内容

- ZIP 顶层一个 mod 目录：`modinfo.ini`、预览图、随包 README、`natives/`、`reframework/`。
- 随包 README 写：替换目标与冲突 mod、REFramework 与 BoneSystem 前置（含版本下限）、
  安装/回退方式、需要重点反馈的清单（附包 SHA256）、已知限制。
- 每次发布保存脚本基线快照与上一版的脚本差异，便于审查与回溯。
