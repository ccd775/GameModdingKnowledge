# Agent 入口（真三国无双 起源）

先读 [README](README.md)，再按当前问题进入对应文档。项目的当前状态写在独立工程的 `_versions/*/README.md` 和版本快照里，不在这里；本目录只提供方法和已被否定的假设。

## 接手一个新任务前

1. 核对 Steam appmanifest 的 `buildid`（本目录快照为 `21711288`）。build 变了，就要重新从资源表解出 KTID 槽表、骨架和原版权重。
2. 确认游戏根目录有 `dinput8.dll` 和 `DWOPATCHER/`。启动后加载器会写 `DWOPATCHER/patcher_log.txt`，可以用它确认 DLL 是否加载。
3. 比对游戏的 `DWOPATCHER/root` 和工程里的版本快照：逐文件比哈希，先弄清当前装的是哪一版。
   - 替换同一服装的 mod 互斥。PicodraTech 版和 Original 版用的是同一组 29 个文件名，后装的会覆盖先装的。
4. 工作区在百度网盘同步目录里时，云端占位文件（`.baiduyun.p.downloading`）会让读取卡住甚至挂死。
   - 大文件先从本地副本（游戏目录或会话暂存目录）复制。
   - 不要对同步目录里还在下载的文件直接跑 bash 管道。
5. 桌面可能被别的会话共用。启动游戏、发送键鼠之前先确认屏幕可用；测完关掉游戏。

## 硬性规矩（本项目已付过学费）

- **不改 SM1G / MM1G / ONUN / LLOC。**
  - 新调色板里的每个关节，都必须在模板或原版的某个调色板里已有 MM1G 逆绑定（`G1MMIndex`）。
  - 确实缺的，按浪人项目的做法追加 MM1G 并更新 FM1G 计数。本项目从未需要这一步。
- **先确认 gust 往返不改变 G1M**：导出后不改任何东西直接导入，G1M 应逐字节相同。之后再替换 vb/ib/vgmap。
- **8 位骨索引的顶点缓冲（身体、手、头发）里，调色板最多 85 个关节**：顶点里的索引等于调色板下标乘 3，要小于等于 255。脸的缓冲用 16 位索引，不受这个限制。
- **权重量化到 2^-11**，保证 8 个半精度权重的和恰好为 1。
- **换了 UV 布局，所有依赖布局的贴图都要重做或中和**：颜色、法线、类型 49 细节遮罩，以及脸的 t2 / t21 / t39 / t49 / t62。只有常量贴图可以原样保留。
- **平法线不要用 texconv 默认的 BC1**：它会编成偏斜的 (132,130,255)。用 BC7（解码为 (129,128,255)）或手写 BC1 块。
- **读档会自动存档**：读取任一存档都会立刻写 AUTO 槽和 `USER.dat`。自测前备份存档目录，并告诉用户 AUTO 槽会被覆盖。
- **菜单输入**：
  - 按键要按住约 150 ms，用扫描码发送，并先关闭中文输入法。
  - 主菜单的确认键偶尔会丢。每一步截图确认后再走下一步；脚本里要校验高亮行，不对就停下，不要盲按。
  - 旅馆菜单里方向键会被鼠标悬停抢走焦点，改用点击。
- **不要把离线渲染说成实机通过**。读档截图只算 `runtime-load-pass`，用户实际游玩确认后才算 `runtime-confirmed`。
