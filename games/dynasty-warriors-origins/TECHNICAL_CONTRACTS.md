# 技术合同（build 21711288）

标注说明：`[I]` = 引擎/格式不变量；`[B]` = 随 build 变化；`[C]` = 本案例数值。

## 1. 资源与加载器

- `[I]` 资源表是 KT 的 `_DRK` 格式：`root.rdb`（条目）加 `root.rdx`（索引），实际数据在 IDRK `*.fdata` 里。
  - 数据目录是游戏下的 `File/ASSET/FDataPackage/Dev`，有一部分 fdata 在 `File/DLC/4038930`。
  - 少数条目对应的 fdata 本机不存在，读取器要能跳过。
  - 浪人崛起项目的 `parse_rdb` / `read_fdata_entry` / `parse_kidsobjdb` 原样可用。
- `[I]` 材质贴图通过 KTID 解析：G1M 材质里的贴图下标 → KTID（`*.ktid`，每个槽一个对象 ID）→ kidsobjdb → G1T 文件哈希。
  - 要找到某个模型的 KTID：把所有 kidsobjdb 解析一遍，找槽数与模型贴图数一致、并且能全部解析的那个 KTID。
- `[I]` 加载器是 `dinput8.dll` 代理加 `DWOPATCHER/` 目录：
  - `root/` 下按哈希命名的散装文件（`0x<8 位十六进制>.g1m/.g1t/.mtl`）会覆盖 rdb 里的同名资源。
  - `DWOPATCHER.ini` 与 `Patches/` 是加载器自己的配置，mod 包里不要带，以免覆盖玩家设置。
  - `[B]` 加载器每次启动会重写 `DWOPATCHER/patcher_log.txt`。
- `[C]` 鸾翼将装：模型 `0x329ffb26.g1m`，KTID `0x6EE9F815`（63 个槽）。
  - mod 包有 29 个文件：1 个 G1M、1 个 `.mtl`、27 个 G1T。

## 2. G1M

- `[I]` 块顺序：FM1G、SM1G（骨架）、MM1G（逆绑定）、GM1G（网格）、LLOC、ONUN（NUNO 布料）、RTXE。
  - 替换角色只需要动 GM1G；FM1G 里的计数由导入器维护。
- `[I]` GM1G 的分节：GEOMETRY_SOCKETS、MATERIALS、SHADER_PARAMS、VERTEX_BUFFERS、VERTEX_ATTRIBUTES、JOINT_PALETTES、INDEX_BUFFER（R16 三角形列表）、SUBMESH、MESH_LOD。
- `[I]` 调色板条目是 `(G1MMIndex, physicsIndex, jointIndex)`，其中 `jointIndex` 就是 SM1G 骨表里的下标。
  - gust 把骨头命名为 `bone_<boneToBoneID[jointIndex]>`，即动画用的 ID，vgmap 要用同样的名字。
  - 顶点里的骨索引等于调色板下标乘 3。
- `[I]` 原版有些顶点缓冲是带 0x80000000 标志的分段复合缓冲，按 stride 和 count 直接切片会读错，要经过 gust 导出再读。

### 顶点格式（`[B]`）

- **身体、手、头发**：VB stride 56。
  - POSITION：R32G32B32。
  - BLENDWEIGHT 0/1：R16G16B16A16 半精度。
  - BLENDINDICES 0/1：R8G8B8A8_UINT。
  - NORMAL：R16G16B16A16 半精度，w 为 0。
  - TEXCOORD0：R16G16 半精度。UV 原点在左上，所以源模型的 v 要换成 1−v。半精度在 4096 贴图上的精度约 1 个像素。
  - TANGENT：R16G16B16A16，w 为 ±1。
- **脸**：VB stride 160。
  - BLENDINDICES 是 R16G16B16A16_UINT，所以调色板可以超过 85 个关节。
  - 另有 COLOR1/2/3、TEXCOORD8/9、FOG、PSIZE 几个属性，在 mod 和原版里都是常量或 NaN，没有存位置。
  - 所以把脸整体平移、缩放时，只需要改 POSITION。

## 3. G1T

- `[I]` 单贴图 G1T 的结构：文件头 → 偏移表 → 贴图头 → 数据。
  - 贴图头：第 0 字节高 4 位是 mip 数，第 1 字节是格式，第 2 字节是 log2 尺寸（高 4 位是高度，低 4 位是宽度）。
  - 格式码：0x59 BC1、0x5C BC4、0x5D BC5、0x5E BC6H、0x5F BC7。
  - 本作的贴图是线性排布（不像浪人那样做 tiled swizzle）。
- `[I]` 文件头偏移 0x1C 的 u32 为 3 时，表示法线贴图。原版存在 BC7 加标志 3 的法线贴图。
- `[C]` 写法：
  1. 用 `texconv -f BC7_UNORM -m <mips>` 编码，mip 一直做到 4×4（4096 的贴图有 11 级）。
  2. 套用同一个槽原来的 G1T 文件头，只改格式、尺寸、mip 数和文件大小。
  3. 写完后解码回读核对。
  - 尺寸和格式可以换，比如 BC1 2048 换成 BC7 4096，材质不在乎。

## 6. 工具

- gust_stuff v1.3.13（eArmada8）：
  - `g1m_export_meshes.py` 导出 fmt/ib/vb/vgmap 和 `mesh_metadata.json`；
  - `g1m_import_meshes.py` 按 metadata 重建 GM1G。
  - 删掉某个子网格的 ib/vb，导入时会把它剔除。需要保留结构时，写一个退化三角形更稳妥。
- DirectXTex `texconv`：编码与解码。解码时把裸 mip 链套上 DX10 DDS 头再交给 texconv。
- Blender 4.0.2：只在后台导出源 FBX（rest 姿势、形态键按当前值、按 corner 的法线、8 骨权重、内嵌贴图）。
