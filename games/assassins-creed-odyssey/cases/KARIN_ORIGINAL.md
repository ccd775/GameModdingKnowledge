# 案例：Karin_Original → 卡珊德拉（2026-10-19 → 10-23）

游戏：PC Ubisoft Connect 版（产品 5059）v1.5.6，`ACOdyssey.exe`。源模型：Karin_Original（FBX + VRM），用的是刺客信条：影项目里规范化过的 blend 和贴图，
与本库其它 Karin 项目同源；不随本库发布。

**用户需求**：「使用 Karin_Original 替换游戏中的卡珊德拉……尽可能使用影的那种角色替换（无论穿什么装备都替换），如果无法做到再考虑使用黑旗重置那种
指定一套装备替换。」里程碑 1 = 模型和材质，之后是次级物理和表情。游戏在另一台测试机上；授权在那台机器上安装、启动、测试，存档是测试存档，可以随意处理。

## 1. 工具链

- 自写 `aco_forge.py`（forge v28 索引 / 提取）、`aco_locate.py`、`aco_install.py`（原地追加安装）、`bt_tool.py`、`build_mod.py`、`aco_phys_skel.py`、
  `aco_pose_sim.py`；AnvilToolkit 1.3.6 经 AcoHarness（从影项目的 harness 分出）无界面调用；Blender 5.0.1 上的拟合、表情、导出、预览脚本是影项目脚本的
  奥德赛副本。
- 先摸清卡珊德拉的可视图（VisualMaster 的列、身体 LODSelector、头部表、头发表），确认「不论装备」的替换在这一作可行，没有退回到单套装备的做法。

## 3. 关键判断

- **不论装备的整角色替换在这一作可行**：卡珊德拉的全部装备都在 VisualMaster 的一列里，去掉这一列就够了；身体 LOD0 / LOD1 是她专属的独立数据文件。
  没有用到单套装备的退路。
- **先列全副本，再动手**：v1 的品红色和残留装备都来自「只改了一份」。用 `aco_locate.py find` 先看每个 ID 在哪些 forge 里，可以省掉这一轮。
- **材质先查模板吃什么**：皮肤 / 服装模板的漫反射是编码数据。图集路线在进游戏之前就放弃了，`ACD_Tex1` 一次成功。
- **眼睑花了六轮（v4、v5、v6、v7d、v7、v8）**：前三轮（v4–v6）都是从用户的描述推断游戏里眼睑骨的角度再改增益 / 预转，每次修好一个症状又引出另一个。真正推进的是两件事：
  不对称的诊断构建配合用户录像的逐帧测量（量出实际转角），和对头部骨架全部姿势的分析（每根眼睑骨都被十几个姿势共用）。早一点做后者，
  v6 / v7 两轮可以省掉；它直接说明了「只靠蒙皮时，常态稳定和完整眨眼只能取舍」，剩下的是让用户选。
- **离线预览不能预测游戏里的偏移**：v7 在 `pose_preview.py` 里每个状态都正常，实机却被扫视驱动的 1–2° 偏移推翻。离线工具只能排除「静止形状错」
  「某个姿势撕裂」这一类问题。
- **一轮只改一类**：里程碑 1 先只做模型和材质；物理和表情在 v4 一起上，之后每轮只调一处（v5 的物理和表情同时改，是因为用户的反馈同时覆盖了两者）。
