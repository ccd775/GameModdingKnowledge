# 案例：Karin_Original → 杰洛特（2026-10-17 → 10-19）

游戏：PC 次世代版，`witcher3.exe` 5.0.1048522（菜单 v5.01，DX12）。源模型：Karin_Original（VRM 1.0 和一份 Blender 能干净导入的 FBX
`Karin(Clone)_BlenderSafe.fbx`，SHA-256 `18F00E1A…AEB16997A`），与本库其它 Karin 项目同源；不随本库发布。

**用户需求**：「使用 Karin_Original 中的角色替换杰洛特……第一个里程碑是模型替换，完成后再进行次级物理效果的装配与表情的装配。」
授权：研究、下载工具、离线构建、部署到游戏的 `mods`、启动游戏测试；存档是测试存档，可以随意处理。

## 1. 工具链

- 自写 `w3bundle.py`（v5 bundle）和 `w3metadata_write.py`（v7 store）；Witcher3-Blender-Tools v1.1.0（Blender 5.0）；WolvenKit 7 nightly 2026-10-14 的 CLI。
- 一开始先做 T1：空模板 + 自己的 bundle 和 store 能不能让杰洛特消失 —— 只放 bundle 时毫无效果，加上 store 才生效。

## 3. 关键判断

- **整角色走物品模板**：杰洛特没有身体网格，所有外观都是按名字解析的物品。铺满全部模板（含 DLC）比改玩家实体或脚本都稳，
  也不会被换装、发型、胡子状态绕过。
- **骨架不动，拟合几何**：W3 动画带平移，改骨长没有意义；比例问题（脖子、上身、肩）全部在拟合这一层解决。
- **物理问题的大部分时间花在「停下后的形状」上**：dyng 在重力 0 时上限内几乎不拉回节点，所以真正有效的是「挂锚点 + 滚转规则 + 小上限 + 刚性形状链接」，
  而不是调刚度。早一点在所有保形链上同时加形状链接，可以省掉 v0.4.2 → v0.4.3 这一轮。
- **验收要看用户的视角**：v0.4.0 和 v0.4.1 都是 agent 正面 / 背面截图「看起来对」，用户从侧面一眼看出扭曲。之后每一轮都加侧面截图，并和目标姿势的
  离线渲染并排比较。
- **离线复现再改**：裙子穿模先在 Blender 里用游戏的走跑动画复现出用户描述的位置（髋侧偏后），确认是 look-at 把漂移传上去，再只改那一圈。
