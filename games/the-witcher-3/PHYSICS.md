# 物理（dyng 次级物理）

Karin 的头发、耳尖、狐尾、裙摆和丝带用游戏自己的 dangle 系统：发型物品里一个 `CAnimDangleComponent` + `CAnimDangleConstraint_Dyng`，
资源是自己生成的 `karin_body.w3dyng`（格式见 [技术合同](TECHNICAL_CONTRACTS.md) §7）。整个 Karin 网格都蒙在这个 dangle 的骨架上，
跟原版薇丝（Ves）的身体 dyng 一样：`man_base` 的每根骨（除 `Root`、`Trajectory`、`Reference`、`IK_*`）都是一个锚点节点，
后面接 Karin 的物理链和碰撞代理。v0.4.4：230 个节点（80 个模拟）、361 条链接、91 个 look-at 三角形，网格 176 根骨。

## 1. 语义（全部实机验证，`invariant`）

| 量 | 含义 | 怎么确认的 |
| --- | --- | --- |
| 节点 `distance` | ≤ 0：钉在动画上；> 0：节点最多能离开它动画位置多远 | v0.1 甩动小就是这个上限卡住的（不是刚度）；加大约 1.75 倍后幅度上来 |
| 节点 `stiffness` | 拉回刚度目标的强度，目标 = dyng 父节点 × 局部变换 | §3 |
| 节点 `mass` | 越大越不容易回去，效果像刚度的倒数 | 一条双马尾质量 ×3 停在外翻状态，另一条回去了 |
| 链接类型 0 / 1 / 2 | 0 刚性（保持长度）、1 最小距离、2 最大距离 | 一条 5 cm 的「头 → 尾巴尖」链接：类型 2 把尾巴拉起来，类型 1 没有效果（2026-10-17） |
| 三角形 (a, b, −1) | a 把 X 轴对准 b（look-at）；滚转规则见 §4 | 只用在单子节点的链上：一个分叉的根（`Skirt_root`）对准其中一个子节点，整个裙腰扭了 |
| 约束 `gravity` | 设 0 后链不再下垂 | 实机 |
| 约束 `wind` | 原版发型 3.0 把长链一直吹向一侧；0.4 也一样 | 实机 → 0 |
| 约束 `dampening` | 原版不设；0.985 摆得更多，但停在奇怪的形状、走一段后尾巴打结 | 实机 → 不设（`pipeline.ps1 -Dampening` 默认不写） |

还有：Karin 的 VRM spring 的 `gravityPower` 是 0（丝带 0.0025）：链靠刚度保持建模时的形状，只因运动而甩。所以约束的 gravity 和 wind 都设 0。

## 2. 分组与最终参数（v0.4.3 / v0.4.4，`case-derived`）

`karin_build.py` 的 `DYNG_GROUPS`。深度从链根算起（根 = 0）；深度 ≤ `anchor_depth` 的节点钉在动画上；模拟节点的上限
`distance = d0 + dstep × (深度 − anchor_depth − 1)`；质量从根到梢线性插值。

| 组 | 链根 | anchor_depth | 上限 d0 + dstep/节 | 质量 | 刚度 | 形状链接 | 碰撞代理 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 双马尾 | `Hair_tail_L/R`（各 6 个模拟节点） | 0 | 0.03 + 0.03（梢 0.18 m） | 1.0 → 0.6 | 2 | 隔 1、2 节 | 背上 / 中 / 下、髋、两上臂 |
| 侧发 | `Hair_side_L/R` | 0 | 0.025 + 0.025 | 1.0 → 0.7 | 2 | 隔 1、2 节 | 头 `head_c` |
| 刘海 | `Hair_front_root` | 0 | 0.02 + 0.02 | 1.0 → 0.8 | 2 | 隔 1、2 节 | 头 `head_c` |
| 头饰丝带 | `Ribbon_L/R` | 0 | 0.035 + 0.035 | 0.8 → 0.6 | 2 | 隔 1、2 节 | — |
| 耳 | `Ear_L/R` | 1（根和中段钉住） | 梢 0.015 | 0.6 → 0.5 | 3 | — | — |
| 狐尾 | `Tail`（6 个模拟节点） | 0 | 0.035 + 0.04（梢 0.235 m） | 1.0 → 0.6 | 2 | 隔 1、2 节 | 髋、两大腿 c1 / c2 |
| 裙 | `Skirt_root`（腰圈 + 第一段钉住，下面两段模拟） | 2 | 0.06 + 0.09 | 0.6 → 0.5 | 2 | 环（同深度相邻片之间类型 2，绑定距离 × 1.15） | 髋、两大腿 c0–c2、两膝；每节点 5 个、margin 0.03；髋高一圈 `snug_depth` 3 |
| 其它丝带 | 吊带、上衣、手上的丝带 | 0 | 0.025 + 0.025 | 0.6 → 0.5 | 2 | — | — |

- 父节点：**每个模拟节点直接挂在链的动画锚点上**（头、骨盆、躯干、手；`nearest_humanoid` 找到 Karin 的上级人形骨再映射到 `man_base`）。
  链接和 look-at 仍沿 Karin 的链。上限因此是相对建模形状的绝对偏移。
- look-at：每个单子节点的链节点一个三角形（指向它唯一的子节点），共 91 个。
- 碰撞（§6）：每个模拟节点，到最近的 n 个代理（默认 2）各一条类型 1 链接，长度 `min(半径 + margin, 0.98 × 静止距离)`。

## 3. 保形：刚度目标随父节点走（v0.4.0 → v0.4.1）

- 重力 0 以后，刚度是唯一维持形状的力。刚度 0.1–0.3 看不出恢复力：运动把链甩到哪就飘在哪。原版：普通垂发用刚度 0 + 重力；保形的 dyng
  用 1–10（叶奈法的卷发 2.0，白虎铠甲 4.0），而且没有三角形。
- 实机里，一条带 look-at 的链（三角形 a → 子节点）刚度 10 仍然外翻着不回来；同一条链去掉三角形就回到原形：**look-at 把子节点的刚度目标
  跟着转走了**。v0.4.0 于是用刚度 2（耳 3），双马尾、尾巴、侧发、刘海、丝带去掉 look-at。
- 被 v0.4.1 取代：v0.4.0 的链停下来是扭的（用户：静止时尾巴 S 形、双马尾扭曲）。根因是刚度目标 = dyng 父节点 × 局部变换，**模拟的父节点
  拖着子节点的目标走**：带 look-at 时停在外翻，不带时停在扭曲的形状。改成每个模拟节点直接挂在动画锚点上，跟原版保形的辫子一样
  （菲丽芭：辫子节点挂在 `torso3` 上，look-at 沿辫子），look-at 恢复。

## 4. 链骨的朝向（v0.4.1，实机验证）

- **look-at 的滚转规则**：游戏把 X 对准目标，Z 尽量保持 dyng 父节点的 Z（保号）。绑定姿势里滚转不符合这条规则的骨，静止时就是转过的。
  早先按「X 对准子节点、任取一个参考轴」建的骨在双马尾、侧发、头饰丝带上差约 175°：发卷朝外翻、侧发从脑后支出来；离线按这个滚转渲染
  （把每根骨按规则重建）与游戏截图一致。现在每个 look-at 节点的绑定朝向按规则建（Z = 父节点 Z 对 X 正交化），`checks/rule_check.py`
  报告 91 个全是 0°。原版的 look-at 节点也遵守（|Z · 父 Z| 中位数 0.98）。
- **非 look-at 的节点用平行移动**：把父骨的坐标系转到这根骨的方向上，不绕骨轴扭。按 X 取参考轴的做法在尾巴中段换了参考轴，两根骨各翻了 180°，
  游戏里尾巴变成捏扁的 S 形。原版链 1307 对相邻骨里 98.7 % 扭转 < 30°。
- 双马尾跟着头保持形状：杰洛特有些待机小动作会大幅歪头（伸展脖子），这时双马尾跟着头甩到接近水平。不想要的话可以把双马尾锚在 `torso3`
  （菲丽芭的做法），未试。

## 5. 上限内几乎没有恢复力：小上限 + 刚性形状链接（v0.4.2 → v0.4.3）

v0.4.2 的实验（威伦，冲刺急停后看 12 秒；和 `checks/blender/idle_view.py` 渲染的目标姿势对比）：

- 重力 0 时，节点基本停在运动把它留下的位置，只要还在上限内。所以**静止误差 ≈ 上限**；相邻节点停在不同方向，链就折了。
  - 尾巴刚度 0.7、上限 0.05 + 0.06/节：根部折痕（v0.4.1 用户反馈「走完停下尾巴折起来」）；刚度 1.4 同上限：卡在侧面、有折痕；
  - 刚度 2、上限 0.04 + 0.05/节：顺滑但停在抬高约 20° 处；刚度 2、上限 0.035 + 0.04/节：回到原位。
- 双马尾的梢部上限：0.42 m 冲刺急停后卡在外翻（可能挂在上臂碰撞上）；0.21 m 抬着约 7 秒；0.18 m（0.03/节）回到原形。
- **刚性形状链接**：每个节点到链上隔 1 节、隔 2 节的节点各一条类型 0 链接，长度 = 绑定距离（原版的跨节链接都等于绑定距离：防折的用类型 1，
  有些是类型 0）。链保持建模时的弯曲，只能整条绕根摆。
- **所有保形的链都要加**：v0.4.2 只给尾巴加了，用户下一轮就看到双马尾和侧发停下来是扭的（它们的上限允许每节 18–36°）。v0.4.3 给双马尾、侧发、
  刘海、头饰丝带都加上，侧发上限降到 0.025/节。

## 6. 碰撞代理

- 代理是挂在动画骨上的锚点节点，半径在拟合后的身体上量（离代理中心的距离，取 90 百分位；背部取 60 百分位）：
  - 大腿 `*_thigh_c0/c1/c2`（大腿骨上 12 % / 30 % / 65 % 处）、膝 `*_knee_c`、上臂 `*_arm_c`（上臂根到肘 35 % 处）；
  - 髋 `hips`（两髋关节中点下 3 cm）、背 `back_lo/mid/hi`（`torso` / `torso2` / `torso3`）；
  - 头 `head_c`（v0.4.3）：头骨空间 (0.03, −0.02, 0)（X 上、Y 前、Z 左），选在「头发顶点 − 中心」最接近刘海 / 侧发下面脸部法线的位置
    （平均夹角约 14°，`checks/blender/face_geom.py` 网格搜索）；半径取到最远的脸部顶点。刘海和侧发离脸只有 0.5–3 cm，而上限是 2–10 cm，
    v0.4.2 跑步时往后甩就进了脸里。现在每个刘海 / 侧发节点到中心的距离不能小于静止距离的 98 %，只能往外或沿着脸摆。
- 链接：模拟节点到最近 n 个代理（按「距离 − 半径」排）各一条类型 1，长度 `min(半径 + margin, 0.98 × 静止距离)`（取 98 % 是为了静止时不违反约束；
  `checks` 里在待机姿势验证过没有被违反的碰撞链接）。
- 碰撞只作用在节点上：节点之间的发丝和裙面仍可能碰到身体。这也是 §7 要把裙子部分蒙到大腿上的原因。

## 7. 裙子

- 结构：腰圈和第一段（髋关节以上）钉在动画上，下面两段模拟。整条裙子都放开时，裙子塌到臀部上，皮肤从裙子里露出来（早期，`rejected`）。
- 抬腿穿裙（v0.2.0）：节点之间挡不住大腿 → 髋关节以下的裙子部分蒙到大腿上（[角色拟合](CHARACTER_FIT.md) §5），裙摆上限 0.06 / 0.15，加了大腿代理 c0。
- 走路时髋侧穿出（v0.4.3 → v0.4.4）：
  - 位置：髋关节以上 0–6 cm、大腿外侧偏后；
  - 原因：髋高的那圈（深度 3，第一圈模拟节点）在碰撞链接（半径 + margin）挡住之前可以往里漂 2.4–4.1 cm；上面钉住的深度 2 那段 look-at 着它，
    跟着转进了臀部，而那里的裙子离皮肤只有 1–1.5 cm；
  - 离线复现（`checks/blender/skirt_walk_sink.py`）：杰洛特的走、快走、慢跑、冲刺各 8 帧，把模拟节点水平推到各自碰撞链接允许的最里面，
    `_002` 和 `_001` 两段按 look-at 跟着转，再沿皮肤法线对裙子做射线检查。v0.4.3 每帧 10–22 个皮肤顶点穿出，最深约 1.1 cm；
    不转 `_001`、或者 dyng 全刚性时都不穿 —— 是 look-at 把漂移传了上去；
  - 处理：组参数 `snug_depth` 3：这一圈到每个代理的距离不小于静止距离的 98 %，只能往外摆。40 帧里不再穿出（全刚性模式下有 1 个顶点在某一帧露出 0.7 cm，
    v0.4.3 时也是这样）。下面的裙摆不变，仍能被抬起的大腿顶开。
- 离线检查的坑：最近面的有符号距离在百褶上没法用（相邻褶的法线方向交替）；要沿皮肤法线射线检查，并过滤 12 cm 以上的命中（打到了裙子另一侧）。

| 版本 | 改动 | 反馈 |
| --- | --- | --- |
| 早期 | 原版发型约束 wind 3.0；整条裙子模拟 | 双马尾和裙子一直偏向一侧；裙子塌到臀部 → wind 0、裙子上部钉住 |
| v0.1.0 | 首版 dyng | 用户：甩动幅度小、耳尖静止时塌、大腿穿出裙子 |

| v0.3.0 | 只改体型 | 用户：待机时上臂根部有缺口；双马尾和尾巴总是垂着，原模型是保持形状的 |
| v0.4.0 | gravity 0、wind 0；刚度 2（耳 3）；保形链去掉 look-at；上限按急停实验定 | 用户：静止时尾巴 S 形、双马尾扭曲（正面 / 背面截图看不出来） |
| v0.4.1 | 模拟节点直接挂锚点；look-at 恢复；绑定朝向按滚转规则；非 look-at 用平行移动 | 中间版用户确认尾巴形状对了但几乎不动、双马尾仍扭（滚转修复前）；v0.4.1 用户：走完停下尾巴折叠 / 打结 |
| v0.4.2 | 尾巴刚度 2、小上限 + 刚性形状链接 | 用户：尾巴好了；双马尾、侧发停下后扭曲；跑步时刘海、侧发穿进脸里 |
| v0.4.3 | 头上所有链加形状链接；头部碰撞代理 `head_c`；侧发上限 0.025/节 | 用户：「看起来好了」 |
| v0.4.4 | 裙子髋高一圈 `snug_depth` 3 | 用户 v0.4.3 时：「走动的时候，侧面的大腿依然会有少量穿出裙片」；v0.4.4 待实测 |

规律：

- **形状问题先看是不是上限内的漂移**：重力 0 时 dyng 不会可靠地把节点拉回原位。允许摆得越多，停下时的姿势越随机；要保形就缩小上限、加形状链接，
  别指望加刚度。
- **实机 A / B 一次测两个变体**：左右两条双马尾各用一组参数，一次进游戏就能比较（本项目刚度、上限、质量都是这样定的）。
- **look-at 会传递**：钉住的节点看着模拟节点，就会跟着它转；离线检查不模拟这一点就复现不出穿模。

## 9. 已知限制

- 双马尾、侧发、刘海和尾巴都只能整条摆动，自身不弯；摆动幅度比 v0.2 小（换来了保形）。
- 头部碰撞只作用在头发节点上，节点之间的发丝可能仍有轻微穿插。
- 头发不和剑鞘碰撞；剑鞘沿用杰洛特的背部槽位，会穿过双马尾。
- 裙摆部分跟随大腿，所以它自己的摆动比头发小；腿抬到接近水平以上时仍可能轻微穿插。
- 骑马、大幅抬腿、与 NPC 的对话动作未逐项看过（[验证与发布](VALIDATION_AND_RELEASE.md) §4）。
