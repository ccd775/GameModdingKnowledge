# 浪人崛起（Rise of the Ronin）

## 范围

本目录整理 Steam《Rise of the Ronin》（App `1340990`，光荣特库摩 Team NINJA 的 KT 引擎）的角色替换方法，资料来自 2026-08 → 10-12 的两个 Karin 项目：

- 修复并持续维护一个现成的 Karin mod；
- 从源模型完整构建第二个 Karin。

两者都替换同一组资源：主角的「火男」头巾、两套服装身体，以及被隐藏的原版基础身体和绑腿。共 74 个按哈希命名的散装文件，由 ROTR Mod Loader（`RONPATCHER`）加载。

| 交付 | 内容 | 最高证据级 |
| --- | --- | --- |
| Karin_Picodra 20260908c / e / f | 用户自己的蓝白 Karin（源模型来自 PicodraTech）。修复头发与脸部脏污、下身材质与亮度、背部标志，以及胸前和外套侧边的 UV；f 还补回了手腕和手指动画 | `runtime-confirmed`（用户逐项认可；f 为可再发行基线） |
| Karin_Picodra 20260908g / 20260916a | 膝盖尖刺修复，原版占位三角形塌缩；右手掌心与指骨重新校准；下身 AO 补齐 mip | `runtime-load-pass`（agent 实机自测）；右手与下身明暗用户未验收 |
| Karin_Picodra 20261004a | 腿部按原版分段权重重新分配；恢复 13 张被改坏的共用贴图（NPC 发白）；下身 SHADING 改为原版均值 | `offline-accepted`：构建机未装游戏，未实机测试 |
| Karin_Original 20260929a → 20261004a/b | 从 FBX 源模型构建头、两套身体与三张颜色图；两个头部变体：清空玩家脸 / 包住玩家头 | 20261001h/i：`runtime-load-pass`（agent 实机正面与背面自测）；20261004a/b：`offline-accepted` |

所有哈希名、骨号、子网格号、阈值和贴图数值都是 `build-sensitive` 或 `case-derived` 快照。
它们对应 build `20673762`（2026-09-30 的 appmanifest；09 月的笔记记作 1.09 版），换 build 后要重新测量。

### 与 KT 引擎其它项目的关系

- 《真三国无双 起源》（完整仓库里的 `games/dynasty-warriors-origins/`；单游戏导出包不含）共用以下格式：
  - `_DRK` 资源表 `root.rdb/rdx`；
  - IDRK fdata；
  - KTID / kidsobjdb；
  - G1M / G1T。
- 本目录便携包的 `ktdata.py` 在那边原样可用。G1T 的存储方式不同：浪人的大贴图是 DX12 64 KB tile，起源是线性的。
- 骨架、材质槽和贴图语义都是各作自己的，不能互相套用。

## 主要结论

- **mod 是一组按哈希命名的散装文件**，放进 `RONPATCHER/root`，`0x<哈希>.g1m/.g1t` 覆盖资源表里的同名资源。
  - 资源表 `root.rdb/rdx` 从不修改。
  - 散装文件比原版大也没问题：已实测，加载器能正确处理超出原体积的覆盖。
- **玩家自己的捏脸头始终绘制**。任何头盔都不会隐藏它，原版火男头巾 `0xD462CD01` 只是包在它外面的一层壳。替换头部有两条路：
  - 把新头做得能完全包住原头；
  - 清空女性捏脸头 G1H `0xB24CAC84` 的全部三角形，男性为 `0x1249DB5D`。
- **隐藏原版几何 = 把三角形塌缩成同一个索引**，文件长度不变。
  - 原版留下的 3 顶点 / 3 索引占位面也要一起塌缩，否则动画下可能有面积，挡住光。
- **调色板里存的是骨号（bone id），不是骨架存储序号**：G1MS 的 id 表负责把骨号映射到存储序号。
  - gust 的 `bone_<n>` 命名、动画、本目录所有骨号都用骨号。
  - 原生逆绑定满足 `MM1G = inv(G1MS world).T`，只有少数辅助骨和布料调色板例外。
- **顶点着色器只读前 7 个权重，第 8 个影响取余量**，最后归一化 N/T。
  - 权重量化到 2^-11，保证存下的 8 个权重之和恰为 1。
  - 骨索引等于调色板下标乘 3，8 位索引时调色板最多 85 根骨。
- **原版的腿从不直接绑膝骨**。它把腿分摊到辅助骨上（大腿 129/85、膝 87/89、小腿 89/91、胫 91/93、踝 93 + 7、脚 7 + 25）。
  - 膝盖以下整段绑一根骨头时，脚不随脚踝弯，跑步时两条小腿互相穿插。
- **共用贴图**：替换服装覆盖的贴图哈希也会被其他模型使用。
  - 最严重的例子：`0x1E76FD2D` 是全局 1×1 R32F 默认值 1.0，1102 个角色模型的 DIRT 槽都在用。上游 mod 把它改成 0，NPC 的皮肤、手、腿、牙齿因此发白。
  - 每个覆盖都要查有没有别的模型在用。
- **大 G1T 用 DX12 64 KB tile 存储**（额外头第 10 字节为 1）。
  - 按线性读会看到「左右两半是副本」的假象。项目早期的「折叠不变量」「u 和 u+0.5 双采样」两种理论都源于这个误读，均已撤回。

## 核心方法

- **先查清每个槽属于谁**：
  1. 从 KTID 槽表和 TextureAlias 表解出每个模型的贴图槽；
  2. 逐个比对 mod 文件和游戏原文件（是否相同、是否常量、格式与 mip）；
  3. 再查这张贴图还有哪些模型在用。
  - 换平、换常量、恢复原版字节或重烘焙，之后再决定。
- **改动以最小单位进行**：
  - 只改一个变量，在冻结基线上构建新候选，绝不覆盖已有包；
  - 发生回归先定位、再回退，不用整体提亮掩盖。
- **每次写回都回读**：
  - 用独立解析器检查哪些块、哪些字节变了；
  - 检查权重和、新增绑定是否为原生矩阵；
  - 做离线姿势测试；
  - 最后实机截图。

## 证据纪律

沿用本库五级：`reference-inferred` / `offline-accepted` / `runtime-load-pass` / `runtime-rejected` / `runtime-confirmed`。

- 主菜单和标题画面里的角色不算实机证据。
- 资源字节没变，不能推断实机外观没变：同一组文件在不同冷启动下的亮度也会不同。
- 2026-10-12 有外部分析报告「NPC 发白没修好」。查明分析对象是游戏目录里 10-01 部署的旧版（Karin_Original 20261001h），不是 20261004a。
  - 处理用户反馈前，先把游戏目录的 `RONPATCHER/root` 与各发布包的 manifest 逐文件对哈希。
