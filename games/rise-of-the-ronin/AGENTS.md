# Agent 入口（浪人崛起）

先读 [README](README.md)，再按当前问题进入对应文档。

项目的当前状态写在独立工程里，不在这里：交接 SOP、`release/README.md` 和每个包的 `manifest.json` / `validation.json`。本目录只提供方法、合同和已被否定的假设。

## 接手一个新任务前

1. **确认游戏在不在。** 核对 Steam appmanifest 的 `buildid`（本目录快照为 `20673762`）和游戏根目录的 `fdata_package_dx12`。
   - 这台机器上游戏多次被卸载又重装。卸载后 `RONPATCHER/`、`dinput8.dll` 和备份目录还留着，但没有游戏数据。
   - 计划任何需要取游戏文件或实机的步骤之前先查这一项。离线工作用工程里保存的原版文件副本（附带 sha256）。
2. **确认当前装的是哪一版。** 把游戏的 `RONPATCHER/root` 与各发布包的 manifest 逐文件对哈希。
   - 两个 Karin mod 用同一组文件名，互斥安装，后装的覆盖先装的。
   - 2026-10-12 有一次「修复没生效」，原因就是游戏目录里还是 10-01 部署的旧版。
3. **分清用户说的是哪个 mod。** 「我自己的那个」「蓝白色的」指 Karin_Picodra；Karin_Original 是第二个 mod。2026-10-04 曾把反馈做到错误的 mod 上。
4. **百度网盘同步目录**：
   - 云端占位文件会让读取卡住甚至挂死，对整个目录做 `find`/`grep` 可能卡几分钟到几小时；
   - 大文件先复制到本地会话目录再解析；
   - 卡住的命令要按进程号结束，不要放着不管。
5. **桌面可能被别的会话或游戏共用**：
   - 启动游戏、发送键鼠之前先确认窗口在前台；
   - 测完用正常关闭（WM_CLOSE），不要强杀。

## 硬性规矩（本项目已付过学费）

- **不改 `root.rdb` / `root.rdx`，mod 包里不带加载器自己的 `RONPATCHER.ini`、`Patches/`、`system/`。** 只交付 `RONPATCHER/root` 下的覆盖文件。
- **模型只动 GM1G，以及必要时的 MM1G 和 FM1G 计数。**
  - SM1G（骨架）、LLOC、ONUN（布料）保持原样。
  - 新调色板里的每根骨都要有 MM1G 逆绑定：缺的就追加原生矩阵 `inv(G1MS world).T`，并把 FM1G +24 的矩阵计数同步加上。
- **8DC 身体的绑定约定和 651 不同**（有多项 MM1G 是单位阵），不能把 651 或 4BA 的矩阵照搬给 8DC。
  - 8DC 部分旧权重的索引也不是 3 的倍数，不要顺手全局重排调色板。
- **头部颜色只写 `0x97338C5A`。** `0xC29D729F`、`0xD4824BF5` 不是 Karin 头的副本，它们属于 C097 头盔模型 `0x3B6EAD06` / `0x666BBE1F`。
  - 把头部图集镜像进去，曾让脸出现蓝白条纹、上身错乱、下身发暗、尾巴变成深蓝。
- **覆盖一张贴图前先查共用**：`ktdata.py usage` 列出还有哪些模型画这张贴图。
  - 属于隐藏部件、但别的模型在用的贴图，要恢复游戏原字节，不要改成常量。
- **贴图只走 `g1t_tool.py` 的 `describe` / `dds`，按每级 mip、每个图层处理。** 不要把 tiled 载荷当线性读；也不要直接清零存储标志，实测会出现粉色图集块。
- **替换贴图保持原容器**：尺寸、格式、mip 数和头部都与原文件一致。游戏自己的 BC 贴图 mip 一直做到 4×4。
- **新构建用新目录和新标签**，脚本拒绝覆盖已有输出。已认可的冻结包（c / e / f）不得覆盖。
- **不反复改用户已认可的部分**（头发、脸、背标、下身明暗）。精修在冻结基线上独立构建；发生回归先定位、回退，不靠整体提亮掩盖。
- **构建链里每一步的输出都要随输入一起重跑。** Karin_Original 有一次姿势测试复用了旧的 `pose/` 输出，配上新网格得出 18043 倍的荒谬拉伸。
- **不把离线渲染或标题画面说成实机通过。** 读档后的截图只算 `runtime-load-pass`，用户实际游玩确认后才算 `runtime-confirmed`。
- **用户说不派审计时就不派**（modding 工作审计默认降档）。自查后交付，报告里写明未审计、未实机。

## 报告口径

结论归入 `invariant` / `build-sensitive` / `case-derived` / `hypothesis` / `rejected` 之一。

历史上的失败不删除；后来的证据只用来收窄旧结论的适用范围，并写明哪条取代了哪条。

推测性的根因（例如下身 SHADING 的 G 通道接近镜面）要标 `hypothesis`，并写出怎样在实机上推翻它。
