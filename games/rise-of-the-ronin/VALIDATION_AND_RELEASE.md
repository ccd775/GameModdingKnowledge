# 验证与发布

## 1. 离线闸门（每个候选都要过）

- **输入身份**：记录模板包和游戏原文件的 sha256，脚本开头就核对。原版文件要来自游戏本体或带哈希的离线副本。
- **改动范围**：
  - 用独立解析器（`g1m_tool.py`，不要用写入时的同一份代码）列出哪些块、哪些 G1MG 分节、哪些顶点字节变了。超出计划的变化一律报错。
  - 腿部改动用 `leg_weights.py check`：只允许混合字节、调色板、MM1G 和 FM1G 计数变化。
- **骨与权重**：
  - 调色板下标乘 3 不超过 255（8 位索引）；
  - 存下的 8 个权重之和恰好为 1；
  - 新增绑定满足 `inv(world).T`（误差 < 1e-4）；
  - 已有的调色板条目和绑定逐字节不变。
- **姿势**：
  - 静止姿态的偏移要小；
  - 离线弯肘、屈膝、弯脚踝、转颈 60°，看拉伸和穿插；
  - 弯脚踝时脚要跟着动。
  - 离线 FK 把辅助骨当刚性子骨，只能算提示。
- **贴图**：
  - 容器长度和头部不变；mip 数达到 4×4 或与原版一致；
  - 常量贴图解码后是同一个值；
  - 改动过的共用贴图，用 `ktdata.py usage` 确认没有别的可见模型在用。
- **重跑整条链**：任何上游输出变了，下游的姿势测试、证据和报告都要清空重跑，不能拿旧输出配新网格。
- **离线渲染只是辅助**：每个离线渲染只采样一次，分辨率本身也是变量（900 px 下看着干净，2400 px 下有斑块）。

## 2. 打包

- 包名：`Karin_<线>_<日期><字母>[_变体]`；每个新候选用新目录和新标签，脚本拒绝覆盖。
- 包内容：
  - `RONPATCHER/root/`：74 项，hidehead 变体 75 项；
  - `README.md`（中文）：改了什么、为什么、是否实机测试过、怎样安装和回退；
  - `manifest.json`：每个文件的 sha256、大小，以及来源标注，例如「沿用基线」「恢复游戏原版」「原版均值常量」「重新蒙皮」；
  - `validation.json`：离线检查结果，以及没测的范围；
  - `tools/`：构建这个包用到的脚本。
- ZIP 生成后重新打开，逐个文件核对哈希。
- 已被用户认可的冻结包（c / e / f）不得重写。
  - 要恢复某一项时，单独提供 `Restore-*.ps1`：先核对候选和备份的哈希，只恢复这一项，其他文件不动。

## 3. 安装、部署核对与回退

1. 退出游戏。
2. 把包里 `RONPATCHER/root` 下的文件复制进游戏的同名目录。不要动 `RONPATCHER.ini` / `Patches/` / `system/`。
3. 部署前把整个旧 root 备份到 `RONPATCHER_backups/<日期>_before_<包名>/`，并核对哈希。
4. 部署后把游戏目录的 root 与包的 manifest 逐文件对哈希，确认数量一致（74 或 75）。
   - 从 75 项的 hidehead 换回 74 项的包时，要删掉多出来的捏脸头文件，否则玩家的脸仍然是空的。
5. 启动后看 `patcher_log.txt`：每个 root 文件都应该有一行 `added to virtualization`。
6. 回退：放回上一版包的 root，或从备份目录还原。

## 4. 实机自测流程

前提：用户已授权启动游戏，并允许操作专用测试存档。先备份存档目录。

1. **启动**：直接运行 `Ronin.exe`。这台机器上 Steam 的 `-applaunch` 会静默失败。每次冷启动都要重新查进程号和窗口句柄。
2. **按键**：
   - 只在游戏窗口位于前台时发送，否则拒绝发送；
   - 用 SendEvent，每次按住约 200 ms；
   - 字母键被输入法吃掉时，只给游戏窗口切换英文布局，结束后恢复，不要改全局输入法设置。
3. **标题流程**：
   - 标题界面的开场动画会自动重播。Space 可以跳过开场；在「PRESS ANY BUTTON」按 Space，在已高亮的 CONTINUE 上再按 Space，离线提示框的默认按钮是「确认」，也按 Space。
   - 标题界面上 Enter 和 Escape 不可靠。确认键偶尔会丢，每一步截图确认后再走下一步。
4. **等待读取**：提示界面可能要 3–4 分钟。画面均值一直不变，直到游戏画面出现。
   - 偶尔会停在着色器编译 30515 / 30515，正常关闭再启动即可。不要改全局画质或清缓存。
5. **取证**：
   - 进游戏后先看到角色背面，适合检查后颈。
   - Esc 打开菜单，Q / E 切换标签；地图之后再按两次 E 是装备页，那里有带光照的正面。
   - 照片模式：P 进入，Esc 退出。右键加相对鼠标移动是平移，左键是转向，滚轮升降。绝对坐标的 MouseMove 拖动无效，要用相对的 mouse_event。
   - Backspace 收刀 / 拔刀，F 切换流派，可用来检查握刀的手。
   - 画面流送有延迟，刚载入时可能显示错误的低级贴图。等角色脚下的地面亮度高于约 40 再截图。
   - 游戏中有时会随机出现红色的「暗夜」横幅，叠在头上会让高频指标翻倍。截取区域里有红色像素就重拍。
   - 本地 OCR（Windows 的中文 / 英文识别）可以帮助导航；识别不到文字不代表失败。
6. **判读**：
   - 主菜单和标题画面里的角色穿着 mod，但不算证据；
   - 装备界面的姿势和高光每次都不一样，对很小的改动做像素级 A/B 不可靠，要用对姿势不敏感的指标（例如头部斑点能量）；
   - 截图里的数字只是辅助，不能替代用户验收；跨场景、跨距离、跨清洁状态的截图不能拿来比较。
7. **收尾**：用正常关闭（WM_CLOSE），不要强杀。把用户最终要用的那一版重新部署，并核对哈希。

## 5. 证据级别

| 级别 | 本游戏里的含义 |
| --- | --- |
| `offline-accepted` | 回读、权重、绑定、姿势、贴图检查全部通过，没有进游戏 |
| `runtime-load-pass` | agent 读档后，在装备界面和游戏中截到了图 |
| `runtime-confirmed` | 用户实际游玩后认可（写明认可的是哪一项、哪一版） |
| `runtime-rejected` | 用户或自测在游戏里看到了问题（保留截图和版本） |
