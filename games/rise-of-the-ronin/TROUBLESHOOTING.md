# 排障手册

## 按症状

| 症状 | 已证实的原因 | 处理 |
| --- | --- | --- |
| 部分 NPC 的身体、手、腿、牙齿发白发亮 | 共用的全局默认值 `0x1E76FD2D`（1×1 R32F，1102 个角色模型的 DIRT 槽）被改成了 0；另有 12 张被别人使用的贴图被改过 | 恢复游戏原版字节（[材质与贴图](MATERIALS_AND_TEXTURES.md) §3）；`ktdata.py usage` 查其它覆盖 |
| 修复「没生效」 | 游戏目录里装的不是新版。2026-10-12 的外部分析对象是 10-01 部署的旧包 | 用 manifest 逐文件核对 `RONPATCHER/root` |
| 跑步时两条小腿互相穿插，脚的姿态不对 | 膝盖以下整段绑在一根骨上，脚不随脚踝动 | `leg_weights.py` 按原版分段重新分配（[角色替换](CHARACTER_REPLACEMENT.md) §1.6） |
| 深屈膝时下身出现几何尖刺 | 权重之和不为 1（0.74–1.24），加上原版占位面 | 只在膝部区间内归一化；`collapse-placeholders` |
| 下半身整体偏暗，而贴图看起来是对的 | 原版的 3 顶点占位面在动画下有面积，挡住光（已证实）；SHADING 被改成常量、遮罩被改成零（部分证实） | 塌缩占位面；遮罩改回 R=255；SHADING 用原版均值 |
| 下半身在某些天气、时间变暗或变红 | `hypothesis`：下身 SHADING 的 G 被压到 8，接近镜面，映出天空颜色 | 20261004a 改成原版均值，待实机确认；嫌暗就提亮 COLOR |
| 同一组文件在不同冷启动下亮度不同 | 未闭合。同一组文件的冷启动结果不稳定，单次 A/B 不能下因果结论 | 多次冷启动对照；不要用「字节没变」推断实机没变 |
| 下身出现原版服装的浮雕杂纹 | NORMAL `0xB406343D` 没有被覆盖，走的是原版法线 | 补一张平法线 |
| 脸上蓝白条纹、上身错乱、尾巴变深蓝 | 头部图集被镜像进 `0xC29D729F` / `0xD4824BF5`，这两个文件属于别的模型 | 只写 `0x97338C5A`，那两个文件保持原样 |
| 头发脏、有蓝灰斑块 | 发丝明暗太弱，盖不住各 UV 岛的色偏；另有管线造成的蓝色污染 | 恢复发丝明暗，按源图做直方图匹配；改色按几何选 |
| 头上有深色条纹（修复之后才出现） | 不限幅的锐化，加上不限范围的死区填充 | 锐化加限幅；死区只在岛周围的一圈内填充 |
| 背部标志错乱 | 原 mod 的图在无光照下就是乱的 | 从源材质局部重烘焙 |
| 手指不随动画，或指尖绕到别处 | 上衣调色板没有手指骨；补了原生绑定后，关节位置与 mod 的手对不上 | 补 32 根原生骨，再用局部仿射校准指骨的逆绑定 |
| 原角色的脸或后颈露在外面 | 玩家的捏脸头始终绘制，头巾不会隐藏它 | 清空捏脸头 G1H，或把新头做得能包住它（hidehead / wrap） |
| 头看起来被拉长、扁平 | 为了包住原头把头加深了 1.3 倍 | 改用两个变体之一 |
| 长屋里像有「绑腿」 | 袖子三分之一的权重在手骨上，被手腕带着扭转 | 袖子只跟前臂 |
| 进室内时小腿出现原版绑腿 | 未解决；怀疑是脱鞋后的装备 `0x8D74E8C2` | 需要游戏数据：取出、塌缩、实测 |
| 跨步时大腿穿出裙片 | 裙摆贴合太紧 | 跟随 0.75 + 下摆外扩 1.5；离线姿势会低估实机 |
| 姿势测试出现 18043 倍的拉伸 | 构建没有重跑姿势测试，旧的 `pose/` 和新网格的顶点顺序对不上 | 每次构建都清空并重跑 |
| 贴图里看到「左右两半是副本」 | 把 tiled 载荷当线性读了 | 只通过 `g1t_tool.py` 读 |
| 清零存储标志后出现粉色图集块 | 只改了标志，没有重排载荷 | 用 `g1t_tool.py storage` 一起改 |
| 补齐 mip 后，脏污没有变化 | mip 缺失是真问题，但不是这个症状的原因 | 保留补齐（远处不再闪烁），另查原因 |
| patcher_log 里看不到某个模型的 Open | 日志的 Open 行不完整 | 用 `added to virtualization` 确认接管，用画面确认效果 |
| RenderDoc 抓不到帧（target control 的 `api=` 一直为空） | 游戏经 NVIDIA Streamline（`sl.interposer.dll`）创建 D3D12 设备；RenderDoc 的 DXGI / LoadLibrary 钩子装上了，但设备创建绕过了它 | 别再试 RenderDoc；用实机探针贴图，或尝试 PIX（未试） |
| 读取或 `ls` 卡住几分钟 | 百度网盘的云端占位文件 | 先把文件复制到本地会话目录；卡住的进程按进程号结束 |
| 同步盘里的 texconv 报「云操作超时」 | 可执行文件是云端占位文件 | 用本地副本 |

## 已证伪或撤回的假设

- **「头部图集左右两半必须相同（折叠不变量）」「运行时在 u 和 u+0.5 各采一次」「运行时按平铺方式采样头部图集」**：三条都来自把 tiled G1T 当线性读，已撤回。按这些假设写的工具（强制折叠、镜像右半）不要再用。
- **「散装文件比原资源大会出问题」**：已撤回。改走 fdata + RDB 后渲染完全相同（头部斑点 11.097 对 11.140）。
- **「RDB 的依赖列表是材质绑定」**：已撤回。6 万多个 G1M 记录都是同样 5 个哈希。
- **「mip 链损坏导致头部脏污」**：已撤回。v1.9 的 mip 比原版的更接近 BOX 下采样，补齐后实机差异低于抖动。
- **「死区颜色经 mip 渗进来」**：已撤回。原版的 mip 漂移更大，原版却看着没问题；填充死区反而让色度变差（39.10 → 46.95）。
- **「共面 z-fighting」**：已撤回。深度复杂度大于 1 的像素只占 1.7%（原版 0.7%），最多 3 层。
- **「下巴暗块是原版的脸透出来」**：已撤回。只用 mod 网格和图集，在离线渲染里就能复现。
- **「AO 贴图缺 mip 是下身偏暗的完整根因」**：已撤回。第一次冷启动对照变亮了，第二次没有复现。
- **「下身变暗是手部修改造成的」**：没有证据，不能这样推断。
- **「4230 属于 627 模型」**（依据是日志里加载时间相邻）：已撤回。KTID 反查不支持；异步日志里时间相邻不能证明资源归属。
- **「社区 mod 用了我们没用过的打包技巧」**：已撤回。两个 Nexus mod 只改 VB / IB / SUBMESH，与本项目的做法相同。
- **「离线指标变好 = 实机变好」**：反例很多，例如色度 / 亮度比被亮度条纹骗过、低分辨率渲染把斑块平均掉。始终以实机为准。
