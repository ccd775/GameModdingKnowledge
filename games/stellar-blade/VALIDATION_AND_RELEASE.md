# 验证与发布

## 1. 离线闸门

| 闸门 | 内容 | 通过条件 |
| --- | --- | --- |
| 打包校验 `verify_pack.ps1` | 解析自己的容器：网格骨数、空材质、变形数 | `VERIFY_OK`；本例身体 315 骨、3 个材质、0 空材质；脸 61 个变形 |
| 参考姿态对比 | 打包后的 bind 姿态 vs 原版 | 共享的带权重骨 ≤ 1.2° / 0.2 cm；负缩放辅助骨差 180° 但无权重 |
| 骨架兼容 | 网格骨在游戏骨架里是否存在、父骨是否相同 | 除明确的网格独有辅助骨外全部一致 |
| AnimBP | 编译结果；cook 出的导入在游戏里是否都存在；图拓扑与游戏服装 AnimBP 对比 | 0 错误 0 警告；导入全部可解析 |
| 属性读回 | 用导出文本设的曲线、胶囊等再读回来 | 数量和值与预设一致 |
| 构建日志 | AnimBP 脚本的成功标记 | 没有成功标记就**不 cook**（曾经 cook 出缺 AnimBP 的包） |
| 穿模（Blender） | 刚性裙子下摆出跑步、弓步、脊柱扭转等姿势，从骨盆轴径向比较皮肤与裙子半径 | 被覆盖的皮肤顶点不越过裙面；只能排除权重问题，不能证明物理没问题 |

离线全绿只是 `offline-accepted`。

## 2. 远程实机测试

本项目的游戏装在另一台机器上，通过 SSH（命令、文件）和计划任务代理（桌面输入、截图）操作。

- **桌面共享**：其他会话（和用户自己）也会用那台机器。约定用锁文件（内容为占用者名字）：不存在时才能拿，只删自己的，
  释放时通知对方。只用 SSH 不需要锁。另一款游戏在运行时不要启动本游戏，也不要关别人的游戏。
- **安装**：游戏运行时拒绝安装；用后台循环等游戏退出后再装，装完列出哈希。
- **启动**：Steam 在多个账号间切换时，`steam://rungameid` 可能只打开 Steam 窗口；从拥有游戏的账号的库里启动。
  首次启动需要用户批准 UAC（Steam Client Service）。
- **游戏内**：Esc 打开的是装备菜单，不是暂停菜单。退出路径：设置 → 离开 → 退出游戏 → 确认。
  每批输入前先点一下游戏窗口（启动代理任务会抢焦点）；运行对话框会失焦，点它的「确定」而不是按回车。
  中文输入法默认中文模式，`text` 会把 `//` 打成 `、、`，先按 Shift。
- **存档**：测试「继续」前备份存档；先确认存档穿的是目标服装。

## 3. 运行时证据

- **诊断标记**：AnimBP 在物理节点**之后**加 ModifyBone，把一根网格独有骨和一根骨架骨缩放 ×2。读法：
  - 两个都变大：后处理 AnimBP 在运行，网格独有骨可写，问题在 Kawaii；
  - 只有骨架骨变大：网格独有骨被覆盖；
  - 都不变：后处理 AnimBP 根本没运行。
  本项目的结果是两个都变大，最终定位到 Kawaii 按骨架建链。
- **连拍**：在游戏里连续按 Steam 截图键（F12），几张截图之间的头发、尾巴、裙摆变化才算物理证据，取回后删除。
  自写的 PowerShell 抓屏连拍脚本被 Windows Defender 当作恶意脚本拦截；不要绕过杀毒软件。
- **不能当证据的**：停步、跳跃的单张截图。头发向后甩、尾巴翘起可以完全来自对头部、骨盆的刚性挂接。

## 4. 发布包

内容：两个 IoStore 包（身体 + 物理一个，脸 + 隐藏件一个）、`SHA256SUMS.txt`、`install.ps1` / `uninstall.ps1`
（共用一个 Steam 库查找脚本）、中文 README。

- 发布的文件取自用户验收时 `~mods` 里装的那一套，逐个比对哈希。
- `install.ps1`：从注册表找 Steam，读 `libraryfolders.vdf` 找到 `steamapps/common/StellarBlade`；游戏运行时拒绝；
  先按清单校验包内文件，复制到 `SB/Content/Paks/~mods`，复制后再校验。也可以用 `-GameDir` 手动指定。
- `uninstall.ps1`：只删本 mod 的 6 个文件，其他 mod 不动。
- 用 Windows PowerShell 5.1 在临时的假游戏目录里测过：找到真实游戏目录、安装、卸载（保留其他包）、
  损坏的包被拒绝。
- README 写明：身体只在目标服装上出现，脸和头发对所有服装生效；不要与替换同一批资源的 mod 混用；适配的游戏 build；
  已知限制。
