# 案例：Karin_Original → 亚诺（2026-10-24）

游戏：PC Steam 版（289650）build 21970519，游戏内 1.5.1，`ACU.exe`。源模型：Karin_Original（Unity FBX `Karin(Clone)_BlenderSafe.fbx`，膝盖已烘焙 + VRM），
与本库其它 Karin 项目同源；不随本库发布。

**用户需求**：替换亚诺为 Karin_Original，首选「不论穿什么装备都替换」（像影和奥德赛那样），不行再退回替换一套装备；第一阶段模型和材质，
第二阶段表情和次级物理。v1 / v2 授权在本机测试（存档可随意处理、测完关游戏）；之后用户要求「提供可再部署的 mod 包」，在另一台电脑上自己测试。

## 1. 工具链

- 从奥德赛项目分出：`acu_forge.py`（forge v27）、`acu_install.py`、`bt_tool.py`、`build_mod.py`，Blender 的拟合 / 表情 / 导出脚本，AcuHarness（AcoHarness 的分支）。
- 新写：`scan_objs.py` / `objs_to_tsv.py`（内嵌副本扫描）、`head_bones.py`（从原版权重认头部骨）、`acu_phys_skel.py`（附加骨架生成）、`make_release.py`
  （发行包）、`prep_karin_original.py`（从 FBX 规范化源模型）、`render_compare.py`。

## 3. 关键判断

- **先查内嵌副本**：v1 的「装备和牙齿都还在」不是表改错了，而是同一个对象还有很多份。大革命里先用 `scan-objs` 列出每个目标对象在哪些数据文件里，
  比按名字找数据文件可靠（名字表只有数据文件名，看不到里面嵌了什么）。
- **闪退先对照数据，不追代码**：`ACU.exe` 加了壳，转储里只有约 0x100 字节代码。读出循环在用哪些字段，就把自己的骨架和全部原版骨架对照这些字段，
  一轮找出三处差异；三处一起修，下一版就能启动。
- **物理先理解约束模型**：v4 → v5 是「直垂」和「不动」两个极端，原因是 BallJoint 没有弹簧。重力补偿偏移的轴向和符号没有文档，是从原版 116 个带偏移的关节
  统计出来的（v5 时第一次统计认为「对不上」，镜像的一对互相矛盾；v6 重新统计：按骨自己的局部坐标系解释时 93 个朝外、7 个朝内，其它组合都在随机水平）。
- **碰撞一次只改尺寸**：v6 打通了碰撞路径但胶囊太小；v7 只改胶囊（加一个、加粗 3 cm、覆盖到髋关节）和裙片锥角，同时备一个半径加倍的诊断包，
  万一 v7 不行就能区分「碰撞没生效」和「不够大」。
- **一轮只改一类**：v2 只做模型和材质；v3 / v4 加表情和物理；v5–v7 只调物理。表情至今没有单独的反馈。
