# 验证与发布

## 1. 离线闸门

构建脚本里的断言与报告：

- 可见槽 ≤ 11；骨链的父子与骨架一致；每条链有顶点、关节位置合理（`build_report.json` 的 `verts` / `joints_cm`）。
- `build_report.json` 里没有未映射的顶点组；静止时重叠而被关掉碰撞的刚体对单独列出（新式链不关腿部碰撞）。
- 编辑器骨架与游戏参考姿势逐骨比较（≤ 0.0003 cm / 1e-7 rad）；网格骨旋转与 W 比较（7e-8）。
- 重构回归：参照 profile `karin_original` 的构建与已发行 v6 逐字节一致（`cloth.json` 与 blend 网格数据）；改过公共脚本后重跑一次，
  并确认已发行模型的 `cloth.json` 没变。

预览（agent 看图判断）：

- 全身联系表（静止、跑步、前踢；正 / 侧 / 背）：穿模、悬挂件方向、贴图分页是否对。
- 游戏动画姿势预览（腰部特写）：躯干分布、裙腰与皮肤的间隙。
- 面部：眨眼、Ah、Oh 不凹陷不撕裂。
- 裙摆替身（`skirt_sim.py`）：候选之间比较「皮肤穿出 > 1 cm 的帧数」，2 / 6 次迭代都同意才采纳。

UE 与 pak：

- `ue_build_out.json` 每步成功；插件的布料报告（如 `Cloth_Skirt verts=352 fixed=32 backstop=288 normals_out=352`）与
  `DumpSections` 核对 section 和布料绑定。
- pak 读回：每个材质槽、后处理动画蓝图都指向 `/<asset_dir>/`；pak 文件数、两边 MD5 一致。

## 2. 实机闸门

1. 首次前备份存档；只读档。
2. 游戏关闭时把 pak + sig 放进 `~mods`；用户原来装的同类 mod 先移出并备份。
3. 标题画面（女主出现在标题背景里）→ 读档 → 武馆院子走动 → 攻击 / 技能预览。
4. 物理和表情用连拍录屏（15 fps）+ 联系表看，而不是单张截图；眨眼要在镜头转到正面时看。
5. 收尾：关游戏，恢复用户原来的 mod 布局，删除连拍帧。

## 3. 发行包

```text
<pak名>/
  <pak名>.pak
  <pak名>.sig          （游戏 pakchunk0 的 .sig 复制改名）
  安装说明.txt          （UTF-8，CRLF）
<pak名>_v<版本>.zip    （内含上面的文件夹，生成后 testzip）
```

安装说明写：适用的游戏版本、安装（关游戏，复制两个文件进 `Sifu\Content\Paks\~mods`，没有就新建）、卸载、替换范围
（女主默认服装网格，因此第 2、3 套服装和部分女性分身敌人也会变）、内容（模型、材质、表情、眼球、物理）、
**同一组替换同一网格的 mod 一次只装一个**、`.sig` 必须同名、MD5。

## 4. 证据分层（本项目）

| 项 | 级别 |
| --- | --- |
| mod pak 加载、标题画面与武馆里的替换网格 | `runtime-load-pass`（agent 截图） |
| 材质修复（贴图生效、白发 / 黑丝带 / 红色点缀 / 刺绣） | agent 实机截图（A/B 构建 + 最终构建） |
| 骨链 v2（不再钟摆） | agent 连拍：待机无残余摆动、停步 0.3–0.5 s 稳定、旋转攻击甩出后恢复 |
| 眨眼 | agent 实机连拍 |
| 躯干分布 v3（跑步不再露腰） | agent 实机连拍，腰后保持一条固定的缝 |
| 裙摆 v3 → v6 | 用户实机逐轮反馈；v6：「基本好了」→ `runtime-confirmed` |
| 眼球转动（v4） | 用户反馈「眼珠不转」后修复；之后的反馈没再提，未单独确认 |
| 另外四个模型 v1 | `offline-accepted`：预览、面部（PicodraTech、Y）、pak 引用检查；未进游戏 |

**未测场景**：对话里的口型、过场动画、完整战斗流程、第 2、3 套服装、女性分身敌人、高速动作下的裙摆布料细节（只看过用户反馈的那几招）。
