# 案例：Karin_Original → 女主默认服装（2026-10-12 → 10-13）

游戏 build `18739835`（`v_1.29_6.775`）。源模型：Karin_Original 的 VRM 1.0（39 个 spring、脸上 237 个形状键），与本库其它 Karin 项目同源；
不随本库发布。用户之前装过一个旧的 Karin mod（W 关节位置、两个材质挂在 `M_CharaMaster_Cloth` 上、4096 图集、自动生成的布娃娃物理资产、
头发上一个 NvCloth、无次级物理）。

**用户需求**：用 Karin_Original 替换女主默认服装；之后按实机反馈修。授权：研究、提取、离线构建、部署到 `~mods`、在测试机上启动游戏。

## 1. 工具链

- AES 密钥从 shipping exe 扫出来（[技术合同](../TECHNICAL_CONTRACTS.md) §1），CUE4Parse 写成 SifuExport。
- 测试机上装 UE 4.26.2（用户装）和 VS2019 Build Tools（用户同意；UBT 实际用了 VS2022 的 MSVC），建 `Sifu` 内容工程和 SifuModTools 插件。
- 编辑器里的 `Base_skeleton` 按游戏参考姿势重建。

## 2. 版本轨迹

| 版本 | 改动 | 结果 / 反馈 |
| --- | --- | --- |
| 测试 1–4（10-12） | 首个完整构建：网格、表情、NvCloth 裙摆；双马尾分别试 NvCloth 管状代理（m2a）和骨链（m2b） | 都能加载、能动；整个人发暗看不出贴图；m2a 的发束被撕碎 → 否决 |
| 测试 5 | 修材质槽为 `null` 的问题（UE Python 结构体副本） | 仍偏暗，原因未查明，之后没有复现 |
| v1（t6 / t7） | A/B 构建（游戏贴图对照红色双马尾）确认贴图生效；最终构建 | agent 实机截图：白发、黑丝带、红色点缀、刺绣可见 |
| v2（10-13） | 骨链按 VRM spring 参数重调（加速度驱动公式、降重力、线阻尼 8、碰撞组） | 用户反馈 v1 像钟摆；v2 agent 连拍：待机稳定、停步 0.3–0.5 s 稳定 |
| v3 | 躯干权重照 W；裙摆代理贴内包络、锥形大腿胶囊 | 用户：跑步前倾时腰腹露出、大腿侧面切进裙子 → 修复；agent 跑步连拍确认腰后只剩固定的缝 |
| v4 | 裙摆碰撞只留骨盆 / 腿 / 手臂、顶环上移；眼片眼骨权重 0.12 | 用户：裙子松垮、腰部有缝；眼珠不转 → 修复 |
| v5 | backstop（插件实现、代理法线朝外）；裙腰前部跟皮肤 | 用户：「大部分情况都好了，少数姿态下，大腿侧面会稍微有点露肉」 |
| **v6** | 代理 11 环 × 32 段、`SolverFrequency` 240 | 用户：「基本好了」；发行 |

v5 → v6 的诊断：大腿皮肤从没超出胶囊（≤ 0.3 cm），是代理下排被穿过。用裙摆替身跑 263 帧（跑步 + 9 个踢腿 / 膝击动画）比较
「加密」「加粗胶囊」「提高求解频率」，选了加密 + 240 Hz（[物理](../PHYSICS.md) §4–5）。

## 3. 流程上的教训

- 一开始怀疑光照 / 材质参数，实际是材质根本没挂上；**先读回烘焙结果，再调外观**。
- 骨链调参从源模型的物理参数出发，用公式定刚度，比在游戏里试数快。
- 每个裙摆反馈都先在离线替身里复现，再改；避免了「加粗胶囊」这种静止时就把裙子撑开的改法。
- 物理只改参数时用 `physics_only` 路线，不重跑 Blender，几分钟一轮。
