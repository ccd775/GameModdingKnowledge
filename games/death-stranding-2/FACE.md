# 表情（有表情版）

无表情版的脸在身体网格（手套材质）里，刚性跟头。有表情版把 Karin 的脸放进山姆的脸皮网格，用游戏自己的 RigLogic 面部绑定驱动。

## 1. 槽位：只有脸皮 LOD2 能用

- 身体骨架 50118 没有任何面部关节。
- Porter 独有的内衬领口 50108:595（各级 78 / 85 / 490 / 310 / 562）只有颈、下颌线、下巴下的关节，**没有眼睑和嘴唇**，做不了表情。最初的计划用它，后来作废。
- 山姆脸皮 LodMesh 50120:1：
  - LOD0 253、LOD1 81 带 ZivaRT，顶点数绑死，不能导入；
  - **LOD2 50120:186**：240 个面部关节（含 6 个 `EyelidUpperA`、20 个 `LipLower`、14 个 `Chin`），1354 个顶点，没有 ZivaRT；LOD3 229、LOD4 45 同理。

  做法：Karin 的脸写进 186 / 229 / 45；链接表（v8f 段）把 LOD0 / 1 也改指 186；面部部件 50108:43 保持原版（无表情版把它改指已塌缩的 595）。
- 脸皮用山姆的皮肤材质。贴图组 67673（`sam_face_def_v00_wm0`，键 `F9A`）的 4 套颜色都换成 Karin 的脸，法线全平，所以表情皱纹法线（74331，105 个组共用，不能改）的混合无效。67673 也是 500、58946、67632、67648 的子组；夹克替身 67632 的底色用它自己的 `sam_face_naked`，不受影响。

## 2. RigLogic 解码（`rigdec.py`）

- 数据：`FacialRigSettingWithLODResource 34853:315` 的关节矩阵，5607 × 734（行 = DNA 关节 × 9 个属性 tx ty tz rx ry rz sx sy sz，列 = 258 个原始控制 + 476 个 PSD）。
- 存储：float16，**16 行一块、块内列主序**，末尾有一块 8 行的；中性值和增量的单位是米和弧度，欧拉序 scipy 的 `'xyz'`。
- DNA 有 623 个关节。DNA 关节 → 骨架关节用面部组件 50108:49 的 `CorrespondingJoints`（骨架关节 → `PerLodJointIndexes[0]` 的槽位 → DNA 关节）。按变换匹配（`rig_map.json`）对共轴心的关节有歧义，作废。
- 骨架 67692 = 67711 的前 299 个关节，同名同序，绑定与脸皮网格的逆绑定矩阵一致。
- `face_motion.py` 输出每个控制量下各关节的世界增量（cm）→ `face_motion.json`。

### 控制号（原始控制按 MetaHuman 顺序）

| 控制 | 含义（值 1） |
| --- | --- |
| c10 / c11 | eyeBlinkL / R：上眼睑 A +32°，眼球 2° |
| c14 | 睁大 |
| c22 | 上眼睑上抬 |
| c30 / c31 | 向上看 |
| c32 / c33 | eyeLookDownL / R：眼球 40°，上下眼睑一起下移 |
| c34–c37 | 左右看 |
| **c200** | 张嘴：`JNT_C_F_000_LowerLipRotation` rx +24°（下唇、下牙、舌头的父骨） |
| c201 / c202、c203 | 下巴左右 ±9°、前伸 |

`rejected`：v17f 把 c32 / c33 当成眨眼（其实是向下看），眨眼只闭三分之一。验证一个控制要看眼球关节的转动，不能只看眼睑。

## 3. 拟合（`build_ds2.py --face`）

- 按 Karin 自己的形态键拟合每顶点的关节权重：`w = clamp(<S, D> / <D, D>, 0, 1)`，S 是形态键位移，D 是关节在该控制下的位移场。
  - jaw ← `kuchi_A`（c200，拟合 0.71）；
  - blink_L / R ← `blink_L` / `blink_R`。
- 方法来自 AC 系列 Karin 的 `face_rig.py`（本库 `games/assassins-creed-odyssey/` 的表情部分）。

### 眼睑杠杆

上眼睑关节的转角很小，套到 Karin 的大眼睛上闭不拢。做法是改该关节的逆绑定矩阵，让它绕一个离眼睛更远的点转（“绑定偏移杠杆”），转同样的角度扫过更大的弧：

- 候选关节：`EyelidUpperA/B` 000–003，只取近景网格 186 关节表里有的（v19f 首次构建时左眼选了 186 没有的 000_A）；
- 网格搜索杠杆偏移 u（侧 ±6、前 0–60、上 ±8 cm），选拟合最好的；`patch_core` 按任务里的 `ibm` 改该关节的逆绑定矩阵；
- 两侧统一用 A 组：右眼 B 组眨眼只闭 0.53，向下看时反而睁开。

### 眨眼强度

`BlinkSettingResource 74336:1`（`DS1TargetValue` 0.7、`RandomValue` 0.3）让游戏里的普通眨眼只走到控制值约 **0.52**：

- 证据：用 v17f / v18f 的设置复算，它们在完整眨眼下闭合 0.64 / 0.97，实测分别是“三分之一”“一半”，两次独立观测都指向 0.52。
- v19f 起按 0.55 拟合（`face_motion.py` 的 `BLINK = 0.55`）：左 `L_001_A` u = (0, 60, −2)、右 `R_001_A` u = (0, 54, 2)，0.55 下闭合 0.98 / 0.96。
- 代价：完整 1.0 的眨眼（睡觉闭眼）过闭 1.7–1.75 倍，完全向下看 2.1–2.3 倍，完全左右看时眼睑漂移 p95 1.3–1.5 cm。
- v19f 之后用户没有再报告眨眼问题，但也没有单独确认。

### 尖刺

v18f 用户报告“一根尖刺跟着动”：杠杆的位置补偿用的是拟合时的权重，而 `restrict()`（关节不在该 LOD 的表里 → 并到父骨）或后一次拟合缩放后，实际导出的权重变了，静止时有顶点离位（186 上 1 个顶点 6.7 cm，LOD4 10 个顶点到 10.8 cm）。现在按量化后的导出权重算补偿，三级都是 0。

## 4. 阴影与天气

- **鼻嘴阴影**（v19f 用户报告，动漫脸不该有）：
  - 两版都把 `Karin_Face` 的法线在网格上扩散平滑（约 3 cm，75 步），离外轮廓 1.5 cm 内渐回原法线（`anime_face_normals`）；
  - 有表情版另把脸皮网格 186 / 229 / 45 的 DrawFlags 低 2 位清零（`F03C004B` → `F03C0048`，按 EShadowCastMode 3 → 0 推断；山姆的 0x48 网格就是这个值），脸不再投影，鼻子不在唇上投影。`PrimitiveResource.Flags` 全是 3，没有逐图元的投影开关，所以无表情版只能靠平滑法线。
  - 修正后用户没有单独确认。
- **雨天脸变暗**（用户报告）：山姆皮肤材质的湿润效果和晒伤层（67648 `sam_face_def_v00_wm0_sunburn`，按山姆脸部 UV0 布局，随日晒加深）作用在脸上。67648 被替身共用，不能改；这是用户决定保留无表情版的原因。
