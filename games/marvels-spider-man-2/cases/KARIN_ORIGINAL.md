# 案例：Karin_Original → Peter / Miles（2026-10-12 → 10-14）

游戏：PC 版 v1.130.1.0（toc SHA-1 `318f4345f3a1`）。本机提取、远程测试机实测，两边的 toc / exe 哈希相同。
源模型：Karin_Original 的 VRM 1.0，与本库其它 Karin 项目同源，不随本库发布。参考：作者之前给漫威蜘蛛侠1 做过的角色替换 mod（i29）。

**用户需求**：用 Karin_Original 替换两个主角，先做基础的模型和贴图替换；通过后尝试物理和表情；最后把物理扩到其它战衣。
授权：研究、提取、离线构建、在测试机上安装和测试。测试机还有别的会话共用桌面，大多数轮次由用户自己进游戏看。

## 1. 工具链

- ALERT 的 `dat1lib` 读 toc 和算 CRC。i30 的变长资产头、`.model` 各段、蒙皮、动力学段、`.actor` 都是自己写的 Python 读写。
- 安装器复刻 Overstrike 的 i30 安装逻辑，不依赖 Overstrike。
- 动力学和挂接的关键问题用 exe 逆向（静态反汇编）定位，两轮多代理调查。

## 3. 关键判断

- **为什么要替换全部战衣**：每套战衣都是独立的身体模型，存档装备的战衣决定显示什么（T4b）。
- **为什么链要离开战衣模型**：T10–T13 都是「约 1 秒后冻结」。逆向确认是每帧门控：SkinManager 创建的战衣部件没有 owner actor
  （[物理](../PHYSICS.md) §3）。这一条在 T15 之前只是推测，T19 / T20 的冻结又让人误以为是动画集或 IsHero 的问题，
  直到逆向把门控条件逐条列出来。
- **为什么选头 actor**：它由带面罩战衣的每个 loadout 生成，有自己的 AnimController，模型谁也不用。
  它冻结的真正原因是 NeverCull = false 加上不到 1 mm 的关节包围球，两处数据改动就修好了。
- **一个载体两族通用**：Peter / Miles 的 head 关节 bind 差 21 mm，但 Karin 的脸在两族的世界位置几乎一样，实机 Miles 没有偏移。

## 4. 交付

- v1：108 个模型 + 3 个头、面部骨骼表情、裙子修正；物理只在蜘蛛猫战衣上（119 个资产）。
- v2：v1 + 头部载体覆盖 91 套带面罩战衣（124 个资产）；便装 / young / 两个过场模型保持静态链。
- 两版都附纯标准库安装器（install / status / uninstall，以 `toc.BAK` 为基准）。

## 5. 遗留

- 便装（Peter 10、Miles 4）与 young 的物理：把链放进各自的头模型，并在头 actor 里插入 NeverCull 字段。
- 共享头 actor 的副作用（invisible actor、nomask 剧情段）：根治需要给英雄单独做头 actor（新资产 id，未验证能否加载）。
- 眨眼需要解 Morph2；Karin_Alpha（眼睛高光 / 腮红）需要半透明材质；切线未解（用平法线）。
