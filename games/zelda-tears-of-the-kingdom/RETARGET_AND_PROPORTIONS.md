# 重定向与比例

`build_karin.py` 的几何部分。数字是本案的 `case-derived` 值；方法和限制适用于把任何人形模型装到 Link 的套装骨架上。

## 1. 按段相似变换

Karin（VRM 人形骨骼，FBX 导出到游戏空间：Y 上、+Z 前、米）的每根人形骨得到一个 4×4 相似变换：

1. 先整体缩放 `S_BODY = 1.38`；
2. 把源骨段方向转到 Link 对应骨段的方向。有参考方向时用两个方向定出完整的旋转（`frame_rot`）；
3. 在 `STRETCH` 里的骨段（上下臂、上下腿、Spine、Chest）沿骨段拉伸到 Link 的骨长；
4. 平移，让源关节落到 Link 的关节上。

顶点按 Karin 自己的蒙皮权重线性混合这些变换（`blend_transform`）。非人形骨用最近的已映射祖先。这样手和手指在每一段内保持刚性。

骨骼对应在 `HUMANOID`：

| Karin | Link |
|---|---|
| Hips | Waist |
| Spine / Chest | Spine_1 / Spine_2 |
| Neck / Head | Neck / Head |
| UpperLeg / LowerLeg / Foot / ToeBase | Leg_1 / Leg_2 / Ankle / Toe |
| Shoulder / UpperArm / LowerArm / Hand | Clavicle / Arm_1 / Arm_2 / Wrist |
| 手指 Proximal / Intermediate / Distal | `Finger_{A..E}_{1..3}`，A = 拇指 … E = 小指 |

- 右手指骨在 Link 的独立右手模型里，用左手的镜像位置。
- 右手不显示，见 [技术合同](TECHNICAL_CONTRACTS.md) §2。

## 2. 头：缩放与下沉（v7、v7b）

头部（及挂在头上的一切）单独缩放 `S_HEAD`，几何比 Link 的 Head 关节低 `HEAD_DROP`。

- **v7：头小了**（用户：「karin的头是不是比原始模型要小不少？」）
  - Link 的躯干和脖子很长，按段拉伸后 Spine→Chest ×1.89、Chest→Neck ×1.59、Neck→Head ×1.58、小腿 ×1.22。
  - 从脚到头关节，身体实际放大了 **1.405** 倍，而头只有 1.30，相对身体小约 7%。
  - `S_HEAD` 改为 1.40。
  - 头上挂件的物理渐入高度原本在 1.30 下调好，构建时以 Head 关节为中心按 1.40 / 1.30 换算（`APP_REF_S_HEAD`）。
- **v7b：脖子长了**（用户：「脖子也比原本长一点」）
  - 下巴到肩关节连线 9.7 cm，按 1.405 的比例应为 7.9 cm。
  - `HEAD_DROP` 从 −0.04 改为 −0.058，挂件高度同样换算（`APP_REF_HEAD_DROP`）。
  - 代价：
    - 头部几何离 Head 关节更远，低头 / 抬头 25° 时颈部衔接处的错位从约 1.7 cm 增加到约 2.5 cm（离线渲染无明显撕裂）；
    - 眼睛离 Link 的眼皮骨更远，眨眼平均闭合从 0.93 降到 0.89。
- **规则**：先量「从脚到 Head 关节」的实际倍率，再定头的缩放。只看 `S_BODY` 会低估。

## 3. 腿：垂直骨段的加粗（v7c）

- **问题**：用户：「腿好像也比模型本身更细」。
  - 横截面按 1.38 缩放，比实际高度倍率 1.405 小约 2%；
  - 大腿又被拉长了 6%，看起来更细。
- **修改**：`retarget.similarity` 加 `radial` 参数，对垂直骨段方向单独缩放：`M = (radial·(I − dd) + stretch·dd)·s`。
  - `LEG_RADIAL`：大腿 1.10，小腿 1.06。
  - 袜子跟着一起放大，裙子内侧的间隙（§5）在加粗之后重新计算。

## 4. 肩：关节是硬限制（v7b、v7c）

- **限制**：Link 两侧 Arm_1 相距 36.6 cm，按 Karin 的比例只有 21 cm（±10.5）。
  - 动画绕 Link 的关节转动手臂，手臂下垂时的左右位置由关节决定。
  - 把手臂网格往里搬 d，只会让下垂的手臂往上顶约 0.94·d（像耸肩），不会变窄（`invariant`，对本作的骨架驱动）。
- **03_kalin 的做法**：没有特殊处理。肩部躯干半宽和本 mod 一样约 20 cm，只是被宽大的落肩外套遮住了。
- **v7c 的做法**（用户：「肩膀确实有点过宽了，像是男性健壮的体格了」）：
  - 在绑定的 T 姿势里，把手臂轴线（y = Link Arm_1 的高度 1.359 m）以上的部分朝轴线压扁，只保留 `SHOULDER_SQUASH = 0.5` 的高度。
    - T 姿势下袖子的上半边，在手臂下垂时转到外侧。压扁它就直接收窄了外轮廓，同时把方肩改成溜肩。
  - 范围：
    - 横向从 |x| = `SHOULDER_X0` 0.05 m 渐入，到 Arm_1 的 x − 0.02 m 完全生效；
    - 只作用于 `Body`、`body_2`、`pullover`、`underwear`；
    - 扣掉手和 Neck / Head 子树的权重。
  - 法线的 y 分量除以压缩比后重新归一化。
  - 手臂下垂时的外轮廓半宽：

    | 位置 | 改前 | 改后 | 按原模型比例 |
    |---|---|---|---|
    | 肩关节上方 6 cm | 13.4 cm | 4.4 cm | 3.8 cm |
    | 肩关节上方 4 cm | 20.1 cm | 16.8 cm | 10.9 cm |
    | 肩关节处 | 22.4 cm | 21.0 cm | 15.5 cm |

  - 结果：肩线接近原模型的斜度，总宽度仍受骨架限制。
- **教训**：「Body」物体里也有脸。第一次压肩没扣掉头部权重，脸的两侧被压扁，眨眼闭合掉到 0.75。

## 5. 裙摆（v3）

- **问题**（v2 实机）：腰带下露出肚子，大腿侧面和后面穿出裙子。
- **原因**：权重按「Karin 第 n 节 → Link 第 n 节」映射，深了一段。
  - Link 的裙骨支点：Skirt_1 约 y 0.91，Skirt_2 约 0.78，Skirt_3 约 0.66。Karin 的裙子在 0.698–1.055 之间。
  - 原映射下，腰带（y 0.93–1.05）100% 跟 Skirt_1，而 Skirt_1 的支点在它下面；裙摆（0.70–0.75）跟 Skirt_3，支点在裙摆处或更低。裙子因此逆着布料运动。
- **修法**（`SK_*` 常量）：
  - 按 Link 的段分权重：支点 k 驱动 [支点 k+1, 支点 k] 之间的那段；
  - Skirt_1 支点以上的腰带刚性跟 Waist；
  - 支点上下 ±2 cm 线性过渡；
  - 每个顶点取方位角最近的两列（Link 8 列：FC、FL、L、BL、BC、BR、R、FR；Karin 16 列）；
  - Leg_1_L/R 再带一点：权重 0.45·√深度，按方位角的 sin 分左右；
  - 身体和内衣在静止姿势里比裙子内表面至少缩进 1.2 cm（123 个顶点，最多 2 cm，跳过腰带的水平封口）。
- **结果**：v3 由用户实机确认。上衣的 bphcl 在 Leg_1（每侧 3 个）、Leg_2、Waist、Spine 上有胶囊碰撞体，游戏里布料会把裙子推离腿。离线的跑步姿势（没有布料，最坏情况）只用于确认没有大面积穿出。
- **兽尾**：跟 `Skirt_*_BC` 列。
