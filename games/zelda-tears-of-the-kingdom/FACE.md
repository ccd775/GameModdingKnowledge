# 面部：嘴型拟合与眨眼

套装的头部骨架带完整的 Link 面部骨骼：Eyelid_U/D、Eyebrow_*、Lip_*、Chin、Cheek_*、Eye_In/Out、Nose、Teeth。游戏用玩家动画驱动它们。

Karin 的 Body 网格有 237 个形态键（blink_L/R、VRC 口型、笑、惊讶……）。本作没有形态键通道，所以把形态键的位移拟合成面部骨骼的蒙皮权重。

## 1. 面部动画

- 位置：`Model/Player_Animation.anim.bfres.zs`。读取方法见 [技术合同](TECHNICAL_CONTRACTS.md) §6。
- `face_anim.py` 在 Head 空间里计算每根面部骨骼的蒙皮矩阵 S = W_pose · W_rest⁻¹：Head 及其祖先保持静止，只换面部骨骼的局部变换，因为面部动画叠加在身体动画上。
- 有面部曲线的动画共 62 个：

  | 动画 | 内容 |
  |---|---|
  | `Face_Default_Blink` | 第 0 帧闭眼，第 3 帧以后是静止 |
  | `Face_{Battle,Smile,Serious,Hot,Cold,Tired}_Blink` | 第 1 帧闭眼，其余帧是该表情的基础姿势 |
  | `Voice_{Default,Battle,Serious}_{A,I,U,O,N}` | 口型 |
  | `Face_Talk_Surprise` / `Embarrass`、`Face_Eat_*` 等 | 其他表情 |

## 2. 嘴和眉（v4）

`face_rig.py`：

- **目标**：对每个面部动画的峰值帧，从 `CORR` 里取对应的 Karin 形态键组合：
  - あ / い / う / お；
  - 怒り；
  - にこり + 口角上げ + にっこり；
  - 真面目；
  - 上 + あ。
- **求解**：逐顶点非负最小二乘（NNLS），求面部骨骼权重。
  - 每个顶点保留 3 根面部骨（第 4 槽给 Head）；
  - 加脊正则，让远处和无关的骨保持 0；
  - 权重在同一位置组上做 2 次拉普拉斯平滑，消除眉线上的折痕。
- **残差**：口型 A 0.48 → 0.20 cm，惊讶 0.62 → 0.40 cm。
- 眼部的顶点（`EYE_KEYS` 涉及的区域）在这一步冻结在 Head 上。

## 3. 眼睛为什么不能直接拟合

- Link 的眼皮骨支点在 Karin 眼睛上方 / 前方约 3 cm 处（头部下沉造成），行程只有 7 mm；Karin 的眨眼要 3.9 cm。
- 按普通的非负、和为 1 的权重，最好也只能做出不到 25% 的闭合，还会把眼睛拉歪。
- 眼皮动画带基础平移（上眼皮还有平移曲线），所以不能挪动骨架里的眼皮支点。

## 4. 眨眼：带符号、可大于 1 的权重（v5）

- **出处**：借鉴本库仁王3的面部方案（`games/nioh-3/FACE.md`）：面部骨骼权重可以 > 1 或 < 0，Head 吃剩余，总和恰好为 1，静止时脸不变。
- **骨骼**：每只眼三根：本眼的 Eyelid_U、Eyelid_D，加另一只眼的 Eyelid_U，外加 Head。
  - 另一只眼的支点离得远，能提供一个独立的运动方向。
  - 用它来抵消 Link 眼皮在战斗、喊叫、吃东西等表情里约 17° 的侧向倾斜。
- **约束**（`face_rig.fit_blink`）：
  - 62 个动画里所有不同的眼皮姿势，共 1916 个；
  - 每个姿势的目标 = c × まばたき 形态键，c = Link 上眼皮沿眨眼轴的转动比例，限制在 −0.5..1.2；
  - `Face_Default_Blink` 每帧权重 4，其余姿势合计 8；
  - 按位置组做拉普拉斯平滑，用稀疏方程求解。
- **第一次尝试**：只用本眼的眼皮、只用眨眼帧，闭合 81%，但需要约 −9.5 的权重，战斗 / 喊叫表情里眼睛整个变形。
- **最终结果**（v5）：
  - 眨眼时沿目标方向闭合 0.94，最差顶点 0.76；
  - 权重范围 −1.35..0.25；
  - 其他姿势的最差顶点偏差：中位 0.6 cm、p90 1.36 cm、最大 2.5 cm（`Face_Hot_Wait_Random`）。
  - v7b 头部再下沉后，闭合 0.89，其他姿势中位 0.74 cm、最大 2.95 cm。
- **实机**：用户确认「眼睛会眨眼了」（`runtime-confirmed`）。这说明本作的蒙皮按浮点、带符号的权重计算，不会截断到 0..1。
- **副作用**：Link 眯眼的表情（微笑、困、冷、吃到难吃的东西、死亡）里，Karin 也会按比例眯眼。

## 5. 浮点权重格式与 Switch Toolbox 的截断

- 原版的权重属性是 `8_8_8_8_UNorm`，存不下负值和大于 1 的值。TotkMdl 给形状加了逐形状的 `"weightFormat"`，例如 `Format_32_32_32_32_Single`。
- Switch Toolbox 的 `SaveVertexBuffer` 会按 8 位无符号的方式打包权重：
  - ×255 后截断，夹到剩余的 255，最后一个 = 余数；
  - `CreateBoneList` 按骨骼索引排序槽位，用（id 0, w 0）补齐。
- TotkMdl 的处理：
  1. 在 `CreateBoneList` 之前按骨骼名记下原始权重；
  2. 把它们对到排好序的槽位；
  3. 在 `SaveVertexBuffer` 之后用 VertexBufferHelper 重写 `_w` 属性。

  3381 个脸部顶点往返读回完全一致。
- **注意**：`pose_test.py` 跳过非正的权重，看面部要用 `face_preview.py`，它支持带符号的权重。
