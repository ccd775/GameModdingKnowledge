# Agent 入口（塞尔达传说：王国之泪）

先读 [README](README.md)，再按当前问题进入对应文档。项目当前状态记在独立工程的 PROJECT_STATE 里。本目录只提供方法、合同和已被证伪的假设。

## 接手一个新任务前

1. **核对游戏版本**：本目录快照为 1.2.0，RESTBL 文件名里的 `Product.120` 就是版本。
   - 版本变了，先重新解出 RESTBL、目标套装的模型和 pack、`Player_Animation`，与上一版比较。
   - 存档工具按哈希定位，不依赖偏移，但仍要先 `-DryRun`。
2. **看模拟器的 `load\0100F2C0115B6000\` 里装了什么**：文件夹按名字排序，同一文件**排在前面的生效**。
   - 本 mod 叫 `00_Karin_Original`。
   - 用户的旧 mod `03_kalin` 改的是同一套 1061，被盖住。
   - `01_Kalin_Base` 改的是 Link 的身体和其他套装。
3. **游戏由用户启动和游玩**：只在模拟器关闭时安装文件或改存档。安装器和存档工具会在模拟器运行时拒绝执行。
   - 远程测试机的传输、锁文件约定以当时的远程操作说明为准。
4. **一版只让一类改动进实机反馈**：几何、材质、物理增益、面部、比例分开。

## 硬性规矩（本项目已付过学费）

- **基础模型要用 Switch Toolbox 能读的版本**：零售版 `.bfres.mc` 的顶点数据是 mesh codec，Switch Toolbox 读不了。项目用 `03_kalin` 里另存过的模型当骨架和材质的来源（[技术合同](TECHNICAL_CONTRACTS.md) §2）。
- **只有平滑矩阵表里的骨骼能蒙皮**：原版头部只列了 Head、后发、鬓发，上衣只列了 2 根裙骨。用 TotkMdl 的 `smoothBones` 重建这张表，否则权重写上去也不生效。
- **借用的材质名要改掉**：`Armor_1061.anim` 的染色动画按材质名把 `_a0` 换成套装贴图。沿用原材质名，身体和腿就会显示别的贴图（v1 的实机问题）。
- **改的是布料驱动的骨骼，不是布料**：不动 `.bphcl`。借骨骼前先用 `bphcl_probe` 看它的驱动三角形：
  - 1 个固定点 = 万向节，会自转、没有回复力；
  - 2 个固定点 = 铰链，只沿一个方向摆。
- **直立的部件用负权重时，摆角大的骨骼一定会把它拉长**：拉伸量约为 |1 + g(e^{iθ} − 1)|。狐耳只借左右摆的鬓发，增益 −0.3。跑动时后发能甩到 60–90°，借它会把耳朵拉长（v6b、v6d 两次实机问题）。
- **裙摆权重按 Link 的裙骨段分**：第 k 根裙骨的支点驱动它与下一根支点之间的那段。按「Karin 第 n 节 → Link 第 n 节」映射会深一段，裙子逆着布料动、腿穿出来（v3）。
- **肩宽改不了关节**：动画绕 Link 的 Arm_1 转。把手臂往里搬只会在手臂下垂时往上顶。只能压扁肩头（[重定向与比例](RETARGET_AND_PROPORTIONS.md) §4）。
- **压扁和加粗只作用于身体**：先扣掉 Neck / Head 子树和手的权重。第一次压肩把脸的两侧也压了，眨眼闭合从 0.89 掉到 0.75。
- **RESTBL 要随 mod 走**：先合并原版、其他启用的 mod，再加本 mod 的条目，每项取较大值。排在前面的 mod 的表会整张盖掉后面的。
- **不要声称实机通过**：构建、读回、离线渲染都只是 `offline-accepted`。实机结论只来自用户。

## 报告口径

结论归到 `invariant` / `build-sensitive` / `case-derived` / `hypothesis` / `rejected` 之一。历史失败不删除，后来的证据只用于收窄旧结论的适用范围。例：「狐耳借耳环吊坠」被实机否定（拉长约 50%），改为「狐耳只借鬓发铰链」。
