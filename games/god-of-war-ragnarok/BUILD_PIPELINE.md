# 构建流程

对应便携包里的脚本，命令见 [便携包说明](../../portable-kits/god-of-war-ragnarok/README.md)。

括号里的数字是 Karin_Original 这次构建的取值。它们都是 `case-derived`：换模型或换角色后，要按新数据重新测。

## 0. 源模型修正

**问题：** Karin_Original 的 body_2（身体皮肤）带一组 `kisekae_*`「换装」形态键：Knee、LowerLeg 1/2、UppeLeg 1/2、Ankle、Foot、Toe、Chest、Hips 等。它们的作用是把衣服下面的皮肤往里收。拟合脚本 `fit_karin.py` 会清掉所有形态键，所以这些键在游戏里从来没生效过。结果是走路屈膝时，膝盖皮肤从过膝袜里穿出来。用户反馈多个游戏的 mod 都出现过同样的问题。

**做法：** 2026-10-02 起，共享源模型的 FBX 和 VRM 都已把 `kisekae_Knee` 烘焙进 body_2 的基础网格（`bake_knee.py`）：

- 影响 174 个顶点，平均往里收约 3 cm，最多 4.5 cm（源模型尺度）。这一圈都在过膝袜里，袜口在它上方约 13 cm，不会露出空洞。
- 形态键本身清零，名字和序号保留。以后在别的工具里打开它，不会叠加两次，表情或换装的绑定也不会错位。
- **FBX：** 用 `fbxbin.py` 直接改二进制，不经过 Blender 重新导出。
  - 先验证：读入再原样写回，与原文件逐字节相同。页脚的补齐长度要按原文件的规则算，否则差 4 字节。
  - 只改 body_2 的顶点，按形态键的法线增量改逐角法线，再正交化切线和副法线，最后把形态键自己的数据清零。
  - 改过的数组按原样 zlib 重新压缩。
- **VRM：** 只改 BIN 里 body_2 的 POSITION 和这个 morph target 的稀疏值（索引保留，值清零）；JSON 里只有这个 target 的 min/max 变了。
- 原件保留在同目录，文件名后加 `.orig`。

| 文件 | 原件 SHA-256 | 烘焙后 SHA-256 |
| --- | --- | --- |
| `Karin(Clone).vrm` | `971a150d…`（11974692 字节） | `8f930404…`（11974584 字节） |
| `Karin(Clone)_BlenderSafe.fbx` | `0b6e268d…`（42289728 字节） | `18f00e1a…`（42193808 字节） |

**复制后要核对哈希。** 烘焙文件第一次复制进共享目录（同步盘）时，两个文件各出现一段 384 KiB 的全零块：FBX 无法解析，VRM 有 70 个脸部形态键被清零。当天发现后已替换为上表的正确版本。共享目录里的 VRM 若是 `32dd84b5…`、FBX 若是 `c8b90bc2…`，就是损坏版，要换掉；在那段时间（2026-10-02 15:29–16:30）读过这两个文件的构建要重做。

**代价：** 如果别的项目要把袜子换成短袜（knee_socks 的 crew / anklet 形态键），膝盖会露出往里收过的皮肤，这种项目要用 `.orig`。

**对其他游戏的影响：** 2026-10-02 之前的项目（例如西之绝境 v4 用的 VRM `971a150d…`）都是用原件构建的。别处再出现同类穿模时，用同一个工具加上形态键名即可：`bake_knee.py <src.fbx> <src.vrm> <out.fbx> <out.vrm> kisekae_LowerLeg_1 …`。

## 1. 贴图提取

`extract_vrm_textures.py` 把 VRM 里内嵌的图片按名字导成 PNG。贴图那一步用其中 4 张拼成一张 4096 图集，每张占一个 2048 象限：

| 象限 | 材质 |
| --- | --- |
| 左上 | `Karin_Face` |
| 右上 | `Karin_Body` |
| 左下 | `Karin_Hair`（`Karin_Hair_Transparent` 共用） |
| 右下 | `Karin_Costume` |

材质为 `Karin_Alpha` 的三角形（腮红、眼睛高光等半透明层）直接丢弃，因为游戏的皮肤材质没有半透明。

## 2. 骨架角色表（`rigspec.py`）

从目标 wad 的 `goProto` 骨架生成 rigspec：人形骨角色 → 游戏骨骼编号，以及全部骨骼在 Blender 坐标下的绑定位置。

- **手工给出**脊柱链（Hips / Spine / Chest / Neck / Head）和右侧肢体（锁骨、肩、肘、腕、髋、膝、踝、脚趾、趾尖、5 根手指各 4 节）。
- **左侧按 X 镜像自动找。** 同一位置有几根骨时，优先选父骨也镜像对应的那根；仍然选错时用 `left_override` 指定。
- **只用带蒙皮的骨骼。** 芙蕾雅的骨架在同一关节上叠了不带蒙皮的 FK 控制骨，要选原版网格真正绑定的子骨：

| 角色 | 脊柱链 | 右臂（锁骨/肩/肘/腕） | 右腿（髋/膝/踝/趾） | 备注 |
| --- | --- | --- | --- | --- |
| 奎托斯（`goProtoheroa00`） | 163 / 175 / 193 / 219 / 318 | 221 / 329 / 955 / 1103 | 167 / 181 / 208 / 315 | 空骨骼槽填 1447 |
| 芙蕾雅（`goProtofreyaValkyrie00`） | 14 / 69 / 94 / 111 / 136 | 113 / 842 / 838 / 972 | 59 / 82 / 76 / 105 | 左膝镜像到不带蒙皮的 86，手工改为 91 |

- 奎托斯的右髋 167 在原版蒙皮里没有出现过（`verify_build.py kratos` 不强制这一项）。实机行走没看出问题，但没有专门检查（`hypothesis`）。

## 3. Blender 姿势拟合（`blender/fit_karin.py`）

在 Blender 5.0.1 后台运行，输入 FBX 和 rigspec：

1. 应用对象变换，整体缩放（奎托斯 1.6，芙蕾雅 1.53）。
2. 清掉所有形态键（所以源模型需要的形态键要先烘焙，见第 0 步）。
3. 断开骨骼连接，让姿势里的平移生效。
4. 按骨架层级逐骨摆姿势：
   - 肢体骨：头移到目标关节，朝向对准子关节；
   - 手：朝向中指根，再按食指根到小指根的方向修正滚转；
   - 手指：按目标指节的方向对齐。
5. 应用骨架修改器，把姿势烘焙进网格。
6. 每个网格导出一个 npz（顶点、逐角法线、UV、三角形、材质、权重），加上 `summary.json` 和 `karin_fitted.blend`。

## 4. 远景 LOD（`blender/decimate_levels.py`）

对拟合后的 blend 做 Collapse 减面，每个比例导出一套 npz，供槽位规划挑选：

- 奎托斯：0.9 0.75 0.6 0.5 0.4 0.3 0.22 0.16 0.12 0.08 0.06 0.04 0.03 0.025 0.02 0.015
- 芙蕾雅：0.9 0.8 0.7 0.6 0.5 0.4 0.3 0.22 0.16 0.12 0.08 0.06 0.04 0.03 0.02

## 5. 几何组装（`geometry.py`）

- **蒙皮映射。** Karin 的每根骨沿父链往上找，找到的第一根人形骨就是它的角色，再换成目标骨架上对应的骨。头发、兽耳随头，尾巴随骨盆。
- **裙子**（`skirt_leg_blend` 0.6）：每个裙子顶点取最近 4 个身体顶点的骨盆和大腿权重，按 60% 混进裙子自己的权重，让裙摆跟着大腿走。
- 每个顶点最多保留 10 个影响，写入时再按槽位的格式截断（10 / 7 / 4）。
- **顶点拆分。** 按「源顶点 + 图集 UV + 法线」去重，UV 换算到图集象限，再算切线。
- **坐标和绕序。** Blender (x, y, z) → 游戏 (−x, z, y)；三角形翻成顺时针。
- `subset` 可以按部件名（以及 `_L` / `_R` 半边）取子集，供槽位规划组合。

## 6. 槽位规划（`charbuild.py`）

**原则：** 只用「始终显示」的皮肤组和主发型组，因为它们不随服装切换消失。每个 LOD 只用组里容量最大的那个定义：同组的小定义盖在同一块区域上，但用的是睫毛、指甲、叠加层等别的材质。

- `room_finder` 按原版布局算出每个定义的顶点 / 索引容量。
- `plan_groups` 输入每组的部件清单（按优先级排序）：第一份放进最大的定义，第二份放进次大的定义。
- `fit_parts` 先找所有部件都能放下的最好的共同精度，再按优先级把剩余空间分给靠前的部件升级。
- 次要定义小到连最粗一级都放不下时，它的部件交给主定义；主定义仍放不下时，从清单末尾开始丢弃优先级最低的部件。

**奎托斯**：组 230（头、躯干、手臂，皮肤材质）的 LOD0–4，每个 LOD 用两个定义。

| 定义 | 部件 |
| --- | --- |
| 头部网格 | Body（脸）、body_2、pullover、shoes、underwear |
| 手臂网格 | hair、kemomimi、tail、skirt、knee_socks |

LOD0 全精度：头部网格 22488 顶点（容量 23081），手臂网格 11124 顶点（容量 12558），合计 33612。

**芙蕾雅**：父组为 0 的 3 个皮肤组加主发型组。

| 组 | 原用途 | 部件 | 骨骼格式 | LOD0 顶点 / 容量 |
| --- | --- | --- | --- | --- |
| 36 | 头颈皮肤 | Body、body_2、kemomimi | 8×u16，7 影响 | 12690 / 20258 |
| 14 | 手臂皮肤 | pullover、underwear、skirt、tail | 4×u16 | 8773 / 11951 |
| 13 | 脚部皮肤 | shoes、knee_socks | u8（骨骼须小于 256） | 3225 / 3266 |
| 27 | 主发型 | hair（刚性绑在头骨 136） | u8 | 6487 / 9930 |

芙蕾雅的 LOD 切换很近（头颈组 1.6 m、3.8 m、10.4 m、33.1 m）。脚部组容量最小：LOD0 的鞋只有 50% 精度，袜子 80%。

## 7. 原地写入（`build_inplace.py`）

对每个用到的流缓冲区：

1. 从 `root.lodpack` 取原版数据。哈希已被参照 mod 加过 1 的，回退到「哈希 − 1」。
2. 检查容量，超了直接报错。
3. 从原网格继承：分量 15 取出现最多的值，UV 取整数 tile，未知分量 14 照抄出现最多的原始值。
4. 按该定义的分量格式编码，覆盖它原有的顶点流和索引区。
5. 更新定义的包围盒、顶点数、三角形数、索引数。
6. 缓冲区哈希加 1；同缓冲区的所有定义和头部流清单都改成新哈希。

**奎托斯的特例：** 底板 wad 里裤子缓冲区的哈希已被参照 mod 加过 1（`PASSTHROUGH`），所以把原版数据按新哈希原样带进补丁包。

## 8. 隐藏其余网格

计划之外的所有定义都改成画一个退化三角形：

- 顶点数 1、三角形数 1、索引数 3；
- 哈希和全部偏移指向一块全零的 `0x100` 字节区域，索引偏移是这块区域的 `+0x80`。

**零块的位置：** 必须在随补丁包发布的缓冲区里，而且不能和任何计划槽位的顶点区或索引区重叠。

- 奎托斯：头部 LOD0 缓冲区（`LOD0_HASH`）的偏移 0。这个缓冲区放着组 230 LOD0 的 6 个定义（1135–1140），偏移 0 原本属于被隐藏的 1135；
- 芙蕾雅：头颈 LOD0 定义 280 的缓冲区里，Karin 顶点之后的空闲尾部（`build_valk_final.dummy_block`）。

指向 wad 内 gpu 条目（哈希 0）的写法会画出乱飞的三角形，已否决。

**效果：** 奎托斯的裤子、全部盔甲和饰品被隐藏，实机里武器和腰间密米尔的头仍然显示。芙蕾雅的其他发型、全部服装、翅膀和眼睛被隐藏。

## 9. 贴图

`build_textures.py`（奎托斯）和 `build_valk_textures.py`（芙蕾雅）只处理角色专属的贴图定义；与其他角色共用的布料、金属贴图哈希是全局的，保持不动。

- **选择规则：**
  - 奎托斯：`BODY_RE`（`kratos00_int9_*`、`youngkratos_*`、`kratos_*` 的头、躯干、手臂等）；
  - 芙蕾雅：`freyavalkyrie00_`、`freyavalkyriehelm00_`、`freya00_` 开头的贴图。
- **每张贴图的取值：**

| 类别 | 取值 |
| --- | --- |
| 漫反射 | 图集；`DIFFUSE_HI` / `VALK_HI` 列出的主要漫反射（头部等）用 4096，其余用 2048 |
| 法线 | 平面 (128, 128, 255) |
| 特效遮罩（灰烬、狂怒、纹身、战纹、泪痕等） | 黑 |
| AO、不透明度 | 白 |
| 其他 | 原贴图的中位色 |

- 常量贴图写成 128×128。中位色从游戏 texpack 里的全分辨率原图读出。
- 每级 mip 用 etcpak 压成原 T# 的格式（BC1 / BC4 / BC7），再用游戏的 DLL tiling，写成 GNF 条目。
- **芙蕾雅的两处特例：**
  - `freyavalkyrie00_head_notearmakeu_06FB`：名字被截断的肤色头部漫反射，按图集处理；
  - 泪痕层强制为黑：它的名字含 `_o_`，按通用规则会被当成不透明度写成全白。
- **数量：** 奎托斯 105 张（图集 12、黑 36、平面法线 17、白 8、中位色 31，跳过 1 张非块压缩格式）；芙蕾雅 284 张（图集 29、黑 76、平面法线 24、白 31、中位色 124）。

## 10. boot-options

在原版 `exec/boot-options.json` 的 `patch-texpacks` 和 `patch-lodpacks` 里各写一项 `"../../patch/<包名>"`。两个 mod 同时装时，两项都写进去。
