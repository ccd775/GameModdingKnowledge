# 开始与接续

先读当前项目 PROJECT_STATE.md 的最新记录，再按目标游戏进入相应 README。不必每次从头重读所有文档，也不要求每轮运行全部工具。

新项目可以用 [公共工具](../portable-kits/common/README.md) 的 init 建立工作目录。先确认源模型、目标槽位、游戏 build、工具和用户的输出要求。部署/运行测试沿用会话中已经给出的授权；不需要重复询问。

读取当前原生资源和参考，确定真正使用者。保留输入身份及哈希，再做派生编辑。必要时分开调查几何、绑定、材质、资源引用和动态行为；一次候选尽量能回答一个明确问题，允许为完整合同协调修改多个文件。

每次暂停保留：当前候选、已通过/被否决项、报告位置、下一条具体命令或 GUI 恢复点。可用 checkpoint 记录里程碑，但项目也可继续使用既有 SOP 格式。

当前 build 变化、输入漂移或输出无法解释时先调查，暂停候选晋级；仍可继续不依赖该问题的工作。静态完成、打包完成、实机加载与用户验收分别记录。不要因格式工具 exit 0 就宣布整个 Mod 完成。
